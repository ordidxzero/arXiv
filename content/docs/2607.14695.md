## Abstract

플로 매칭(flow matching, 노이즈를 목표 분포로 옮기는 속도장을 학습해 노이즈에서 출발해 여러 단계에 걸쳐 출력을 만들어 내는 생성 기법) 기반의 비전-언어-행동(Vision-Language-Action, VLA, 이미지와 언어 지시를 받아 로봇 행동을 직접 출력하는 모델) 모델은 정밀한 연속 제어를 약속하지만, 노이즈를 반복해서 걷어 내는 디노이징(denoising) 방식 때문에 실시간 로보틱스와 근본적으로 맞지 않는 부분이 생긴다. 디노이징 단계를 나타내는 타임스텝이 네트워크 전체에 주입되므로 KV 캐싱(앞서 계산한 어텐션의 키·값을 저장해 두었다가 다시 쓰는 기법)이 무효가 되고, 그 결과 느린 {{< katex >}}O(N^2){{< /katex >}} 재계산과 수학적으로 틀린 캐시 재사용 중 하나를 골라야 한다. 본 논문은 플로 매칭 정책에서 *실시간 스트리밍 추론*(real-time streaming inference)을 가능하게 하는 프레임워크 **Reflex**를 제안한다. Reflex는 *타임스텝 불변성*(Timestep-Invariance Property), 즉 지각(perception) 인코더가 기능적으로 디노이징 루프와 무관하다는 성질을 활용한다. Reflex는 어텐션 컨텍스트를 정적(static)·슬라이딩(sliding)·동적(dynamic) 영역으로 나누어, 입력이 고정되어 있을 때 전체 배치(full-batch) 어텐션과 동일한 출력을 유지하면서 캐시를 {{< katex >}}O(1){{< /katex >}}로 증분 갱신할 수 있게 한다. 끊임없이 이어지는 고빈도 추론에서도 안정성을 확보하기 위해, 플로 단계(flow phase)에 따라 게이팅함으로써 BFloat16(지수부는 FP32와 같고 가수부를 줄인 16비트 부동소수점 형식)의 수치 붕괴를 막는 적응형 정규화 층 *AdaRMSNorm*을 도입한다. 또한 시각 인코딩과 행동 생성을 분리하는 *비동기 파이프라인*(async pipeline)과 커널 오버헤드를 줄이는 *연산자 융합*(operator fusion, 여러 GPU 연산을 하나의 커널로 합쳐 실행하는 최적화)을 결합해 처리량을 최대화한다. LIBERO와 Kinetix 벤치마크에서 Reflex는 추론 속도를 2.58배 높이고 50Hz의 안정적인 스트리밍을 달성하며, 반응 지연을 최대 54% 줄이고, 성능 저하 없이 효율적인 배포를 가능하게 한다.

## 1 Introduction

**그림 1.** **표준 블로킹 방식 vs. Reflex 스트리밍.** 위: 표준 플로 매칭 추론은 추론이 끝날 때까지 실행을 막아(blocking), 반응 지연 때문에 움직이는 목표를 잡지 못한다. 아래: Reflex는 VLA 백본을 독립적인 스트림들로 나누어 각 단계가 겹쳐서 실행되게 한다.

비전-언어-행동(VLA) 모델(Physical Intelligence et al., 2025; Gemini Robotics Team et al., 2025b;a; Bjorck et al., 2025)은 체화 지능(embodied intelligence, 물리 세계에서 몸을 가지고 행동하는 AI)의 최전선에 있으며, 로봇이 자연어 지시를 연속적인 조작 동작으로 옮길 수 있게 해 준다. 최근의 *플로 매칭* 아키텍처(Lipman et al., 2023; Liu et al., 2022)는 행동을 이산 토큰으로 나타내는 방식(Black et al., 2025a)보다 고차원 행동 공간(action manifold)을 더 정밀하게 모델링함으로써 이 능력을 한층 끌어올렸다. 그러나 이 표현력에는 대가가 따른다. 플로 매칭은 반복적인 디노이징 과정을 거쳐 행동을 생성하므로 실행을 멈추고 기다리는 블로킹 실행(blocking execution)이 불가피하다. 로봇은 장면을 관찰하고, 디노이징 단계 전체를 거쳐 추론한 뒤에야 행동한다. 움직이는 컵을 잡으려는 것 같은 동적인 상황에서는 이 추론 지연 때문에 로봇이 이미 낡은 정보에 반응하게 된다. 로봇이 어떻게 움직일지 결정했을 때는 목표가 이미 다른 곳으로 옮겨 가 있다.

흔히 모델 추론을 빠르게 하면 로봇도 곧바로 빨라진다고 가정한다. 그러나 이 관점은 시스템 수준의 중요한 통찰을 놓친다. 주된 병목은 계산에 걸리는 시간 자체가 아니라, 계산이 끝날 때까지 실행을 멈추고 동기적으로 기다리는 데 있다. 그림 1에서 보듯이 표준 블로킹 추론은 로봇이 계획하는 동안 멈춰 있게 만들고, 그 결과 생긴 반응 지연이 동적 환경에서의 실패로 이어진다. 이 문제를 근본적으로 풀려면 더 빠른 계산이 아니라, 추론이 진행되는 동안에도 로봇이 행동할 수 있도록 서로 다른 시스템 단계들을 겹쳐 하나의 연속적인 스트림으로 만드는 비동기 아키텍처가 필요하다.

비동기 추론은 반응 지연을 줄이는 유망한 방법으로 보인다(Black et al., 2025b; Ma et al., 2025; Shukor et al., 2025; Sendai et al., 2025). 핵심 아이디어는 계산과 실행을 파이프라인으로 겹치는 것이다. 즉, 추론에 걸리는 시간만큼 앞선 로봇의 미래 상태를 예측하고, 이 예측을 바탕으로 한 행동 생성을 현재 제어 루프와 동시에 진행한다(Tang et al., 2025). 이렇게 하면 행동이 추론 전에 관측한 상태가 아니라 실제로 실행되는 시점의 상태에 맞춰지도록 할 수 있다. 그러나 비동기 추론은 계산과 실행 사이의 블로킹 공백은 없애 주지만, 추론 자체의 계산 비용은 줄이지 못한다. 플로 매칭 VLA에서는 실행을 어떻게 스케줄링하든 디노이징 단계마다 여전히 백본 전체를 순전파(forward pass)해야 한다.

이런 고빈도 실행을 계산적으로 감당할 수 있도록, 표준 트랜스포머(Vaswani et al., 2017)는 키-값(Key-Value, KV) 캐싱으로 이전 계산을 재사용한다. 그러나 이 방법은 플로 매칭 모델 아키텍처에서는 통하지 않는다. 이 모델들은 시간에 따라 달라지는 신호(타임스텝)를 모든 레이어에 주입하므로, 생성 도중 내부 상태가 계속 바뀐다. 과거 컨텍스트가 고정되어 있는 언어 모델과는 크게 다른 점이다. 그래서 캐시해 둔 특징은 곧바로 쓸모없어지고, 감당할 수 없을 만큼 느린 재계산과 수학적으로 틀린 근사 사이에서 하나를 골라야 한다.

이 문제들을 해결하기 위해 본 논문은 *플로 매칭 VLA*에서 매끄러운 연속 제어를 가능하게 하는 시스템 **Reflex**를 제안한다. 개별 추론 단계를 빠르게 하는 데 집중한 기존 접근(Black et al., 2025b; Ma et al., 2025; Shukor et al., 2025; Sendai et al., 2025)과 달리, Reflex는 하나의 핵심 통찰을 바탕으로 서빙 루프 전체를 다시 설계한다. 그 통찰은 *VLA 모델의 계산 구조가 물리 세계의 시간 구조와 밀접하게 맞아떨어진다*는 것이다.

Reflex는 모델의 컨텍스트를 정적 영역과 동적 영역으로 나누어 이 통찰을 활용한다. 계산량이 큰 지각 인코더가 처리하는 시각 특징은 연속된 제어 단계 사이에서 사실상 변하지 않지만, 빠르게 돌아가는 디노이징 루프는 빠른 갱신을 필요로 한다는 것이 저자들의 관찰이다. 이를 바탕으로 Reflex는 변하지 않는 지각 특징은 보존하고 동적인 플로 상태만 효율적으로 다시 계산하는 특화된 캐싱 메커니즘을 도입한다. 관측 윈도와 입력이 고정되어 있을 때, 이 방식은 각 단계의 계산 복잡도를 이차에서 상수 시간으로 줄이면서도 전체 배치 어텐션과 동일한 출력을 유지한다.

지연 외에도 Reflex는 긴 시간 동안 이어지는 스트리밍에 내재한 분포 이동(distribution shift) 문제를 다룬다. 저자들은 오프라인 학습 중에는 거의 겪지 않는, 분산이 큰 초기화 노이즈에 계속 노출되는 상황이 표준 혼합 정밀도(mixed-precision) 추론을 불안정하게 만들 수 있음을 발견했다. 이를 막기 위해, 스트리밍되는 플로에서 생기는 분산 변화에 동적으로 맞춰 주어 로봇이 멈추지 않고 무기한 동작할 수 있게 하는 정밀도 인식(precision-aware) 정규화 연산자 AdaRMSNorm을 제안한다.

마지막으로, 관측과 구동(actuation) 사이에 남는 시간 차이를 메우기 위해 Reflex는 가벼운 미래 예측 모듈을 포함한다. 예상 추론 시간만큼 로봇 상태를 앞당겨 예측함으로써, 정책이 실행 시점에 더 가까운 상태를 조건으로 삼을 수 있게 돕는다. 실험 결과 Reflex는 추론을 2.58배 가속하고 LIBERO에서 성능을 그대로 유지하면서 시스템 반응 지연을 최대 54% 줄여, 50Hz의 안정적인 고빈도 제어를 가능하게 한다. 이는 체화 AI에서는 개별 구성 요소를 따로 최적화하는 것보다 아키텍처 수준의 파이프라이닝이 훨씬 큰 이득을 준다는 것을 확인해 준다. 구현은 <https://github.com/9yc/Reflex>에서 공개되어 있다.

본 논문의 기여는 다음과 같다.

- 실시간 VLA 제어를 위해, 개별 추론 단계를 가속하는 데서 스트리밍 기반 비동기 실행으로의 근본적인 전환을 제시한다.
- 지각과 행동 생성을 분리하는 비동기 서빙 아키텍처 Reflex를 제안한다. 핵심 혁신은 타임스텝 불변성을 활용해 상수 시간 추론을 달성하는 구조 인식(structure-aware) 캐싱과, 끝없이 이어지는(infinite-horizon) 스트리밍에서 수치 안정성을 보장하는 AdaRMSNorm이다.
- LIBERO와 Kinetix 실험을 통해 Reflex가 기준선 대비 시스템 반응 지연을 줄이고 안정적인 연속 제어를 달성함을 보인다.

## 2 Background and Related Work

### 2.1 The Control-Inference Gap

로봇 조작에서 궤적을 매끄럽게 만들려면 50–100Hz의 제어 루프가 필요하지만, 최신 VLA 모델은 한 번 추론하는 데 100–200ms가 걸린다. 주파수로 따지면 한 자릿수(10배) 차이다. 이 간극을 메우기 위해 시스템들은 **행동 청킹**(action chunking)을 쓴다. 한 번 추론할 때 앞으로 실행할 행동 여러 개를 한꺼번에 생성하는 것이다(Zhao et al., 2023). 그러나 청크가 길어질수록 *낡음*(staleness)이 커진다. 청크 뒤쪽의 행동은 이미 오래된 관측을 근거로 실행되기 때문이다. 이 긴장 관계가 진정한 스트리밍 추론을 추구하는 동기다.

VLA 모델(Driess et al., 2023)은 RT-1(Brohan et al., 2023) 같은 특정 작업 전용 제어기에서 범용 모델로 발전해 왔다. RT-2(Zitkovich et al., 2023)는 550억(55B) 파라미터 VLM을 로봇 데이터와 함께 공동 파인튜닝했고, OpenVLA(Kim et al., 2025)는 7B 오픈소스 모델로 접근성을 넓혔다. 최근 연구는 연속적인 행동 생성에 **플로 매칭**을 선호한다(Black et al., 2025a; Octo Model Team et al., 2024). 플로 매칭은 속도장(velocity field) {{< katex >}}v_\theta(\mathbf{x}, t){{< /katex >}}를 학습하고, 상미분방정식(ODE) 적분(Chen et al., 2018)을 통해 노이즈를 행동으로 옮겨 간다.

> **역주.** 플로 매칭에서 {{< katex >}}t{{< /katex >}}는 "노이즈에서 정답 행동까지 얼마나 왔는가"를 나타내는 연속 시간 변수다. 생성할 때는 순수 노이즈에서 출발해 학습된 속도장 {{< katex >}}v_\theta{{< /katex >}}를 따라 작은 걸음을 여러 번(보통 10–50번) 옮기며 행동을 만든다. 이 한 걸음 한 걸음이 본문에서 말하는 디노이징 단계이고, 매 걸음마다 네트워크를 한 번씩 순전파해야 한다.

**그림 2.** 플로 매칭 VLA 아키텍처.

그림 2에서 보듯이 플로 매칭 VLA는 공통된 2단계 구조를 가진다. 하나는 시각 관측과 언어 지시를 임베딩으로 인코딩하는 무거운 **VLM 백본**이다. 계산 비용은 크지만 *디노이징 타임스텝 {{< katex >}}t{{< /katex >}}와는 무관*하다. 다른 하나는 플로 매칭 헤드를 단 가벼운 트랜스포머 디코더인 **행동 전문가**(action expert)로, 타임스텝 {{< katex >}}t{{< /katex >}}를 조건으로 받으므로 그 표현이 *디노이징 단계마다 바뀐다*. 타임스텝과 무관한 백본과 타임스텝에 의존하는 행동 전문가로 나뉘는 이 구조적 분리가 Reflex의 캐시 분할 전략의 핵심이다.

### 2.2 The Cache Reuse Dilemma

키-값(KV) 캐싱은 트랜스포머의 복잡도를 {{< katex >}}O(n^2){{< /katex >}}에서 {{< katex >}}O(n){{< /katex >}}으로 줄이며, 효율적인 LLM 서빙에 필수적이다(Kwon et al., 2023; Xiao et al., 2024). 최근 연구는 캐싱을 VLA로 확장했다. VLA-Cache(Xu et al., 2025)는 프레임 간 차이에 따라 시각 토큰을 나누었고, VL-Cache(Tu et al., 2024)는 모달리티를 고려한 압축을 적용했다. ActionFlow(Dai et al., 2025; Open X-cEmbodiment Collaboration et al., 2025)는 프리필(prefill, 입력 전체를 한 번에 인코딩해 캐시를 채우는 단계)과 디코드 단계를 파이프라인으로 겹쳐 엣지 기기에서 처리량을 2.55배 높였다. FASTer(Liu et al., 2025)처럼 토큰화를 통해 자기회귀 모델을 빠르게 하려는 시도 역시 캐시가 유효하다는 전제에 기대고 있다.

그러나 표준 KV 캐싱은 플로 매칭 VLA에서는 통하지 않는다. **타임스텝 임베딩** {{< katex >}}t{{< /katex >}}가 네트워크 전체를 조건화하므로, 디노이징 단계를 넘어가며 {{< katex >}}t{{< /katex >}}가 바뀌면 캐시해 둔 키-값 표현이 무효가 된다(Prasad et al., 2024; Song et al., 2023). 더 중요한 점은 기존 연구 대부분이 연속 생성 과정의 수치적 취약성을 간과한다는 것이다. LaVin-DiT(Wang et al., 2025) 같은 대규모 비전 확산 트랜스포머(Ho et al., 2020)는 학습을 안정시키기 위해 적응형 정규화(adaptive normalization)를 쓰지만, 이를 고빈도 스트리밍 추론에 적용하는 일은 아직 탐구되지 않았다. 서빙 분야에서는 vLLM(Kwon et al., 2023)과 FlashAttention(Dao et al., 2022; Dao, 2023) 같은 프레임워크가 커널 수준 최적화(Yu et al., 2022)가 처리량의 열쇠임을 보여 주었다. Reflex는 플로 매칭의 정확성과 혼합 정밀도 안정성을 모두 처리하는 융합 커널과 스케줄링을 함께 설계(co-design)하여 이 공백들을 메운다.

### 2.3 Design Goals

플로 매칭 VLA 모델 {{< katex >}}M{{< /katex >}}, 관측 스트림 {{< katex >}}\mathcal{O}{{< /katex >}}, 목표 제어 주파수 {{< katex >}}f{{< /katex >}}가 주어졌을 때, 다음 세 가지 성질을 만족하는 스트리밍 추론 시스템을 설계하는 것이 목표다.

**(G1) Correctness(정확성).** 관측 윈도와 입력이 고정되어 있을 때 Partitioned Attention은 전체 배치 어텐션과 동일한 출력을 내야 한다. 플로 매칭 모델에서는 타임스텝 임베딩 {{< katex >}}t{{< /katex >}}가 모든 레이어를 조건화하므로 표준 KV 캐시 재사용이 무효가 된다. 어떤 캐싱 전략이든 이 타임스텝 의존성에도 불구하고 의미적 정확성을 보존해야 한다. 단, 비동기 스케줄링, 미래 상태 예측, 혼합 정밀도 실행은 이 정확성(exactness) 주장의 범위에 포함되지 않으며 실험으로 평가한다.

**(G2) Stability(안정성).** 시스템은 *끝없이 이어지는*(infinite-horizon) 혼합 정밀도 배포 중에도 수치적으로 안정해야 한다. 50Hz로 계속 동작하면 모델은 오프라인 학습 때보다 훨씬 자주 분산이 큰 노이즈 초기화에 노출되고, 이는 BFloat16 환경에서 수치 언더플로(너무 작은 값이 0으로 떨어지는 현상)를 일으킬 위험이 있다.

**(G3) Throughput(처리량).** 시스템은 비동기 파이프라이닝으로 무거운 비전 인코더의 비용(50–100ms)을 숨겨 반응 지연을 최소화하고, 커널 수준 융합으로 하드웨어 활용도를 최대화해야 한다.

## 3 Method: Streaming VLA Inference

본 논문은 비전 처리와 행동 생성을 병렬화해 끊김 없는 추론을 가능하게 하는 스트리밍 추론 프레임워크 **Reflex**를 제안한다. 이 접근은 하나의 핵심 통찰을 활용한다. VLA 모델의 구성 요소들은 서로 다른 시간 역학을 보인다는 것이다. 시각 인코더는 천천히 변하는 관측(10–30Hz)을 처리하는 반면, 플로 매칭은 빠른 갱신(50Hz)을 필요로 한다. Reflex는 이 구성 요소들을 분리함으로써, 컨텍스트 윈도가 고정되어 있을 때 단계당 지연을 상수 시간으로 줄인다. Partitioned Attention은 관측 윈도와 입력이 고정되어 있으면 전체 배치 어텐션과 동일한 출력을 내며, 비동기 파이프라인과 미래 상태 예측은 실험으로 평가한다.

그림 3은 전체 시스템 아키텍처를 보여 준다. 비전 스트림(Vision Stream)은 관측을 계속 인코딩해 세 구역으로 나뉜 링 버퍼(Ring Buffer, 끝에 닿으면 처음으로 돌아가 덮어쓰는 고정 크기 버퍼)에 저장하고, 정책 스트림(Policy Stream)은 이와 독립적으로 행동 전문가와 플로 매칭 디노이저를 통해 행동을 생성한다. 두 스트림은 비동기적으로 통신하며, 미래 상태 예측기(Future State Predictor)가 실행 지연을 보상한다. Reflex는 세 가지 핵심 구성 요소로 설계 목표를 달성한다. 정확성을 위한 Partitioned Attention(3.1절), 안정성을 위한 AdaRMSNorm(3.2절), 처리량을 위한 비동기 파이프라이닝(3.3절)이다. 여기에 지연을 결정론적으로(매번 거의 같게) 유지하기 위한 저수준 시스템 최적화(3.4절)가 이들을 뒷받침한다.

### 3.1 Stream Correctness: Partitioned Attention

진정한 스트리밍이 되려면, 새 관측이 밀려 들어오고 행동이 빠져나가는 동안에도 내부 상태(KV 캐시)가 무기한 유효해야 한다. 그러나 표준 플로 매칭 모델은 타임스텝을 네트워크 전체에 주입하는 방식 때문에 이 성질을 깨뜨린다. 컨텍스트 전체가 특정 디노이징 단계 {{< katex >}}k{{< /katex >}}와 얽혀 버리기 때문이다. 이를 해결하기 위해 본 논문은 *타임스텝 불변성*을 활용한다. 관측 인코더는 플로 매칭 타임스텝과 기능적으로 무관하다는 성질({{< katex >}}\partial \text{Enc}/\partial t_k = 0{{< /katex >}})이다.

{{< image src="/2607.14695/figures/attention.png" alt="어텐션 행렬에서 정적 접두부·슬라이딩 히스토리·동적 접미부 구역별 마스크 패턴과, 시간 t에서 t+2까지 가장 오래된 프레임이 빠지고 새 프레임이 들어오는 슬라이딩 히스토리의 변화를 보여 주는 그림" title="그림 4. **그림 4.** **Partitioned Attention 마스크.** 컨텍스트 윈도는 고정된(pinned) 지시문 접두부, 슬라이딩되는 관측 윈도, 동적인 플로 생성 접미부로 나뉜다. 디노이징 단계마다 다시 계산해야 하는 것은 동적 접미부뿐이므로 {{< katex >}}O(1){{< /katex >}} 갱신이 가능하다.

본 논문은 컨텍스트를 세 개의 의미 영역으로 형식적으로 나눈다(그림 4). 언어 토큰은 {{< katex >}}\ell{{< /katex >}}, 시각 관측은 {{< katex >}}o{{< /katex >}}, 플로 상태는 {{< katex >}}\mathbf{x}{{< /katex >}}로 표기한다. **정적 접두부**(Static Prefix)는 작업을 정의하는 시스템 지시문 {{< katex >}}\ell_{1:L}{{< /katex >}}을 담는다. 이 부분은 한 번만 계산해 KV 캐시에 영구히 고정해 둔다. **슬라이딩 히스토리**(Sliding History)는 최근 {{< katex >}}N{{< /katex >}}개의 시각 관측 {{< katex >}}o_{t-N:t}{{< /katex >}}를 FIFO(먼저 들어온 것이 먼저 나가는) 큐로 유지한다. 새 프레임이 들어오면 가장 오래된 토큰을 내보내므로 메모리 사용량이 일정하게 유지된다. 윈도 크기 {{< katex >}}N{{< /katex >}}은 작업에 따라 다르며, 짧은 조작 작업(예: LIBERO)에서는 {{< katex >}}N=10{{< /katex >}} 프레임(약 300ms 분량의 기록)이면 충분하다. 마지막으로 **동적 접미부**(Dynamic Suffix)는 일시적인 플로 상태 {{< katex >}}\mathbf{x}^{(k)}{{< /katex >}}와 타임스텝 임베딩을 담으며, 디노이징 사이클이 끝날 때마다 초기화된다. 이렇게 나누어 두면 어텐션 메커니즘을 동적으로 조합할 수 있다. 결정적으로, 관측 시간 {{< katex >}}t{{< /katex >}}와 디노이징 단계 {{< katex >}}k{{< /katex >}}가 서로 분리된다.

{{< katex display=true >}}
\begin{aligned}
\text{Attn}(\mathbf{x}^{(k)}) = \text{Softmax}\left(\frac{Q^{(k)} [K_{\text{pin}}; K_{\text{slide}}(t); K_{\text{dyn}}(k)]^T}{\sqrt{d}}\right) \\
\times [V_{\text{pin}}; V_{\text{slide}}(t); V_{\text{dyn}}(k)]
\end{aligned}
\tag{1}
{{< /katex >}}

즉, 현재 디노이징 단계 {{< katex >}}k{{< /katex >}}의 쿼리 {{< katex >}}Q^{(k)}{{< /katex >}}는 세 구역의 키를 이어 붙인 것 전체에 대해 어텐션을 계산한다. 이때 고정 구역의 키·값({{< katex >}}K_{\text{pin}}, V_{\text{pin}}{{< /katex >}})은 아예 변하지 않고, 슬라이딩 구역({{< katex >}}K_{\text{slide}}(t), V_{\text{slide}}(t){{< /katex >}})은 관측 시간 {{< katex >}}t{{< /katex >}}에만 의존하며, 디노이징 단계 {{< katex >}}k{{< /katex >}}에 따라 바뀌는 것은 동적 구역({{< katex >}}K_{\text{dyn}}(k), V_{\text{dyn}}(k){{< /katex >}})뿐이다.

이 정식화는 관측 윈도와 입력이 같으면 전체 배치 어텐션과 동일한 출력을 내면서도 {{< katex >}}O(1){{< /katex >}} 캐시 갱신을 가능하게 한다(증명은 **부록 A.1** 참조). 이 동등성 명제는 Partitioned Attention 자체에 대한 것이며, 비동기 스케줄링, 미래 상태 예측, 혼합 정밀도의 수치적 동작에는 적용되지 않는다.

Reflex는 지각 인코더가 타임스텝에 불변인, 즉 관측 인코더가 디노이징 타임스텝을 입력으로 받지 않는 VLA 아키텍처에 적용된다. 타임스텝 조건이 비전 인코더에까지 들어가는 통합형 DiT(Diffusion Transformer) 스타일 아키텍처는 현재 범위 밖이다.

효율을 더 높이기 위해, 매 단계 가장 새로운 관측 프레임만 감지해 인코딩하는 *증분 프리필*(Incremental Prefill)을 구현한다. 증분 프리필은 LLM 서빙에서는 표준 기법이지만(Dao, 2023; Kwon et al., 2023), 타임스텝 주입 때문에 캐싱이 복잡해지는 VLA 스트리밍에 적용하려면 본 논문의 분할 구조가 필요하다. 결정적으로, 실시간 성능에는 알고리즘 복잡도만큼이나 올바른 메모리 관리가 중요하다. 표준 자기회귀 생성에서는 매 단계 KV 캐시에 값을 덧붙일 때마다 연속되지 않은(non-contiguous) 새 텐서가 만들어져 메모리 할당이 자주 일어난다. 이를 막기 위해 Reflex는 *수동 캐시 병합*(Manual Cache Merging)을 구현한다. 촘촘하게 돌아가는 플로 매칭 디노이징 루프(보통 10–50단계)에 들어가기 전에, 정적 접두부와 슬라이딩 히스토리를 하나의 연속된 메모리 버퍼로 미리 합쳐 둔다. 동적 접미부는 미리 할당한 텐서에서 관리하며 추론 사이클마다 초기화한다. 이 방식 덕분에 고빈도 디노이징 반복은 전적으로 고정된 메모리 주소 위에서 동작하며, `torch.cat` 연산의 오버헤드가 사라지고 지연이 일정하게 유지된다.

### 3.2 Stream Stability: AdaRMSNorm

Partitioned Attention으로 정확성은 확보되지만, 연속 배포를 해 보면 수치 불안정이라는 중요한 문제가 드러난다. 50Hz로 동작할 때 모델은 분산이 큰 플로 초기화({{< katex >}}t=1{{< /katex >}}에서 {{< katex >}}\mathbf{x} \sim \mathcal{N}(0, I){{< /katex >}})를 오프라인 학습 때보다 {{< katex >}}50\times{{< /katex >}} 더 자주 처리하게 되고, 이것이 활성값 급등(spike)을 일으켜 표준 RMSNorm(평균을 빼지 않고 제곱평균제곱근으로만 나누는 정규화 층)(Zhang & Sennrich, 2019)에서 BFloat16 언더플로를 유발한다.

보통 RMSNorm 같은 정규화 층은 오프라인 학습에서는 충분히 견고하다. 그러나 저자들은 스트리밍 환경에 특유한 취약점을 찾아냈다. 배포가 "끝없이 이어진다"(infinite-horizon)는 성격 때문에, 모델은 학습 때 보는 수천 단계가 아니라 수백만 단계 동안 안정적으로 유지되어야 한다. 작은 수치 오차가 쌓이고, 여기에 분산이 큰 초기화 노이즈에 50배나 자주 노출되는 것이 겹치면 결국 활성값이 붕괴한다.

이를 완화하기 위해, 로봇의 상태에 따라 활성값 분포를 동적으로 조절하는 정밀도 인식 정규화 연산자 **AdaRMSNorm**을 도입한다.

{{< katex display=true >}}
\begin{aligned}
\text{AdaRMSNorm}(x, c) &= \frac{x}{\text{RMS}(x)} \odot \gamma(c) \\
\text{where } \gamma(c) &= 1 + \text{MLP}(c), \\ \quad \text{RMS}(x) &= \sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}
\end{aligned}
\tag{2}
{{< /katex >}}

여기서 {{< katex >}}\text{RMS}(x) = \sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}{{< /katex >}}는 FP32로 계산하며, {{< katex >}}c = [t_k, s_t]{{< /katex >}}는 사인파(sinusoidal) 타임스텝 임베딩과 로봇의 고유수용(proprioceptive, 관절 각도처럼 로봇이 자기 몸에 대해 측정한) 상태를 이어 붙인 것이다.

> **역주.** 식 (2)는 입력 {{< katex >}}x{{< /katex >}}를 크기(RMS)로 나눠 정규화한 뒤, 조건 {{< katex >}}c{{< /katex >}}에서 계산한 성분별 배율 {{< katex >}}\gamma(c){{< /katex >}}를 곱한다. {{< katex >}}\gamma(c) = 1 + \text{MLP}(c){{< /katex >}} 형태이므로 MLP 출력이 0이면 보통의 RMSNorm과 같아진다. 즉, 현재 디노이징 단계와 로봇 상태에 따라 정규화 뒤의 스케일을 조금씩 조절하는 층이다.

결정적으로, 엄격한 혼합 정밀도 안전장치를 구현한다(Micikevicius et al., 2018). 분산 계산 {{< katex >}}\sqrt{\sigma^2 + \epsilon}{{< /katex >}}은 언더플로를 막기 위해 FP32로 실행하도록 강제하고, 게이팅 MLP는 메모리 대역폭을 줄이기 위해 BFloat16으로 동작한다. 두 정밀도 영역이 견고하게 맞물리도록, Reflex는 초기화 시점에 *견고한 자료형 추론*(Robust Dtype Inference) 메커니즘을 사용한다. 모호할 수 있는 모델 설정 속성에 의존하는 대신, 백본의 출력 프로젝션 층(`o_proj`)을 직접 조사해 실제 하드웨어 연산 정밀도를 알아낸다. 이 런타임 감지 덕분에 게이팅 로직이 백본의 자료형에 자동으로 맞춰지고, 중요한 다시 변환(cast-back) 연산에서 자료형 불일치 오류가 생기지 않는다.

### 3.3 Stream Throughput: Asynchronous Pipeline

**그림 5.** **비동기 파이프라인 스케줄링.** 스레드 A는 시각 관측을 계속 인코딩하고, 스레드 B는 반복 디노이징으로 행동을 생성한다. 시스템은 비전 인코딩과 행동 실행을 겹침으로써 더 낮은 지연({{< katex >}}\tau_{\text{async}} < \tau_{\text{sync}}{{< /katex >}})을 달성한다. 정책은 비동기 지연을 보상하기 위해 예측한 미래 상태({{< katex >}}\hat{s}_{t+\Delta} \approx a_t^{\text{cmd}}{{< /katex >}})를 조건으로 삼는다. 회색 음영 영역은 병렬 실행 구간을 나타낸다. 아래쪽의 동기(Sync) 기준선은 비교를 위해 전통적인 순차 처리를 보여 준다.

안정적인 스트림을 확보하고 메모리 오버헤드를 최소화하고 나면, 마지막 병목은 비전 백본의 순수한 연산 지연이다. 효율적인 캐싱을 쓰더라도 고해상도 이미지({{< katex >}}224 \times 224{{< /katex >}} 이상)를 인코딩하는 데 NVIDIA RTX 4090에서 PaliGemma(2B 파라미터) 기준 50–100ms가 걸리고, 더 큰 백본에서는 그에 비례해 늘어난다. 동기 방식으로 돌리면 이것만으로 제어 주파수가 사실상 10–20Hz로 제한된다.

이 한계를 깨기 위해 Reflex는 그림 5와 같이 시각 지각과 행동 생성을 서로 다른 하드웨어 실행 스레드로 분리한다. **스레드 A(비전)**\ 는 VLM 백본을 실행하며, 최신 카메라 프레임을 가져와 인코딩하고 KV 쌍을 공유 캐시에 넣는 "생산자(producer)" 역할을 계속한다. **스레드 B(정책)**\ 는 플로 매칭 정책을 실행하는 "소비자(consumer)"로, 가장 최근에 사용 가능한 캐시 상태를 조회해 행동 청크를 생성한다. 이 병렬화는 비전 지연과 정책 지연을 효과적으로 겹치며, 그 효과는 4.6절에서 검증한다.

그러나 비동기 실행은 상태 정렬 문제를 낳는다. 행동 계산이 끝났을 때는 로봇이 이미 움직여 있다. 본 논문은 이를 **미래 조건부 상태 예측**(Future-Conditional State Prediction)으로 처리한다. 정책은 미래 시점 {{< katex >}}t+\Delta{{< /katex >}}에 대한 행동을 계산하므로, 낡은 센서 상태 {{< katex >}}s_t{{< /katex >}}를 조건으로 쓰면 진동하는 동작이 나타난다. 그래서 낡은 센서 측정값을 시스템이 마지막으로 명령한 목표 행동으로 대체한다.

{{< katex display=true >}}
\hat{s}_{t+\Delta} \approx a_{t}^{\text{cmd}}
\tag{3}
{{< /katex >}}

이 미래 상태 예측기는 지연을 보상하기 위한 가벼운 휴리스틱일 뿐, 학습된 동역학 모델이나 형식적 동등성 보장의 일부가 아니다. 이 1차 근사는 짧은 시간 동안의 동역학을 사실상 선형화하여, 로봇이 *곧 있게 될* 위치에서 이어지는 매끄러운 궤적을 정책이 생성할 수 있게 해 준다. 이 근사는 로봇의 저수준 제어기가 명령된 행동을 정확히 따라간다는 가정에서 성립한다. 실제로 저자들의 AgileX PiPer 환경에서는 100ms 앞을 내다보는 구간에서 엔드 이펙터(로봇 팔 끝의 작업 도구) 편차가 3cm 미만으로 관찰되었다.

알고리즘 1은 메인 추론 루프를 보여 준다. Reflex는 적응형 겹침 스케줄링(Adaptive Overlap Scheduling)으로 동시성을 관리한다. 실시간으로 측정한 추론 지연을 바탕으로 앞당겨 시작하는 정도 {{< katex >}}K{{< /katex >}}를 동적으로 조정해, 현재 행동 청크가 끝나는 바로 그 순간에 다음 청크가 준비되도록 한다.

**알고리즘 1.** 미래 조건부 겹침 스케줄링(Future-Conditional Overlap Scheduling)

```
입력: 행동 청크 크기 C, 전파기(Propagator) P
 1: queue ← initial_inference()
 2: while not done do
 3:     K ← ⌈ τ̄_inf / τ_step ⌉                   ▷ 필요한 겹침 정도 추정
 4:     for i = 1 to C do
 5:         Execute queue.pop()
 6:         if i = C − K then
 7:             ŝ_future ← P(s_now, queue, K)     ▷ 미래 상태 예측
 8:             async next_chunk ← π(· | ŝ_future) ▷ 다음 추론 시작
 9:         end if
10:     end for
11:     queue ← await(next_chunk)
12: end while
```

> **역주.** {{< katex >}}\bar{\tau}_{inf}{{< /katex >}}는 측정된 평균 추론 시간, {{< katex >}}\tau_{step}{{< /katex >}}은 행동 하나를 실행하는 데 걸리는 시간이다. 따라서 {{< katex >}}K{{< /katex >}}는 "다음 추론이 끝나는 동안 실행할 수 있는 행동 개수"이고, 현재 청크에서 행동이 {{< katex >}}K{{< /katex >}}개 남았을 때({{< katex >}}i = C-K{{< /katex >}}) 다음 추론을 비동기로 시작하면 현재 청크가 소진되는 시점에 다음 청크가 준비된다.

### 3.4 System Optimizations

이런 상위 수준 아키텍처 기능을 뒷받침하기 위해, 연산과 메모리 양쪽에 저수준 최적화를 구현한다. 첫째, *연산자 융합*(Operator Fusion)으로 원소별(element-wise) 연산의 커널 실행 오버헤드를 줄인다. 깊은 PyTorch 모델은 배치 크기가 작을 때({{< katex >}}B=1{{< /katex >}}) CPU가 커널을 실행(launch)하는 오버헤드가 GPU 실행 시간보다 커지는 "실행 지연(launch latency)" 문제를 자주 겪는다. 본 논문은 표준 `Linear` 층을 여러 논리적 프로젝션을 하나로 합친 맞춤형 CUDA 커널로 대체한다. 구체적으로 쿼리·키·값 프로젝션을 하나의 묶음 커널({{< katex >}}W_{QKV} = [W_Q; W_K; W_V]{{< /katex >}})로 융합하고, SwiGLU 블록의 게이트(Gate) 프로젝션과 업(Up) 프로젝션을 합친다. 이로써 레이어당 커널 실행 횟수가 50% 줄고, 단일 스트림 추론에서 실제 경과 시간(wall-clock) 기준 15–20%의 속도 향상을 얻는다.

둘째, 메모리 단편화를 없애고 지연을 결정론적으로 유지하기 위해 동적 메모리 할당을 정적인 *링 버퍼 아키텍처*(Ring Buffer Architecture)로 대체한다. 표준 PyTorch 추론에서는 24시간 내내 동작하는 동안 텐서 할당과 해제가 자주 일어나 힙 단편화가 생기고, 이것이 예측할 수 없는 가비지 컬렉션 지연 급등을 일으킨다. 본 논문은 시스템 초기화 시점에 하나의 거대한 텐서 {{< katex >}}\mathcal{B} \in \mathbb{R}^{L \times N_{\max} \times H \times D}{{< /katex >}}를 미리 할당한다. 맞춤형 포인터 연산으로 이 버퍼를 원형으로 인덱싱하여, 메모리 접근 시간이 {{< katex >}}O(1){{< /katex >}}이고 제어 루프 동안 동적 할당이 전혀 일어나지 않음을 보장한다. 이 덕분에 시스템은 몇 시간짜리 실험에서도 무기한 반응성을 유지한다.

## 4 Experiments

### 4.1 Experimental Setup

**Base Models.** Reflex를 Pi0 계열의 VLA 모델 두 개로 평가한다. Pi0.5는 PaliGemma 비전-언어 백본(2B 파라미터)과 행동 전문가 디코더(300M 파라미터)로 이루어진 2.3B 파라미터 모델이다. 접근법이 모델 규모와 무관하게 통하는지(scale invariance) 검증하기 위해 더 큰 Pi0 변형에서도 평가한다.

**Benchmarks.** 서로 보완적인 두 벤치마크에서 평가한다.

- **LIBERO**(Liu et al., 2023): 네 가지 작업 범주에 걸친 조작 벤치마크다. LIBERO-Spatial(공간 추론), LIBERO-Object(다양한 물체), LIBERO-Goal(목표 조건부), LIBERO-Long(여러 단계로 이루어진 작업)으로 구성된다. 이 준정적(quasi-static, 환경이 거의 움직이지 않는) 작업들은 체계적인 조작 능력을 시험한다.
- **Kinetix**(Matthews et al., 2025): 동적인 교란에 빠르게 반응해야 하는, 물리 상호작용이 풍부한 벤치마크다. 집어서 옮기기(pick-and-place)에 초점을 둔 LIBERO와 달리, Kinetix는 복잡한 물리 상호작용이 있는 환경에서의 고빈도 제어를 강조한다.

**Metrics.** 시스템 성능을 종합적으로 평가하기 위해 다섯 가지 핵심 지표를 보고한다. *추론 지연*(inference latency)은 행동 청크 하나를 생성하는 데 걸리는 시간이다. *반응 지연*(reaction latency)은 관측을 캡처한 순간부터 행동이 실행되기까지의 종단 간(end-to-end) 시간이다. *정지율*(stall rate)은 행동 출력이 늦어진 제어 주기의 비율이다. *최대 메모리*(peak memory)는 추론 중 GPU 메모리 사용량의 최댓값이다. 마지막으로 *성공률*(success rate)은 평가 에피소드에서 작업을 완수한 비율이다.

**Baselines.** Reflex를 세 가지 기준선 구성과 비교한다. **Standard**는 매 단계 전체 기록을 다시 계산하는 동기 추론으로, 기존의 일반적인 VLA 배포 방식을 대표한다. **Naive Cache**는 Partitioned Attention 없이 KV 캐싱을 적용하는데, 이는 플로 매칭에 필요한 타임스텝 조건을 무시한다. **Async-Naive**는 미래 조건부 스케줄링 없이 비동기 추론만 구현한 것으로, 본 논문의 겹침 전략이 얼마나 중요한지 보여 준다(Shukor et al., 2025).

### 4.2 System Efficiency

그림 6은 두 벤치마크에서 컨텍스트 윈도 {{< katex >}}K=10{{< /katex >}}일 때의 시스템 효율을 비교한다.

**Incremental Speedup.** Reflex는 Pi0.5로 LIBERO에서 **2.58배 속도 향상**을 달성해, 추론 지연을 135.2ms에서 52.4ms로 줄인다. 이 가속은 Partitioned Attention 메커니즘에서 나온다. 출력의 정확성을 유지하면서 슬라이딩 관측 윈도를 불필요하게 다시 계산하지 않기 때문이다. 반면 Naive Cache 기준선은 비슷한 지연 감소를 얻지만, 플로 매칭에 필요한 타임스텝 조건을 무시하므로 틀린 출력을 낸다.

**Scale Invariance.** Reflex가 모델 규모에 관계없이 일반화되는지 검증하기 위해 더 큰 Pi0 모델(3.1B 파라미터)에서도 평가한다. 속도 향상 비율은 일정하게 유지될 뿐 아니라 오히려 약간 커진다. Pi0은 **2.73배 속도 향상**을 달성해 Pi0.5의 2.58배보다 높다. 이는 전체 관측 기록을 다시 인코딩하는 비용이 모델 용량과 함께 커지므로, 본 논문의 스트리밍 접근이 더 큰 모델에도 똑같이, 혹은 더 많이 이득을 준다는 것을 확인해 준다.

**Partitioned Attention Exactness.** Reflex의 핵심 장점은 캐시 분할이 고정된 입력과 고정된 관측 윈도에서 어텐션 계산을 그대로 보존한다는 것이다. 두 벤치마크와 두 모델 규모 모두에서, 같은 입력을 주었을 때 Partitioned Attention 출력과 전체 배치 어텐션 오라클(정답 기준) 사이의 **MSE가 정확히 0.00**임을 확인했다. 비동기 스케줄링과 미래 상태 예측은 상태를 언제, 어떻게 조건으로 삼는지를 의도적으로 바꾸므로, 이들의 효과는 형식적인 정확성 주장 대신 지연, 정지율, 작업 성공률로 평가한다.

**Memory Efficiency.** 표준 추론은 전체 관측 기록을 유지해야 하므로 컨텍스트 길이에 따라 메모리가 선형으로 늘어난다. 반면 Reflex는 증분 캐시 갱신으로 메모리 사용량을 일정하게 유지하여, LIBERO에서 **최대 VRAM을 27%**, Kinetix에서 **24%** 절약한다. 이 절감은 메모리가 제한된 엣지 기기에 배포할 때 특히 가치가 크다.

### 4.3 Control Responsiveness

표 1은 실제 동작 조건에서 제어 루프 성능을 평가한다. 본 논문의 적응형 겹침 스케줄링은 작업 범주 전반에 걸쳐 종단 간 반응 지연을 최대 **54%** 줄인다. 이 개선은 추론 계산을 행동 실행과 겹쳐 추론 지연을 제어 루프에서 사실상 감추는 데서 나온다. 지연 감소는 특히 LIBERO-Long에서 두드러지는데, 여러 단계로 이어지는 조작 순서에서는 지연이 단계마다 누적되기 때문이다.

동기 기준선에는 근본적인 한계가 있다. 행동 청크를 다 쓰고 나면 다음 추론이 끝날 때까지 로봇이 멈춰 기다려야 한다. 그 결과 정지율이 100%가 되고, 갑작스러운 멈춤이 동작 품질과 작업 성공률을 모두 떨어뜨린다. Reflex는 미래 상태를 예측하고 실행 중에 행동을 미리 계산해, 필요할 때 항상 새 행동 명령이 준비되도록 함으로써 이 병목을 완전히 없앤다. 이로써 **정지율 0%**\ 를 달성하고 50Hz의 매끄러운 연속 제어를 가능하게 한다. Kinetix에서는 50%의 지연 감소가 곧바로 물리적 교란에 대한 더 빠른 반응으로 이어져, 동기 제어에서라면 실패했을 교란에서도 정책이 회복할 수 있게 한다.

**Stream Stability.** 표 5는 긴 시간 스트리밍에서 AdaRMSNorm이 얼마나 중요한지 보여 준다. 표준 BFloat16 추론은 정규화 경로에서 반올림 오차가 쌓여 수치가 표류(drift)하고, 120–220단계 뒤에 모델이 붕괴한다. 정규화 경로만 FP32로 바꾼 변형(FP32 norm-only)은 주된 실패 원인이 어디인지 짚어 준다. 정규화 경로만 FP32로 바꿔도 안정적으로 버티는 단계가 700–1200단계로 늘지만 0.8ms가 추가된다. ## 5 Conclusion

본 논문은 무거운 비전-언어-행동 모델과 실시간 로봇 제어 사이의 간극을 메우는 시스템 아키텍처 Reflex를 제시했다. 입력과 관측 윈도가 고정된 조건에서 어텐션을 분할하고, 혼합 정밀도 안정성을 위해 AdaRMSNorm을 도입하고, 실험으로 평가한 융합 비동기 파이프라인을 구현함으로써, Reflex는 추론을 2.58배 가속하면서 50Hz의 안정적인 스트리밍을 달성한다. 이 결과는 "멈추고-생각하고-행동하는(stop-think-act)" 주기가 VLA 모델에 내재한 한계가 아니라, 알고리즘과 런타임 최적화를 함께 설계해 해결할 수 있는 시스템 설계상의 선택임을 보여 준다.

## A Theoretical Analysis

이 절에서는 Partitioned Attention이 정확하다는 것의 이론적 근거를 제시한다.

### A.1 Correctness of Streaming Attention

**명제 A.1 (Partitioned Attention의 동등성).** 임의의 관측 시간 {{< katex >}}t{{< /katex >}}와 디노이징 단계 {{< katex >}}k{{< /katex >}}에 대해, {{< katex >}}\mathbf{A}_{full}{{< /katex >}}을 전체 기록 {{< katex >}}H_t^{(k)} = [\ell_{1:L}, o_{t-N:t}, \mathbf{x}^{(k)}]{{< /katex >}}에 대한 표준 인과(causal) 셀프 어텐션의 출력이라 하자. {{< katex >}}\mathbf{A}_{part}{{< /katex >}}를 식 (1)로 정의한 Partitioned Attention의 출력이라 하자. 관측 인코더가 타임스텝에 불변이고({{< katex >}}\partial \text{Enc}/\partial t_k = 0{{< /katex >}}) 메모리 축출(eviction) 정책이 크기 {{< katex >}}N{{< /katex >}}의 FIFO 큐를 엄격히 따른다면, 동적 접미부의 모든 토큰에 대해 {{< katex >}}\mathbf{A}_{part} = \mathbf{A}_{full}{{< /katex >}}이다.

*증명.* 전체 기록에 대한 쿼리 {{< katex >}}Q{{< /katex >}}, 키 {{< katex >}}K{{< /katex >}}, 값 {{< katex >}}V{{< /katex >}} 행렬이 정적({{< katex >}}s{{< /katex >}}), 슬라이딩({{< katex >}}l{{< /katex >}}), 동적({{< katex >}}d{{< /katex >}}) 성분으로 이루어져 있다고 하자. 즉 {{< katex >}}K = [K_s; K_l; K_d]{{< /katex >}}이다. 표준 어텐션은 다음을 계산한다.

{{< katex display=true >}}
\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{Q K^T}{\sqrt{d}}\right) V
{{< /katex >}}

이어 붙인 구조를 대입하면 다음과 같다.

{{< katex display=true >}}
Q K^T = Q [K_s^T; K_l^T; K_d^T] = [Q K_s^T, Q K_l^T, Q K_d^T]
{{< /katex >}}

소프트맥스 연산은 로짓 전체가 빠짐없이 주어지기만 하면 입력 벡터를 어떻게 나누어 놓든 결과가 같으므로, 결과로 나오는 어텐션 가중치 {{< katex >}}\alpha{{< /katex >}}는 각 구역의 가중치를 이어 붙인 것과 같다. 즉 {{< katex >}}\alpha = [\alpha_s, \alpha_l, \alpha_d]{{< /katex >}}이다. 따라서 값의 가중합은 다음과 같다.

{{< katex display=true >}}
\mathbf{A}_{part} = \alpha_s V_s + \alpha_l V_l + \alpha_d V_d
{{< /katex >}}

이는 정확히 행렬 곱 {{< katex >}}\text{Attn}(Q, K, V){{< /katex >}}의 정의와 같다. 타임스텝 불변성은 {{< katex >}}K_s, V_s{{< /katex >}}({{< katex >}}t=0{{< /katex >}}에서 계산됨)와 {{< katex >}}K_l, V_l{{< /katex >}}(관측 시간 {{< katex >}}\tau < t{{< /katex >}}에서 계산됨)이 추론 시점 {{< katex >}}t{{< /katex >}}에서도 유효한 표현으로 남아 있음을 보장하므로, 이들을 다시 계산하지 않고 캐시해 둘 수 있다. ∎

> **역주.** 이 증명의 핵심은 두 가지다. 첫째, 어텐션은 쿼리 하나가 모든 키에 대해 점수를 매기고 소프트맥스로 정규화하는 계산이므로, 키를 세 묶음으로 나눠 저장해 두더라도 점수를 계산할 때 세 묶음을 모두 이어 붙여 쓰기만 하면 결과가 달라지지 않는다. 둘째, 정적·슬라이딩 구역의 키·값은 디노이징 타임스텝을 입력으로 받지 않는 인코더에서 나오므로 디노이징 단계가 바뀌어도 값이 그대로다. 따라서 매 단계 새로 계산해야 하는 것은 동적 구역의 키·값뿐이다.

### B.3 AdaRMSNorm Details

적응형 게이팅을 위한 MLP는 SiLU 활성화 함수를 쓰는 은닉층 하나로 이루어진다.

```python
self.dense = nn.Sequential(
    nn.Linear(cond_dim, hidden_dim),
    nn.SiLU(),
    nn.Linear(hidden_dim, model_dim),
)
```

수치 표류를 막기 위해 RMSNorm 통계는 FP32로 계산한다.

```python
def forward(self, x, cond):
    rms = x.float().pow(2).mean(-1, keepdim=True)
    x_norm = x * torch.rsqrt(rms + self.eps)
    gate = 1 + self.dense(cond)
    return x_norm * gate
```
