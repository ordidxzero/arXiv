## Abstract

비전-언어-행동(Visual Language Action, VLA) 모델은 여러 모달리티를 다루는 인공지능(AI) 시스템의 한 종류다. 시각 인식, 자연어 이해, 행동 계획을 하나로 묶어, 에이전트가 주변 환경을 해석하고 지시를 이해한 뒤 물리적 작업(embodied task)을 스스로 수행하게 한다. 최근 이 분야는 크게 발전했다. 그런데 이런 모델은 보통 작업 성공률로만 평가된다. 성공률로는 작업이 얼마나 잘 수행되었는지(품질)도, 모델이 자기 결정을 얼마나 확신하는지도 알 수 없다. 본 논문은 로봇 조작(manipulation) 작업을 하는 VLA 모델을 위해 특별히 설계한 불확실성 지표 8개와 품질 지표 5개를 제안한다. 이 지표들이 얼마나 효과적인지는 대규모 실증 연구로 평가한다. 연구에는 당시 최고 수준의 VLA 모델 3개를 썼다. 이 모델들을 대표적인 로봇 조작 작업 4개에 실행했고, 그중 성공한 실행 908건을 분석했다. 해당 분야 전문가들이 작업 품질에 직접 레이블을 달았고, 이를 바탕으로 제안한 지표와 전문가 판단 사이의 상관을 분석했다. 그 결과 여러 지표가 사람의 평가와 중간\~강한 상관을 보였다. 즉 이 지표들은 작업 품질과 모델 확신도를 평가하는 데 쓸모가 있다. 또한 일부 지표는 고·중·저품질 실행을 실패한 작업과 구별할 수 있었다. 이 성질은 테스트 오라클(test oracle)을 쓸 수 없을 때 유용할 수 있다. 이 결과는 이진 성공률에만 기대는 현재의 평가 관행이 충분하지 않다는 점을 보여 준다. 또한 VLA 기반 로봇 시스템을 실시간으로 모니터링하고 적응적으로 개선하는 연구의 길을 연다.

> **역주.** 테스트 오라클은 소프트웨어 테스트에서 "이 실행 결과가 맞는가"를 판정하는 기준을 말한다. 이 논문에서는 시뮬레이터가 물체의 최종 위치 등을 보고 성공/실패를 자동 판정하는 규칙이 오라클 역할을 한다.

**키워드(Index Terms):** Visual Language Action models, Robotic Manipulation, Uncertainty Quantification, Quality Assurance, Cyber-Physical Systems.

## 1 Introduction

로봇 시스템은 오늘날 제조 공정에서 빼놓을 수 없는 요소다. 하지만 로봇 프로그래밍 역량을 갖춘 인력이 부족하기 때문에 로봇 도입은 크게 제약되어 있고, 매출 규모가 큰 기업에만 사실상 한정된다 [1]. 최근 생성형 인공지능의 발전이 이 격차를 줄이고 있다 [2, 3]. NVIDIA 같은 기업은 이런 모델로 움직이는 로봇이 머지않아 제조업을 넘어 아파트, 사무실, 호텔 등 여러 영역에 배치될 것으로 예측한다. Tesla의 휴머노이드 로봇 Optimus, Boston Dynamics의 Spot 로봇, Samsung의 Bot Handy 로봇이 그 예다.

이를 가능하게 하는 생성형 AI 기반의 최신 모델이 비전-언어-행동(Visual Language Action, VLA) 모델이다. VLA 모델은 로봇이 시각 장면을 해석하고, 자연어 명령을 이해하고, 변화하는 환경에서 복잡한 작업을 매끄럽게 수행하게 하는 유망한 방향이다. 이 모델은 이미지 여러 장, 자연어 지시, 제어 대상 로봇의 상태를 입력으로 받는다. 출력으로는 행동 청크(action chunk, 한 번에 예측하는 연속 행동 묶음) 여러 개를 생성하고, 이 청크는 곧바로 이동(loco-motion) 및 조작 명령으로 변환된다. 이렇게 고수준의 인지적 지시와 저수준의 로봇 행동이 직접 연결되므로, 로봇 프로그래밍이 단순해지고 사람-로봇 상호작용이 쉬워진다.

최근 여러 VLA 모델이 제안되었다. GR00T-N1 [4], {{< katex >}}\pi_0{{< /katex >}} [5], OpenVLA [6], SpatialVLA [7] 등이다. 그러나 이 모델들의 평가 방식은 표준화되어 있지 않다. 누구나 받아들이는 벤치마크가 없어서, VLA 모델 개발자가 대개 자기만의 평가 벤치마크를 제안하기 때문이다. 이런 벤치마크는 보통 여러 시나리오로 이루어지고, 각 시나리오에는 미리 정해 둔 물체 집합과 다양한 지시(예: *"grasp a coke can"*)가 들어 있다. 평가가 이처럼 체계적이지 않다 보니, 최근 Wang et al. [8]은 퍼징(fuzzing, 변형된 입력을 대량 생성해 시험하는 기법)으로 최신 VLA 모델을 평가하는 벤치마킹 프레임워크 VLATest를 제안했다. 새 VLA 모델을 제안하는 연구들과 마찬가지로, VLATest [8]도 기호 오라클(symbolic oracle)로 작업 성공 여부를 판정한다. 이 오라클은 대상 물체의 최종 상태(예: 최종 위치)를 확인해서 VLA 모델이 목표를 달성했는지 판단한다.

이것은 VLA 모델 평가를 향한 의미 있는 첫걸음이지만, 작업 실행 품질을 정량적으로 재는 척도가 없다. 앞의 콜라 캔 잡기 예에서, 고품질 실행이라면 로봇 팔이 환경의 다른 물체와 부딪히지 않고 대상 물체로 곧장 다가가야 한다. 또한 콜라 캔을 첫 시도에 제대로 잡아야 한다. 그런데 VLATest [8]에서 성공으로 판정된 테스트 케이스를 자세히 들여다보면, 그중 상당수가 저품질 실행이었다. 예를 들어 많은 VLA 모델이 잡는 도중 대상 물체를 떨어뜨리거나, 다른 물체와 충돌하거나, 최적이 아닌 궤적을 따라갔다. 게다가 작업이 모델의 능력 덕분에 성공했는지, 단지 우연히 성공했는지 분명하지 않은 경우가 많았다.

이 문제를 해결하기 위해, 작업이 높은 품질로 수행되었는지 평가하는 품질 지표 5개를 제안하고 검증한다. 또한 작업 실행 중 VLA 모델의 확신도를 정량화하는 불확실성 지표 8개를 제안한다. 바탕에 깔린 직관은 다음과 같다. 불확실성이 높다는 것은 모델의 확신이 낮다는 뜻이고, 확신이 낮으면 작업 실행 품질도 낮아지는 경우가 많다. 나아가 저자들은 이 지표들을 실행 중 모니터링(run-time monitoring)이나 반증 기반 테스트 생성(falsification-based test generation, 요구사항을 어기는 입력을 찾아내는 테스트 생성) 같은 곳에도 활용할 수 있을 것으로 본다.

구체적으로 이 논문의 핵심 기여는 다음과 같이 정리할 수 있다.

- VLA 모델을 위한 불확실성 지표 8개와 품질 지표 5개를 제안한다. 저자들이 아는 한, 로봇 조작 작업용 VLA 모델의 맥락에서 이런 지표를 제안한 것은 이 논문이 처음이다.
- 최신 VLA 모델 3개의 품질을 작업 4개에 걸쳐 수작업으로 평가한다. 이를 위해 해당 분야 전문가 3명이 세 VLA 모델의 성공한 테스트 실행 908건을 직접 분석하고 레이블을 달았다.
- 제안한 품질 지표와 불확실성 지표를 수작업 레이블과의 상관으로 평가한다. 결과에 따르면 일부 지표는 사람의 판단과 중간\~높은 상관을 보이므로 실제로 쓸 만하다.
- 재현성과 후속 연구를 돕기 위해 코드, 설정 파일, 사용 설명을 담은 전체 재현 패키지 [9]를 제공한다. 또한 실험 결과 전체를 담은 Zenodo 패키지 [10]도 제공한다.

이 연구의 결과는 현재 VLA 모델 평가 방식에 심각한 결함이 있음을 보여 준다. 기존 평가는 주로 작업 완료 여부라는 이진 성공에 의존해 왔다. 하지만 널리 알려진 VLA 모델 3개의 성공 실행 908건을 면밀히 분석하자, 작업 실행 품질에서 두드러진 차이가 드러났다. 예를 들어 {{< katex >}}\pi_0{{< /katex >}} 모델은 실행 품질이 낮았다. {{< katex >}}\pi_0{{< /katex >}} 개발진은 대체로 낙관적인 자체 평가를 내놓았으므로, 이는 그와 뚜렷이 대비되는 중요한 발견이다. 똑같이 성공으로 판정된 작업이라도 전문가가 매긴 품질 레이블은 크게 갈렸다. 이는 성공률만으로는 믿을 만한 평가 지표가 되지 못함을 보여 준다. 또한 제안한 불확실성 지표 8개와 품질 지표 5개는 전문가 평가와 중간\~높은 상관을 보였다. 즉 이 지표들이 모델 성능의 차이를 효과적으로 포착하는 것으로 보인다. 이 결과는 기존 평가 프레임워크에 문제를 제기할 뿐 아니라, 로봇 시스템의 실시간 모니터링과 적응적 개선을 위한 앞으로의 중요한 연구 방향도 제시한다.

## 2 Background on VLA Models

VLA 모델 [4, 5, 6, 7]은 새로 등장한 다중 모달 학습 시스템으로, 인식, 언어 이해, 행동 계획 사이의 간극을 잇는다. 전통적인 심층 신경망(Deep Neural Network, DNN)은 보통 한 영역의 작업만을 위해 설계된다. 예를 들어 합성곱 구조는 이미지에서 계층적 특징을 뽑는 데 뛰어나고 [11, 12, 13, 14], Transformer [15] 기반 언어 모델은 텍스트의 장거리 의존성을 포착한다 [16, 17, 18, 19, 20]. 반면 VLA 모델은 시각 관측(예: 이미지나 비디오 프레임)과 텍스트 지시를 하나의 공유 임베딩 공간으로 인코딩하고, 이 공간에서 구조화된 행동 시퀀스를 생성한다. 그래서 VLA 모델은 "*Pick up the Apple*" 같은 지시를 장면의 맥락 속에서 해석할 수 있다. 이때 모델은 지시가 장면의 어느 물체를 가리키는지를 시각 어텐션으로 확정해 모호함을 해소하고, 지시를 정밀한 물리적 동작 시퀀스로 바꿔야 한다.

**그림 1.** VLA 모델 구조와 관측 처리 단계의 개요.

그림 1에서 보듯, 모든 VLA 모델은 인식, 추론, 제어를 아우르는 다단계 구조로 이루어진다. 관측 {{< katex >}}o_t = \left[I^t_1,\, I^t_2,\, \dots,\, I^t_n,\, \ell_t,\, q_t\right]{{< /katex >}}가 주어진다고 하자. 여기에는 RGB 이미지 {{< katex >}}n{{< /katex >}}장({{< katex >}}I^t_n{{< /katex >}}), 언어 지시({{< katex >}}\ell_t{{< /katex >}}), 로봇의 고유수용 상태 {{< katex >}}q_t{{< /katex >}}가 들어 있다. 고유수용 상태(proprioceptive state)는 관절 각도처럼 로봇이 스스로 재는 내부 상태다. 먼저 시각 인코더가 이미지를 특징 맵으로 처리해 국소 구조와 전역 맥락을 함께 담는다. 동시에 언어 인코더는 지시를 밀집된 의미 임베딩으로 바꾼다. 로봇의 고유수용 상태 역시 별도 인코더를 거쳐 특징 벡터로 바뀐다. 이 임베딩들은 공유 잠재 공간으로 사영되며, 여기서 언어 토큰이 관련 시각 영역 및 로봇 상태와 정렬된다. 이렇게 섞인 표현에서 행동 디코더가 행동 청크 {{< katex >}}A_t = \left[a_t,\, a_{t+1},\, \dots,\, a_{t+H-1}\right]{{< /katex >}}를 출력한다. 각 {{< katex >}}a_{t+h}{{< /katex >}}는 다차원 제어 신호 {{< katex >}}a_{t+h} = \left[a_{t+h,1},\, a_{t+h,2},\, \dots,\, a_{t+h,D}\right]{{< /katex >}}이고, {{< katex >}}D{{< /katex >}}는 제어 차원의 총수다. 대부분의 VLA 모델에서 이 신호는 7차원이다. 위치 3차원({{< katex >}}x, y, z{{< /katex >}}), 방향 3차원({{< katex >}}roll, pitch, yaw{{< /katex >}}), 그리퍼 열림 1차원이다. 행동 청크 크기 {{< katex >}}H{{< /katex >}}를 행동 호라이즌(action horizon)이라고 하는데, 이 값은 모델마다 다르다. 예를 들어 {{< katex >}}\pi_0{{< /katex >}} 모델의 행동 호라이즌은 최대 50개 행동이다 [5].

최근 VLA 모델 [4, 5]은 행동을 내놓기 전에 확산(diffusion) 기반 디노이징 과정을 도입했다. 이런 모델에서는 VLA 모델이 출력한 행동 청크 {{< katex >}}A_t{{< /katex >}}를 디노이징 확산 과정으로 다듬는다. 이 과정에서는 시각 입력, 언어 지시, 고유수용 상태(즉 {{< katex >}}o_t{{< /katex >}})의 표현에서 뽑은 맥락 정보를 이용해, 초기 행동 예측에서 노이즈를 반복적으로 제거한다. 확산 모듈은 궤적 전체를 처음부터 샘플링하지 않는다. 대신 후처리 단계로 작동해, 기본 모델의 출력을 행동 공간에서 더 그럴듯한 영역으로 이끌어 개선한다. 이 방식은 복잡한 장면에서 일반화를 높이고, 긴 호라이즌 작업에서 오차 누적을 줄여 강건성을 높이는 것으로 보고되었다 [5, 21, 4].

VLA 모델의 학습은 보통 다음 두 방식 중 하나를 따른다. (1) 처음부터 학습하거나, (2) 대규모 사전학습 후 목적에 맞게 파인튜닝한다. 전자에서는 모델을 초기화한 뒤 특정 로봇이나 작업 환경에 맞춘 데이터셋으로 학습한다. 그러면 학습된 정책이 그 시스템 고유의 제약에 맞춰진다 [22, 23]. 후자는 규모를 키우기에 더 유리한 방식이다. 여기서는 VLA 모델을 Open X-Embodiment 데이터셋 [24] 같은 대규모 다중 모달 데이터셋으로 사전학습한다. 이런 데이터셋에는 여러 영역에서 모은 다양한 언어 명령, 시각 관측, 행동 시퀀스가 들어 있다. 사전학습 단계에서 모델은 다른 작업으로 옮겨 쓸 수 있는 표현과 일반적인 추론 능력을 얻는다. 이어서 로봇별 데이터셋으로 파인튜닝해, 행동 디코더를 하드웨어 고유의 제약(예: 기구학이나 관절 한계)에 맞춘다. 이 파인튜닝은 매우 중요하다. 예측된 행동이 의미 있을 뿐 아니라, 로봇의 물리적 제약 안에서 실제로 실행 가능하고 안전하도록 보장하기 때문이다.

## 3 Uncertainty Metrics

모델의 확신도를 정량화하기 위해, VLA 모델용 불확실성 지표를 모두 8개 제안한다. 지표를 고를 때는 다중 모달 작업에서 불확실성의 서로 다른 측면을 포착해야 한다는 점을 기준으로 삼았다. 먼저 딥러닝 모델에서 흔히 쓰는 확신도 기반 지표 4개(Token Probability, PCS, Entropy, DeepGini)를 VLA 모델의 맥락에 맞게 바꿨다. 이 지표들을 고른 이유는 두 가지다. 첫째, 예측 확신도를 직접 반영한다. 둘째, 해석 가능한 확률적 원리를 바탕으로 하므로 VLA 모델의 출력으로 확장해도 여전히 의미가 있다. 이와 별도로, VLA 모델의 출력은 구조화된 결정 시퀀스이므로, 생성된 행동의 불확실성을 재도록 특별히 설계한 새 지표 4개도 도입한다. 새 지표들은 전통적인 토큰 기반 지표와 다르지만, 그 지표들을 보완한다. 새 지표들은 행동이 얼마나 흔들리는지, 그리고 모델의 여러 추론이 얼마나 일치하는지를 세밀하게 포착하는 것을 목표로 한다. 기존 지표를 바꾼 것과 새 지표를 함께 묶어, VLA 모델의 불확실성을 평가하는 폭넓은 지표 집합을 제공하려 한다.

> **역주.** 이 절의 8개 지표는 크게 세 묶음이다. A-로 시작하는 3개(A-PI, A-VI, A-AI)는 모델이 낸 행동 값의 시간적 변화를, TB-로 시작하는 4개(TB-TP, TB-PCS, TB-D, TB-E)는 모델 내부 언어 모델이 낸 토큰 확률 분포를, EV는 같은 입력에 대한 반복 추론의 흩어짐을 본다. 모든 지표는 값이 클수록 불확실성이 크다는 방향으로 맞춰져 있다.

### 3.1 Action Position Instability (A-PI)

행동 위치 불안정성(Action Position Instability, A-PI)은 모델이 추론한 행동 값(또는 예측한 상태)이 시간에 따라 어떻게 바뀌는지를 살펴 불확실성을 정량화한다. 이 불확실성을 효과적으로 재기 위해, 연속한 단계 사이의 차이를 계산해 행동 시퀀스가 얼마나 매끄럽고 일관된지 평가한다. 이 차이가 뚜렷한 봉우리처럼 갑자기 크게 튀면, 모델의 행동이 갑자기 바뀌었다는 신호다. 이런 급변은 주어진 작업에서 모델이 망설이거나 불안정하게 동작한다는 것을 반영할 수 있다.

VLA 모델이 추론해 실행 중 단계마다 로봇에 보낸 행동을 시간순으로 늘어놓은 시퀀스 {{< katex >}}\{a_1, a_2, \dots, a_T\}{{< /katex >}}가 있다고 하자({{< katex >}}T{{< /katex >}}는 길이). 이때 시점 {{< katex >}}t{{< /katex >}}({{< katex >}}t>1{{< /katex >}})에서의 1차 차분을 다음과 같이 계산한다.

{{< katex display=true >}}
\Delta a_t = a_{t} - a_{t-1}, \tag{1}
{{< /katex >}}

여기서 절댓값 {{< katex >}}\lvert \Delta a_t \rvert{{< /katex >}}는 로봇에 전달되는 행동이 그 순간 얼마나 빨리 바뀌는지를 잰다. 따라서 연속한 단계에 걸쳐 {{< katex >}}\lvert \Delta a_t\rvert{{< /katex >}}에 두드러진 봉우리가 나타나면, 모델의 행동이 급변했다는 뜻이고 불확실성을 반영할 수 있다. 이 불확실성을 정량화하기 위해, Matinnejad et al. [25]이 신호의 진동을 재려고 제안한 불안정성(Instability) 지표를 변형해 썼다. 즉 임의의 시점 {{< katex >}}t{{< /katex >}}({{< katex >}}t>1{{< /katex >}})에서 VLA 모델의 불확실성을 다음과 같이 잰다.

{{< katex display=true >}}
\text{u}_t = \frac{1}{D} \sum_{d=1}^{D} \left| \Delta a_{t,d} \right| \tag{2}
{{< /katex >}}

여기서 2절에서 설명했듯 {{< katex >}}D{{< /katex >}}는 행동의 차원 수이고, {{< katex >}}d{{< /katex >}}는 행동 벡터 안의 특정 차원을 가리키는 인덱스다. 즉 차원마다 1차 차분의 크기를 구해 평균한 값이다.

### 3.2 Action Velocity Instability (A-VI)

앞의 지표는 어떤 상황에서는 약점이 있다. 예를 들어 빠르게 움직이는 로봇은 동작이 불규칙하지 않더라도 자연스럽게 {{< katex >}}\Delta a_t{{< /katex >}} 값이 계속 크게 나온다. 로봇의 동적 거동을 더 정확히 특징짓기 위해 행동 속도 불안정성(Action Velocity Instability, A-VI) 지표를 도입한다. 이 지표는 행동 시퀀스의 2차 차분, 즉 이산적인 2계 도함수로 정의된다.

{{< katex display=true >}}
\begin{aligned}
\Delta^2 a_t
&= \Delta a_{t} - \Delta a_{t-1}
= a_{t} - 2\,a_{t-1} + a_{t-2}
\end{aligned} \tag{3}
{{< /katex >}}

속도의 변화를 분석하면 VLA 모델의 의사결정 과정에서 생기는 진동을 평가할 수 있다. 속도 차이가 클수록 움직임이 더 급격하게 바뀐다는 뜻이고, 이는 불확실성이 커졌으며 로봇 거동이 덜 안정적일 수 있음을 반영한다. 이 불확실성은 다음 지표로 정량화한다.

{{< katex display=true >}}
\text{u}_t = \frac{1}{D} \sum_{d=1}^{D} \left| \Delta^2 a_{t,d} \right| \tag{4}
{{< /katex >}}

여기서 2절에서 설명했듯 {{< katex >}}D{{< /katex >}}는 행동의 차원 수이고, {{< katex >}}d{{< /katex >}}는 행동 벡터 안의 특정 차원을 가리키는 인덱스다.

### 3.3 Action Acceleration Instability (A-AI)

로봇의 거동을 더 자세히 특징짓기 위해, 여러 VLA에서 자주 관찰되는 진동성 움직임을 정량화하고자 했다. 이런 진동은 보통 움직임이 빠르게 요동치는 형태인데, 속도만으로는 이를 온전히 포착할 수 없다. 속도는 빠르기와 방향을 재지만, 그것이 시간에 따라 얼마나 빨리 바뀌는지는 재지 않기 때문이다. 속도의 변화를 반영하는 가속도를 보면 이런 요동이 드러난다. 그래서 행동 가속도 불안정성(Action Acceleration Instability, A-AI) 지표를 도입하고, 행동 시퀀스의 3차 차분으로 정의한다.

{{< katex display=true >}}
\Delta^3 a_t = \Delta^2 a_t - \Delta^2 a_{t-1}
= a_t - 3a_{t-1} + 3a_{t-2} - a_{t-3} \tag{5}
{{< /katex >}}

이 지표는 가속도의 변화율을 잰다. A-AI 값이 클수록 거동이 더 급격하고 덜 매끄럽다는 뜻이며, 로봇 의사결정 과정의 불안정성과 불확실성이 크다는 것을 반영한다. 앞의 지표들과 마찬가지로 불확실성 값은 다음과 같이 계산한다.

{{< katex display=true >}}
\text{u}_t = \frac{1}{D} \sum_{d=1}^{D} \left| \Delta^3 a_{t,d} \right| \tag{6}
{{< /katex >}}

여기서 2절에서 설명했듯 {{< katex >}}D{{< /katex >}}는 행동의 차원 수이고, {{< katex >}}d{{< /katex >}}는 행동 벡터 안의 특정 차원을 가리키는 인덱스다.

### 3.4 Token Probability (TB-TP)

시각 기반 의사결정을 다루는 최근 접근법 중 상당수는 주로 확산 모델만으로 의사결정을 한다 [26, 27]. 이와 달리 VLA 모델은 고수준 제어의 백본으로 비전-언어 모델(Visual Language Model, VLM)을 쓴다 [5, 4]. 이 VLM은 이산 토큰을 출력하고, 확산 모델은 이 토큰을 입력으로 삼는다. 의사결정 과정의 불확실성을 정량화하기 위해, 이 출력 토큰에 딸린 확률을 분석해 여러 지표를 정의한다. 불확실성이 높을수록 토큰 확률이 낮고, 이는 모델이 고른 행동이나 예측에 덜 확신한다는 뜻이다.

이런 모델은 입력 {{< katex >}}I{{< /katex >}}(모델에 들어가는 관측 전체)가 주어지면 이산적인 클래스(또는 토큰) 집합 위의 확률 분포를 만든다. 각 확률 {{< katex >}}p_i{{< /katex >}}는 정답 출력이 클래스 {{< katex >}}i{{< /katex >}}라고 모델이 얼마나 확신하는지를 나타내며, 모든 확률의 합은 1이다. 최대 확률(Maximum Probability, MaxP) 지표는 분포에서 가장 높은 예측 확률을 골라 모델의 확신도를 정량화한다.

{{< katex display=true >}}
MaxP(I) = \max \, p_i \tag{7}
{{< /katex >}}

MaxP가 높으면 모델이 한 클래스를 강하게 선호한다는 뜻이고, 이는 불확실성이 낮다는 것에 해당한다. 이 개념을 이용해, 시점 {{< katex >}}t{{< /katex >}}에서의 토큰 기반 토큰 확률(Token-Based Token Probability, TB-TP) 불확실성 지표를 다음과 같이 정의한다.

{{< katex display=true >}}
u_t = 1 - \frac{1}{TN} \sum_{tn=1}^{TN}MaxP(a_{t,tn}) \tag{8}
{{< /katex >}}

여기서 {{< katex >}}TN{{< /katex >}}은 행동 하나를 이루는 토큰 수이고, {{< katex >}}tn{{< /katex >}}은 한 행동의 토큰 중 특정 토큰을 가리키는 인덱스다. 이 지표는 모든 토큰의 최대 확률을 평균한 뒤 1에서 빼므로, MaxP 값이 높을수록 {{< katex >}}u_t{{< /katex >}}가 낮아져 모델의 불확실성이 작음을 나타낸다.

> **역주.** 3.4\~3.7절의 {{< katex >}}p_i{{< /katex >}}는 토큰(클래스) {{< katex >}}i{{< /katex >}}의 확률이다. 4.1\~4.3절에서 같은 글자 {{< katex >}}p_t{{< /katex >}}가 툴 중심점의 위치를 뜻하므로 혼동하지 않아야 한다.

### 3.5 Prediction Confidence Score (TB-PCS)

예측 확신 점수(Prediction Confidence Score, TB-PCS) 불확실성 지표는 비전-언어 모델이 생성한 토큰 기반 출력에 대해 작동한다. 그 모델이 백본으로 쓰이든 행동 생성 모듈로 쓰이든 상관없다. 이런 모델은 예측한 행동의 각 성분마다, 가능한 각 클래스에 확률을 매긴다. TB-PCS는 가장 높은 예측 확률 {{< katex >}}max(p_i){{< /katex >}}와 두 번째로 높은 예측 확률 {{< katex >}}\textit{second-max} (p_i){{< /katex >}}의 차이를 재서 불확실성을 정량화한다. 차이가 크면 1위 예측에 대한 확신이 높다는 뜻이고, 차이가 작으면 상위 후보들 사이에서 모델이 확신하지 못한다는 뜻이다. 형식적으로 PCS 지표는 다음과 같이 계산한다.

{{< katex display=true >}}
PCS(I) = max(p_i) - \textit{second-max} (p_i) \tag{9}
{{< /katex >}}

다만 여러 불확실성 지표를 같은 방향으로 해석하려면, 지표가 낮을수록 모델의 불확실성이 낮아야 한다. 또 성분(토큰)이 여러 개인 행동에도 쓸 수 있어야 한다. 그래서 시점 {{< katex >}}t{{< /katex >}}에서의 TB-PCS 불확실성 지표는 1에서 PCS의 토큰 평균을 빼서 다음과 같이 계산한다.

{{< katex display=true >}}
u_t = 1 - \frac{1}{TN} \sum_{tn=1}^{TN} PCS(a_{t,tn}) \tag{10}
{{< /katex >}}

여기서 {{< katex >}}u_t{{< /katex >}}가 높을수록 모델의 불확실성이 높다는 뜻이다. {{< katex >}}TN{{< /katex >}}은 행동 하나를 이루는 토큰 수이고, {{< katex >}}tn{{< /katex >}}은 한 행동의 토큰 중 특정 토큰을 가리키는 인덱스다.

### 3.6 DeepGini (TB-D)

DeepGini는 모델이 행동의 각 성분마다 내놓는 토큰 기반 확률 분포를 이용한다. 이 지표는 분포가 얼마나 한쪽에 몰려 있는지를 정량화한다.

{{< katex display=true >}}
DeepGini(I) = 1 - \sum_{i=1}^{n} \, p_i^2 \tag{11}
{{< /katex >}}

이 식에서 뾰족한 분포는 한 클래스에 대한 확신이 높다는 뜻이고, 더 고른 분포는 여러 클래스 사이에서 불확실성이 크다는 뜻이다. 이 원리를 바탕으로 DeepGini 토큰 기반(DeepGini Token-Based, TB-D) 불확실성 지표를 정의한다. 값이 클수록 모델의 토큰 예측에 대한 불확실성이 크다. 이 불확실성 지표는 다음과 같이 나타낸다.

{{< katex display=true >}}
u_t = \frac{1}{TN} \sum_{tn=1}^{TN} DeepGini(a_{t,tn}) \tag{12}
{{< /katex >}}

여기서 {{< katex >}}TN{{< /katex >}}은 행동 하나를 이루는 토큰 수이고, {{< katex >}}tn{{< /katex >}}은 한 행동의 토큰 중 특정 토큰을 가리키는 인덱스다.

> **역주.** 식 (11)은 지니 불순도(Gini impurity)와 같은 형태다. 확률 하나가 1이고 나머지가 0이면 값이 0이고, {{< katex >}}n{{< /katex >}}개 클래스에 확률이 고르게 퍼질수록 {{< katex >}}1-1/n{{< /katex >}}에 가까워진다.

### 3.7 Entropy (TB-E)

마지막으로 제안하는 토큰 기반 불확실성 지표는 엔트로피(Entropy, TB-E)다. DeepGini와 마찬가지로, 이 지표는 모델이 예측한 확률 분포가 얼마나 퍼져 있는지를 평가해 불확실성을 정량화한다. 모델이 넓은 범위의 출력에 비슷한 확률을 매기면 불확실하다는 뜻이고, 그 결과 엔트로피가 높아진다. 입력 {{< katex >}}I{{< /katex >}}에 대한 엔트로피는 다음과 같이 계산한다.

{{< katex display=true >}}
Entropy(I) = - \sum_{i=1}^{n} \, p_i \, \log \, p_i \tag{13}
{{< /katex >}}

여기서 {{< katex >}}p_i{{< /katex >}}는 클래스 {{< katex >}}i{{< /katex >}}에 매겨진 확률이고, {{< katex >}}N{{< /katex >}}은 가능한 클래스의 총수다. 시점 {{< katex >}}t{{< /katex >}}가 주어지면, TB-E 지표로 전체 불확실성을 계산하기 위해 모델 출력의 각 성분마다 엔트로피를 구해 평균한다.

{{< katex display=true >}}
u_t = \frac{1}{TN} \sum_{tn=1}^{TN} Entropy(a_{t,tn}) \tag{14}
{{< /katex >}}

여기서 {{< katex >}}TN{{< /katex >}}은 행동 하나를 이루는 토큰 수이고, {{< katex >}}tn{{< /katex >}}은 한 행동의 토큰 중 특정 토큰을 가리키는 인덱스다.

> **역주.** 본문의 "{{< katex >}}N{{< /katex >}}은 가능한 클래스의 총수"는 식 (11), (13)의 합 상한 {{< katex >}}n{{< /katex >}}을 가리키는 것으로 보인다. 3.8절에서는 {{< katex >}}N{{< /katex >}}이 다시 추론 횟수라는 다른 뜻으로 쓰인다.

### 3.8 Execution Variability (EV)

VLA 모델은 본래 확률적(stochastic)이다. 입력 {{< katex >}}I{{< /katex >}}가 같다면, 확신하는 VLA 모델은 여러 번 추론해도 일관된 출력을 낼 것으로 기대된다. 실행 변동성(Execution Variability, EV) 불확실성 지표는 같은 입력에 반복 추론해서 나온 출력이 얼마나 흩어지는지를 평가해, 모델 의사결정의 내적 일관성을 정량화한다. 구체적으로, 작업의 각 단계에서 입력을 VLA 모델에 여러 번 통과시키고[^1], 그 출력의 표준편차를 계산한다. 불확실성 점수는 다음과 같이 계산한다.

[^1]: 실제로는 VLA 모델 인스턴스를 여러 개 따로 만들어야 한다. 단계 {{< katex >}}t{{< /katex >}}의 추론이 단계 {{< katex >}}t+1{{< /katex >}}의 추론에 영향을 줄 수 있기 때문이다.

{{< katex display=true >}}
u_t = \frac{1}{D} \sum_{d=1}^{D}\sqrt{\frac{1}{N}\sum^{N}_{n=1}{\left(a_{t,d,n} - \left(\frac{1}{N}\sum^{N}_{m=1}{a_{t,d,m}}\right)\right)^2}} \tag{15}
{{< /katex >}}

여기서 {{< katex >}}N{{< /katex >}}은 단계당 추론 횟수, {{< katex >}}D{{< /katex >}}는 행동의 차원 수, {{< katex >}}t{{< /katex >}}는 시간 단계다. {{< katex >}}a_{t,s,n}{{< /katex >}}은 {{< katex >}}n{{< /katex >}}번째 추론이 시간 단계 {{< katex >}}t{{< /katex >}}에 대해 내놓은, 차원 {{< katex >}}d{{< /katex >}}의 행동이다. 즉 차원마다 {{< katex >}}N{{< /katex >}}번 추론 결과의 표준편차를 구해 차원에 걸쳐 평균한 값이다.

> **역주.** 원문은 {{< katex >}}a_{t,s,n}{{< /katex >}}이라고 썼지만 식 (15)에 맞춰 보면 {{< katex >}}a_{t,d,n}{{< /katex >}}을 뜻한다.

표준편차는 같은 입력을 여러 번 평가했을 때 VLA 모델의 예측이 얼마나 흩어지는지를 정량적으로 보여 준다. 이 흩어짐은 모델이 자기 의사결정을 얼마나 확신하는지를 반영하므로 불확실성의 지표가 된다. 표준편차가 클수록 출력이 일관되지 않다는 뜻이다. 이는 입력이 모호하거나, 학습 데이터에 충분히 나타나지 않았거나, 모델이 해석하기에 본래 어려운 입력이라는 것을 나타낼 수 있다.

## 4 Quality Metrics

이 절에서는 VLA 모델이 수행한 작업의 품질을 평가하도록 설계한 새로운 품질 지표 5개를 소개한다. 작업 성공이나 완료에만 집중하는 전통적인 성능 지표와 달리, 이 지표들은 로봇 움직임의 품질을 평가하는 것을 목표로 한다. 즉 매끄러움, 안정성, 사람다운 거동 같은 요소를 포착한다. 이 새 지표들은 작업 품질을 더 자세히 보여 주므로, VLA 모델이 높은 품질의 자연스러운 거동을 얼마나 잘 만들어 내는지 더 깊이 이해할 수 있게 한다.

### 4.1 Trajectory Position Instability (TCP-PI)

TCP 궤적 위치 불안정성(TCP Trajectory Position Instability, TCP-PI)은 로봇 움직임의 매끄러움을 정량화한다. 이를 위해 말단 장치(end-effector, 그리퍼처럼 팔 끝에 달린 도구)의 위치가 시간에 따라 얼마나 변하는지를 잰다. A-PI, A-VI, A-AI 같은 지표와 달리, TCP-PI는 로봇의 툴 중심점(Tool Center Point, TCP)이라는 물리적 위치를 명시적으로 평가한다. 그래서 실행된 궤적의 품질과 정밀도에 대해 유용한 정보를 준다.

> **역주.** 3절의 A- 지표는 모델이 *명령한* 행동 값을 보고, 4절의 TCP- 지표는 시뮬레이터에서 로봇 팔 끝이 *실제로* 움직인 위치를 본다. 계산 방식(1·2·3차 차분)은 서로 같다.

TCP 점의 시퀀스 {{< katex >}}\{p_1,p_2,...,p_T\}{{< /katex >}}가 주어졌다고 하자. 각 점 {{< katex >}}p_t = (x_t,y_t,z_t){{< /katex >}}는 시점 {{< katex >}}t{{< /katex >}}에서 로봇 말단 장치의 3차원 위치다. {{< katex >}}t > 1{{< /katex >}}에 대해 1차 차분을 계산한다.

{{< katex display=true >}}
\Delta p_t = p_t - p_{t-1}, \tag{16}
{{< /katex >}}

이 차분은 연속한 시간 단계 사이에 TCP 위치가 얼마나 바뀌었는지를 정량화한다. 이를 이용해 품질 지표를 다음과 같이 정의한다.

{{< katex display=true >}}
\text{q}_t = \left| \Delta p_t \right| \tag{17}
{{< /katex >}}

여기서 {{< katex >}}q_t{{< /katex >}} 값이 낮을수록 궤적이 더 매끄럽고 안정적이라는 뜻이다. 반대로 값이 높으면 움직임이 빠르거나 일관되지 않다는 뜻이며, 궤적 품질이 낮아서 생긴 것일 수 있다.

> **역주.** 4절의 {{< katex >}}q_t{{< /katex >}}, {{< katex >}}q{{< /katex >}}는 품질 지표 값이다. 2절에서 같은 글자 {{< katex >}}q_t{{< /katex >}}는 로봇의 고유수용 상태를 뜻했다. 또 4절의 {{< katex >}}p_t{{< /katex >}}는 위치이지 3절의 확률 {{< katex >}}p_i{{< /katex >}}가 아니다. 품질 지표도 불확실성 지표처럼 값이 낮을수록 좋다.

### 4.2 Trajectory Velocity Instability (TCP-VI)

3.2절에서 논의했듯, 위치 변화가 크다고 해서 반드시 움직임이 불규칙한 것은 아니다. 빠른 움직임 때문에 생길 수도 있다. 이에 대한 대안으로 궤적 속도 불안정성(Trajectory Velocity Instability, TCP-VI)을 제안한다. 이 지표는 움직임의 가속도를 평가한다. 이를 위해 다음과 같이 2차 차분을 계산한다.

{{< katex display=true >}}
\Delta^2 p_t = \Delta p_t - \Delta p_{t-1} = p_t - 2p_{t-1} + p_{t-2} \tag{18}
{{< /katex >}}

이 값은 말단 장치의 속도 변화를 포착한다. {{< katex >}}|\Delta^2 p_t|{{< /katex >}}가 갑자기 치솟으면 가속도가 불규칙하다는 뜻이고, 불안정한 거동을 반영할 수 있다. 이에 따라 품질 지표를 다음과 같이 정의한다.

{{< katex display=true >}}
\text{q}_t = \left| \Delta^2 p_t \right| \tag{19}
{{< /katex >}}

여기서 {{< katex >}}q_t{{< /katex >}} 값이 낮을수록 가속이 매끄럽고 궤적 실행이 더 일관된다는 뜻이다. 반대로 값이 높으면 로봇의 속도 조절이 불안정하다는 뜻이다.

### 4.3 Trajectory Acceleration Instability (TCP-AI)

앞의 TCP 기반 품질 지표 두 개에 더해, 3차 차분도 계산해 궤적 가속도 불안정성(Trajectory Acceleration Instability, TCP-AI) 지표를 도입한다. 이 지표는 로봇의 가속도가 시간에 따라 어떻게 변하는지를 포착한다.

{{< katex display=true >}}
\Delta^3 p_t = \Delta^2 p_t - \Delta^2 p_{t-1} = p_t - 3p_{t-1} + 3p_{t-2} - p_{t-3} \tag{20}
{{< /katex >}}

이 도함수는 로봇이 서로 다른 가속 국면 사이를 얼마나 매끄럽게 넘어가는지 평가한다. 값이 크면 가속도가 급변한다는 뜻이며, 로봇 궤적이 떨리거나 덜덜거리는 모습으로 나타날 수 있다. 이 척도를 바탕으로 품질 지표를 다음과 같이 정의한다.

{{< katex display=true >}}
\text{q}_t = \left| \Delta^3 p_t \right| \tag{21}
{{< /katex >}}

여기서 값이 낮을수록 궤적이 매끄럽고, 사용자가 느끼는 품질이 높아진다. 궤적이 이렇게 떨리는 안티패턴(바람직하지 않은 거동)은 실무자들이 GR00T-N1 저장소에 이미 이슈로 보고한 바 있다[^2].

[^2]: <https://github.com/NVIDIA/Isaac-GR00T/issues/114>

### 4.4 Trajectory Instability (TI)

궤적 불안정성(Trajectory Instability, TI) 품질 지표는 로봇의 물리적 거동, 특히 말단 장치의 움직임이 시간에 따라 어떻게 전개되는지를 분석해 작업 품질을 정량화한다. 이 지표는 VLA 모델이 예측한 행동이 아니라, 궤적의 매끄러움과 일관성을 평가하는 데 초점을 둔다. TCP 기반 품질 지표와 비슷하지만, 이 지표는 특정 시간 단계의 품질 지표가 아니라 작업 전체의 품질 지표다. 일반적으로 사용자는 더 매끄러운 움직임을 더 높은 품질로 인식하므로, 이 지표는 움직임의 매끄러움을 평가해 로봇 움직임의 품질을 평가한다.

이런 매끄럽지 않은 움직임을 포착하기 위해 저크(jerk)를 지표로 쓴다. 저크는 위치의 3계 시간 도함수, 즉 가속도의 변화율이다. 저크는 로봇공학에서 움직임의 매끄러움을 평가하는 데 널리 쓰여 왔다 [28, 29]. 또한 Flash et al. [30]의 연구는 사람의 움직임이 최소 저크 원리(minimum-jerk principle)를 따른다는 것을 보였다. 이 관점에서 저크가 최소인 움직임이 가장 매끄럽다고 본다. 저크가 낮다는 것은 가속도가 급격한 전환 없이 점진적이고 연속적으로 바뀐다는 뜻이기 때문이다.

로봇 말단 장치의 위치 벡터로 정의되는 궤적이 다음과 같이 주어진다고 하자.

{{< katex display=true >}}
\vec{r}(t) = \big(x(t), y(t), z(t)\big) \tag{22}
{{< /katex >}}

이 궤적은 일정한 시간 간격 {{< katex >}}\Delta t{{< /katex >}}로 샘플링된다. 그러면 속도 {{< katex >}}\vec{v}(t){{< /katex >}}, 가속도 {{< katex >}}\vec{a}(t){{< /katex >}}, 저크 {{< katex >}}\vec{j}(t){{< /katex >}}는 다음과 같다.

{{< katex display=true >}}
\vec{v}(t) = \frac{d\vec{r}(t)}{\Delta t},\quad \vec{a}(t) = \frac{d\vec{v}(t)}{\Delta t},\quad \vec{j}(t) = \frac{d\vec{a}(t)}{\Delta t} \tag{23}
{{< /katex >}}

> **역주.** 여기서 {{< katex >}}\vec{a}(t){{< /katex >}}는 말단 장치의 가속도로, 2·3절의 행동 {{< katex >}}a_t{{< /katex >}}와 다른 양이다. 또 식 (23)의 {{< katex >}}d{{< /katex >}}는 차분(연속한 샘플 사이의 변화량)을 뜻하며 3절의 차원 인덱스 {{< katex >}}d{{< /katex >}}와 관계없다.

따라서 품질 지표로서, 각 시간 단계에서 가속도의 순간 변화율을 평가한다. 구체적으로 그 시간 단계에서 저크 벡터의 크기를 다음과 같이 계산한다.

{{< katex display=true >}}
\lVert \vec{j}_i \rVert = \sqrt{j_{x,i}^2 + j_{y,i}^2 + j_{z,i}^2} \tag{24}
{{< /katex >}}

이 정보를 궤적 전체에 걸쳐 모아 하나의 품질 지표로 만들기 위해, Hogan et al. [28]이 제안한 대로 RMS(Root Mean Square, 제곱평균제곱근) 저크를 계산한다. 이 값은 작업 실행 전체 구간의 움직임 품질을 하나로 요약한 척도가 된다.

{{< katex display=true >}}
q = J_{RMS} = \sqrt{\frac{1}{T - 3} \sum_{t=1}^{T - 3} \lVert \vec{j}_t \rVert^2} \tag{25}
{{< /katex >}}

여기서 {{< katex >}}T{{< /katex >}}는 전체 샘플 수다. 이 값은 움직임의 매끄러움을 강건하게 잰다. RMS 저크가 낮을수록 더 높은 품질의 일관된 궤적이고, 높을수록 불규칙하거나, 진동하거나, 급격한 움직임이다.

> **역주.** 위치 샘플이 {{< katex >}}T{{< /katex >}}개이면 3차 차분(저크)은 {{< katex >}}T-3{{< /katex >}}개 나오므로, 식 (25)는 그 {{< katex >}}T-3{{< /katex >}}개의 저크 크기를 제곱평균한 뒤 제곱근을 취한 것이다.

### 4.5 Optimal Trajectory Difference (OT)

최적 궤적 차이(Optimal Trajectory Difference, OT)는 로봇 말단 장치가 작업과 관련된 기준 위치에 얼마나 가까운지를 재서 로봇 작업 실행의 품질을 평가한다. 매끄러움이나 안정성을 평가하는 움직임 중심 지표(예: 궤적 불안정성)와 달리, 이 지표는 목표 지향적 거동에 초점을 둔다. 핵심 직관은 이렇다. 효과적인 궤적이라면 작업이 진행될수록 목표 물체나 목표 위치까지의 거리가 꾸준히 줄어야 한다. 거리가 늘어나는 등 이 기대 패턴에서 벗어나면 망설임이나 최적이 아닌 의사결정을 나타낼 수 있다.

작업 종류가 달라도 의미가 일관되도록, 이 지표는 작업 맥락에 맞춰 기준점을 바꾼다. 즉 측정 방식을 작업마다 따로 정했다. `"Pick Up"` 작업에서는 매 시간 단계마다 TCP와 물체 위치(pose) 사이의 유클리드 거리를 계산한다.

{{< katex display=true >}}
d_t = \left\lVert \vec{p}_{tcp}(t) - \vec{p}_{obj}(t) \right\rVert \tag{26}
{{< /katex >}}

이 값은 로봇이 잡기를 시작하려고 물체에 얼마나 효과적으로 다가가는지를 반영한다.

*"Move"*, *"Put In"*, *"Put On"* 같은 배치·이동 작업에서는 물체를 잡는 데 성공했는지에 따라 기준점이 동적으로 바뀐다. 잡기 전에는 대상 물체까지의 거리를 재서 로봇이 올바른 물체에 집중하는지 확인한다. 이와 함께 물체에서 의도한 목적지까지의 거리도 고려한다. 잡은 뒤에는 최종 목표 위치(예: 용기나 표면)를 기준으로 거리를 계산해, 배치 단계가 얼마나 효과적인지를 포착한다.

{{< katex display=true >}}
d_t =
\begin{cases}
\left\lVert \vec{p}_{tcp}(t) - \vec{p}_{obj}(t) \right\rVert + \left\lVert \vec{p}_{tcp}(t) - \vec{p}_{end} \right\rVert, & \text{if object not grasped} \\
\left\lVert \vec{p}_{tcp}(t) - \vec{p}_{end} \right\rVert, & \text{if object grasped}
\end{cases} \tag{27}
{{< /katex >}}

> **역주.** 본문은 잡기 전에 "물체에서 목적지까지의 거리"도 고려한다고 설명하지만, 식 (27)의 둘째 항은 TCP에서 목적지 {{< katex >}}\vec{p}_{end}{{< /katex >}}까지의 거리로 쓰여 있다. 여기서는 식을 원문 그대로 옮겼다.

시간에 따른 로봇 거동의 일관성을 평가하기 위해, 거리 시퀀스 {{< katex >}}\{d_1, d_2, \dots, d_N\}{{< /katex >}}가 시간에 따라 어떻게 변하는지를 분석한다. 이를 위해 이산 1계 도함수를 계산한다.

{{< katex display=true >}}
\Delta d_t = d_t - d_{t-1} \tag{28}
{{< /katex >}}

도함수가 음수({{< katex >}}\Delta d_t < 0{{< /katex >}})이면 목표를 향해 효과적으로 나아가고 있다는 뜻이고, 양수({{< katex >}}\Delta d_t > 0{{< /katex >}})이면 목표에서 멀어지고 있다는 뜻이다. 그런 다음 {{< katex >}}\Delta d_t{{< /katex >}}를 [0, 1] 범위로 정규화해 OT 지표를 계산한다.

{{< katex display=true >}}
q_t = \frac{1}{2} (1 + \Delta d_t) \tag{29}
{{< /katex >}}

따라서 이 지표 값이 낮을수록 VLA의 성능이 좋다는 뜻이다.

> **역주.** 식 (29)에서 거리가 그대로면({{< katex >}}\Delta d_t = 0{{< /katex >}}) {{< katex >}}q_t = 0.5{{< /katex >}}가 되고, 가까워지면 0.5보다 작아지며 멀어지면 커진다. 또 4.5절의 {{< katex >}}N{{< /katex >}}은 거리 시퀀스의 길이로, 3.8절의 추론 횟수 {{< katex >}}N{{< /katex >}}과 다르다.

## 5 Empirical Study

VLA 기반 로봇 시스템에서 제안한 불확실성 지표와 품질 지표가 얼마나 잘 작동하는지 조사하기 위해 실증 연구를 수행했다. 이 절에서는 연구 질문(Research Question, RQ)을 제시하고 평가 설정을 설명한다.

### 5.1 Research Questions

제안한 불확실성 지표와 품질 지표의 효과와 실행 오버헤드를, VLA 모델 3개와 VLATest [8]의 평가에 쓰인 작업 4개에 걸쳐 평가했다. 구체적으로 다음 RQ에 답하고자 한다.

- **RQ1 – Replication:** *VLATest에서 성공으로 판정된 작업은, 사람이 판단한 작업 품질과 얼마나 맞아떨어지는가?* 성공한 작업의 품질을 평가하기 위해 Wang et al. [8]의 실험을 재현한다. 이를 위해 VLATest [8]가 성공으로 분류한 테스트 케이스를 사람 전문가가 더 자세히 분석했다.
- **RQ2 – Correlation:** *제안한 불확실성 지표와 품질 지표는 로봇의 성능을 얼마나 정확히 반영하는가?* 제안한 지표가 로봇 성능 저하를 알려 주는 신호 역할을 할 수 있는지 평가한다. 이를 위해 3절과 4절에서 제안한 지표가 해당 분야 전문가가 매긴 품질 수준과 얼마나 상관이 있는지 조사한다.
- **RQ3 – Discrimination:** *제안한 지표는 성공한 작업과 실패한 작업을 얼마나 구별할 수 있는가?* 제안한 지표가 로봇의 작업 성공과 관련이 있는지 조사한다. 작업별로 각 지표의 분포와 효과 크기를 분석해, 지표가 작업 성공·실패를 알려 주는 신호로 쓰일 수 있는지 평가한다.
- **RQ4 – Overhead:** *이 지표들을 통합하면 추론 시간이 어떻게 달라지는가?* 로봇 시스템의 제어는 실시간으로 이루어지므로 VLA 모델의 추론 시간은 매우 중요하다. 따라서 앞으로 실무자들이 지표 도입을 판단할 수 있도록, 각 지표가 만드는 오버헤드를 연구하는 것이 무엇보다 중요하다. 이 RQ는 제안한 불확실성 지표와 품질 지표 각각의 계산 비용을 연구한다.

### 5.2 VLA Models

평가에는 최신 VLA 모델 3개, 즉 OpenVLA [6], SpatialVLA [7], {{< katex >}}\pi_0{{< /katex >}} [5]를 썼다. 이 세 모델을 고른 이유는 (1) 비교적 최근 모델이고, (2) 비교적 잘 알려져 있으며, (3) 연구 [6, 5, 7]에서 보고된 성능이 꽤 높았기 때문이다. 또한 세 모델 모두 공개되어 있고, 오픈소스 시뮬레이터의 로봇에 맞춰 파인튜닝된 버전이 있었다. 벤치마크 데이터셋 2개(Fractal, Bridge) 각각으로 파인튜닝된 버전을 썼고, 각 버전은 평가 작업 두 개씩에 쓰인다. *Pick up*과 *Move Near* 작업용 모델은 Google Robot용으로, *Put on*과 *Put in* 작업용 모델은 WidowX 로봇용으로 학습되었다. 모델별로 사용한 체크포인트는 다음과 같다.

- **OpenVLA:** 저자들이 HuggingFace에 공개한 기본 체크포인트를 썼다 [31].
- **{{< katex >}}\pi_0{{< /katex >}}:** SpatialVLA 저자들이 자기 평가에 썼던 체크포인트를 썼다. 데이터셋마다 하나씩, 두 버전의 모델을 썼다. Fractal 데이터셋용 체크포인트는 [32]에서, Bridge 데이터셋용 체크포인트는 [33]에서 구할 수 있다.
- **SpatialVLA:** 두 데이터셋을 섞어 사전학습한 체크포인트 [34]를 썼다. 이 체크포인트는 SpatialVLA 논문 [7]에서 공개한 것이다.

각 모델 구조에 대한 자세한 설명은 부록 A.1에 있다. SpatialVLA와 {{< katex >}}\pi_0{{< /katex >}}은 VLATest [8]에서 쓰이지 않았으므로, 이 연구는 두 모델에 대한 새로운 결과를 제공한다.

### 5.3 Environments

VLATest [8]와 마찬가지로 *SimplerEnv* 벤치마크 [35]로 평가했다. 로봇 플랫폼 2개와 서로 다른 작업 모두 4개에 걸쳐 지표의 효과를 평가했다. 첫 번째 로봇 팔은 이른바 Google 로봇으로, Everyday Robot[^3]이며, VLA 모델 학습에는 Fractal 데이터셋 [23]이 쓰였다. 두 번째 로봇 팔은 WidowX 로봇이며, VLA 모델 학습에는 Bridge V2 데이터셋 [36]이 쓰였다. 평가에는 [8]에서 고른 것과 같은 작업 4개를 썼다. 두 작업은 한 로봇에, 나머지 두 작업은 다른 로봇에 해당하며, 아래와 같다.

[^3]: <https://everydayrobots.ai/>

- **Task 1: Pick Up an Object.** VLA 모델은 대상 물체를 찾아내고, 그것을 잡아 들어 올리는 제어 신호를 생성해야 한다. 성공하려면 로봇이 올바른 물체를 잡아 연속 5프레임 동안 최소 0.02미터 들어 올려야 한다. 이 작업은 Google 로봇으로 평가했다.
- **Task 2: Move Object A near Object B.** VLA 모델은 원래 물체 A의 위치를 찾고, 그것을 대상 물체 B 근처로 옮기는 제어 신호를 생성해야 한다. 물체 A가 물체 B로부터 0.05미터 이내에 놓이면 성공으로 본다. 이 작업은 Google 로봇으로 평가했다.
- **Task 3: Stack Object A on Object B.** VLA 모델은 물체 A를 물체 B 위에 안정적으로 올려놓아야 한다. 물체 A가 넘어지지 않고 물체 B 위에서 균형을 유지하면 성공이다. 이 작업은 WidowX 로봇으로 평가했다.
- **Task 4: Place Object A Inside Object B.** VLA 모델은 물체 A를 물체 B 안에 완전히 넣는 제어 신호를 생성해야 한다(예: *"Place the apple into the basket"*). 물체 A가 물체 B 안에 완전히 들어가면 성공으로 본다. 이 작업은 WidowX 로봇으로 평가했다.

> **역주.** 이후 본문과 표에서 Task 1\~4는 각각 *Pick up*, *Move near*, *Put on*, *Put in*이라는 짧은 이름으로 불린다.

각 작업마다 Wang et al. [8]이 생성한 장면 중 처음 500개를 썼다. 이 장면들에서 대상 물체는 무작위로 골랐고, 헷갈리게 하는 방해 물체가 0\~3개 함께 놓였다. 각 물체의 위치와 자세는 [8]에서 설명한 몇 가지 제약을 따르며 무작위로 정했다. 물체끼리 겹쳐 충돌하지 않도록, 배치할 때 물체 사이에 최소 0.15미터 간격을 두었다. 환경의 조명과 카메라 자세는 기본 설정을 썼다.

### 5.4 Configurations

재현성을 보장하고 후속 연구와 공정하게 비교할 수 있도록, 실험에 쓴 관련 파라미터 설정을 모두 보고한다. 결과를 재현하는 데 핵심이 되는 요소는 VLA 모델 가중치이며, 이는 5.3절에서 설명했다. 모델 체크포인트에 더해, 환경을 초기화할 때 모든 모델에 같은 고정 시드를 썼다. 그래서 모든 평가에서 초기 장면 상태가 똑같이 유지되었다.

> **역주.** 원문은 모델 가중치가 5.3절에 설명되어 있다고 하지만, 체크포인트 목록은 실제로 5.2절에 있다.

불확실성·품질 지표의 설정 파라미터는 다음과 같다. EV 지표는 추론 샘플 4개로 설정했다. 하드웨어에 추가로 올릴 수 있는 모델 인스턴스의 최대 개수가 4였기 때문이다. TCP-PI, TCP-VI, TCP-AI, A-PI, A-VI, A-AI 지표는 계산에 시간 차분이 필요하다. 그래서 직전 몇 단계의 데이터를 함께 모으는 시간 윈도를 정했다. 차분 값은 윈도 가장자리의 값에 특히 민감하다. 이 때문에 A-AI와 TCP-AI를 계산하는 데 필요한 최소 범위인 4 시간 단계로는 충분히 정확한 결과가 나오지 않았다. 따라서 신뢰도를 높이려고 윈도 크기를 8 시간 단계로 늘렸다. 이 값은 경험적 관찰을 바탕으로 정했다. 더 작은 윈도(예: 5\~6단계)는 추정을 덜 안정적으로 만들었고, 단기 요동에 민감한 A-AI와 TCP-AI에서 특히 그랬다. 윈도를 8로 늘리자 시간적 맥락과 계산 비용 사이의 균형이 더 좋아졌고, 지표 값이 더 일관되고 믿을 만해졌다.

### 5.5 Execution Platform and Runs

실험 속도를 높이려고 작업량을 실행 플랫폼 두 곳에 나눴다. {{< katex >}}\pi_0{{< /katex >}} 모델 실험은 AMD EPYC 7773X CPU와 NVIDIA RTX A6000 GPU를 갖춘 서버에서 실행했다. OpenVLA와 SpatialVLA 실험은 모두 AMD EPYC 7763 CPU와 NVIDIA A100-SXM4-80GB GPU 2장을 갖춘 서버에서 실행했다. 두 서버 모두 운영체제는 64비트 Ubuntu 20.04 LTS였고, Python 3.10과 CUDA 12.8을 썼다.

모델마다 내부 구조와 가중치가 달라 자원 소비 수준이 달랐고, 이는 장면 실행 시간에도 영향을 주었다. 장면 하나를 실행하는 데 평균적으로 SpatialVLA는 약 270초, {{< katex >}}\pi_0{{< /katex >}}은 235초, OpenVLA는 210초가 걸렸다. 네 작업 각각에 장면이 500개씩 있으므로, 필요한 총 GPU 시간은 4 (작업) {{< katex >}}\times{{< /katex >}} 500 (장면) {{< katex >}}\times{{< /katex >}} (270 + 235 + 210)초 = 1,430,000초 = 397 GPU 시간이었다.

### 5.6 Human Evaluation Procedure

### 5.7 Statistical tests

RQ2에서는 성공 작업의 품질 수준과 지표 사이의 상관을 스피어만 순위 상관(Spearman's rank correlation)으로 통계적으로 측정했다. p-값이 0.05 미만이면 통계적으로 유의하다고 보았다. 양의 상관은 지표가 작업 품질의 차이를 포착할 수 있음을 뜻한다. Cohen [37]에 따라 결과를 다음과 같이 해석한다. {{< katex >}}\rho{{< /katex >}} {{< katex >}}<{{< /katex >}} 0.10이면 *상관 없음*, 0.10 {{< katex >}}\leq{{< /katex >}} {{< katex >}}\rho{{< /katex >}} {{< katex >}}\leq{{< /katex >}} 0.29이면 *약한 상관*, 0.29 {{< katex >}}<{{< /katex >}} {{< katex >}}\rho{{< /katex >}} {{< katex >}}\leq{{< /katex >}} 0.49이면 *중간 상관*, {{< katex >}}\rho{{< /katex >}} {{< katex >}}>{{< /katex >}} 0.49이면 *강한 상관*이다.

> **역주.** 품질 레이블은 고품질을 작은 값으로 두고 순위를 매긴 것으로 보인다. 그래서 "지표 값이 낮을수록 품질이 높다"는 관계가 양의 {{< katex >}}\rho{{< /katex >}}로 나타난다(표 3 캡션 참조).

RQ3에서는 성공 작업을 품질 수준별로 나누고, 각 수준의 결과가 실패 작업의 결과와 얼마나 다른지 측정했다. 이를 위해 먼저 Shapiro-Wilk 검정으로 데이터 분포를 분석했다. 데이터가 정규분포를 따르지 않았으므로 Mann-Whitney U 검정(정규성을 가정하지 않고 두 집단을 비교하는 순위 기반 검정)을 썼다. p-값이 0.05 미만이면, 해당 품질 수준의 작업과 실패 작업 사이에서 지표가 통계적으로 유의한 차이를 보인다고 보았다. 또한 Vargha와 Delaney의 {{< katex >}}\hat{A}_{12}{{< /katex >}} 값으로 효과 크기를 평가했다. Romano et al. [38]에 따라 {{< katex >}}\hat{A}_{12}{{< /katex >}}의 효과 크기를 다음과 같이 분류한다. {{< katex >}}d < 0.147{{< /katex >}}이면 *무시할 수준(negligible)*, {{< katex >}}d <{{< /katex >}} 0.33이면 *작음(small)*, {{< katex >}}d < 0.474{{< /katex >}}이면 *중간(medium)*, {{< katex >}}d \geq 0.474{{< /katex >}}이면 *큼(large)*\ 이다. 여기서 {{< katex >}}d = 2\lvert\hat{A}_{12} - 0.5\rvert{{< /katex >}}다.

> **역주.** {{< katex >}}\hat{A}_{12}{{< /katex >}}는 첫 번째 집단(여기서는 성공 작업의 한 품질 수준)에서 무작위로 뽑은 값이 두 번째 집단(실패 작업)에서 뽑은 값보다 클 확률이다. 0.5면 두 집단이 차이가 없고, 0.5보다 작으면 성공 쪽 지표 값이 대체로 작다(즉 불확실성이 낮거나 품질이 좋다). 여기서의 {{< katex >}}d{{< /katex >}}는 효과 크기이며, 3절의 차원 인덱스 {{< katex >}}d{{< /katex >}}나 4.5절의 거리 {{< katex >}}d_t{{< /katex >}}와 다르다.

### 6.1 RQ1 - Replication

RQ1은 Wang et al. [8]의 실험을 재현하되, 중요한 변경이 하나 있다. 성공한 작업에 사람이 직접 고품질·중품질·저품질 결과라는 레이블을 달았다. 또한 거짓 음성(false negative) 몇 건을 찾아냈다. 이는 테스트 오라클이 *"success"*\ 로 판정했지만 그렇게 판정되어서는 안 되었던 작업이다(예: 물체가 처음부터 이미 대상 물체 안에 놓여 있었던 경우).

> **역주.** 오라클이 "성공"이라고 잘못 판정한 경우이므로 통상의 용어로는 거짓 양성에 가깝지만, 원문은 이를 false negative라고 부른다. 여기서는 원문 용어를 따른다.

표 2는 RQ1의 전체 결과를 보여 준다. 성공률 면에서는 대체로 {{< katex >}}\pi_0{{< /katex >}}과 SpatialVLA가 OpenVLA보다 나았다. OpenVLA의 성공률은 1.2\~13.8%였다. 성공률만 보면 SpatialVLA가 *Pick up*과 *Move near* 작업에서 가장 좋은 모델로, 성공률이 각각 38.2%와 20.8%였다. 반면 {{< katex >}}\pi_0{{< /katex >}}은 *Put In*과 *Put on* 작업에서 더 나았고, 성공률은 각각 14.4%와 18.6%였다. 앞의 두 작업에는 Google 로봇이, 뒤의 두 작업에는 WidowX 로봇이 쓰였다. 이는 로봇 종류가 작업의 전반적인 성능에 영향을 줄 수 있음을 시사한다.

> **발견 1 (Finding 1).** 성공률만 보면, 앞의 두 작업(Google 로봇)에서는 SpatialVLA가, 뒤의 두 작업(WidowX 로봇)에서는 {{< katex >}}\pi_0{{< /katex >}}이 가장 좋은 모델이었다.

### 6.2 RQ2 - Correlation

표 3은 레이블러가 매긴 품질 수준과, 3절과 4절에서 각각 제안한 불확실성 지표·품질 지표 사이의 전체 상관을 보여 준다. 상관을 재 보니, 결과는 작업 종류와 분석한 VLA 모델에 따라 달랐다.

불확실성 지표를 보면, SpatialVLA에서는 거의 모든 지표가 통계적으로 유의한 양의 상관을 보였다. 게다가 [37]의 기준으로 이 상관은 대부분의 지표와 작업에서 강하거나 중간 수준이었다. {{< katex >}}\pi_0{{< /katex >}}에서는 A-PI, A-VI, A-AI 불확실성 지표가 *"Pick up"*\ 과 *"Put on"* 작업에서 통계적으로 유의한 강한 상관을 보였다. 반면 {{< katex >}}\pi_0{{< /katex >}}의 "*Put in*" 작업에서는 양의 상관을 보인 지표가 하나도 없었고, *"Move near"* 작업에서는 3개(TB-TP, TB-PCS, TB-E)만 통계적으로 유의한 중간 상관을 보였다. 마지막으로 OpenVLA에서는 *"Pick up"* 작업에서 모든 불확실성 지표가 통계적으로 유의한 중간 상관을 보였지만, *"Move near"* 작업에서는 상관이 없었다. 이 모델은 *"Put in"*\ 과 *"Put on"* 작업에서 표본 수가 너무 적어 의미 있는 통계 평가를 할 수 없었다.

전반적으로 불확실성 지표 중 A-VI와 A-AI가 가장 적절한 지표로 보였다. 작업-모델 조합 12개 중 8개에서 중간\~강한 상관을 보였기 때문이다. 반면 EV는 {{< katex >}}\pi_0{{< /katex >}} VLA 모델의 *"Pick up"* 작업에서만 통계적으로 유의했다. 작업-모델 조합 12개 중 6개에서는 EV 지표의 상관을 잴 수 없었다. 서로 다른 모델 인스턴스가 모든 경우에 정확히 같은 추론 값을 냈기 때문이다. 나머지 5개 경우에는 통계적으로 유의한 상관이 없었다. 따라서 이 지표를 불확실성 측정에 쓰는 것은 권하지 않는다.

> **역주.** EV는 표 3의 12개 칸 중 6개가 "-"이고, 나머지 6개 중 유의한 칸은 {{< katex >}}\pi_0{{< /katex >}}의 *Pick up*과 *Put on*(0.68) 두 곳이다. 본문의 "Pick up에서만", "나머지 5개"라는 서술과 표의 숫자가 정확히 맞지는 않으며, 본문은 이 차이를 따로 설명하지 않는다.

> **발견 3 (Finding 3).** 불확실성 지표의 성능은 구체적인 작업과 VLA 모델에 따라 다르다. 전반적으로 A-VI와 A-AI는 믿을 만한 지표로, 많은 작업에서 중간\~높은 상관을 보였다. 다만 실무자들은 자기 모델의 맥락에서 지표를 깊이 분석해 볼 것을 권한다.

품질 지표에서도 결과는 VLA 모델과 작업 종류에 따라 달랐다. 불확실성 지표와 마찬가지로, *"Pick up"* 작업에서는 사용 가능한 모든 지표가 통계적으로 유의한 상관을 보였다. 구체적으로 TCP-VI, TCP-AI, TI는 세 모델 모두에서 강한 상관을 보였다. TCP-PI와 OT는 {{< katex >}}\pi_0{{< /katex >}}에서 강한 상관을, OpenVLA와 SpatialVLA에서 중간 상관을 보였다. *"Move near"* 작업에서는 {{< katex >}}\pi_0{{< /katex >}} 모델에서 모든 지표가 중간 상관을 보였고, SpatialVLA에서는 TCP-VI, TCP-AI, TI만 중간 상관을 보였다. OpenVLA에서는 OT만 중간 상관을 보였고, 나머지는 통계적으로 유의한 상관이 없었다. 뒤의 두 작업에서 OpenVLA의 성공 실행은 매우 적었다(각각 9건과 6건). 그래서 이 작업과 모델에 대해서는 표본이 너무 작아 통계적으로 탄탄한 주장을 할 수 없다고 본다. SpatialVLA의 *"Put in"* 작업에서는 OT를 뺀 모든 지표가 통계적으로 유의한 양의 상관을 보였고, 그중 3개(TCP-VI, TCP-AI, TI)는 강한 상관이었다. 한편 이 세 번째로 다룬 작업(*Put in*)에서 {{< katex >}}\pi_0{{< /katex >}}은 TCP-PI만 통계적으로 유의한 양의 상관을 보였다. 반대로 *"Put on"* 작업에서는 {{< katex >}}\pi_0{{< /katex >}}의 경우 OT를 뺀 모든 지표가 중간\~강한 상관을 보였다. 반면 같은 작업에서 SpatialVLA는 TCP-VI만 통계적으로 유의한 양의 상관을 보였다.

전반적으로 가장 일관된 지표는 TCP-VI로 보인다. 품질이 서로 다른 성공 작업들에서 통계적으로 유의한 양의 상관을 가장 꾸준히 보였기 때문이다. 매끄럽고 끊김 없는 움직임은 정밀하고 확신 있는 제어를 반영한다. 반면 속도가 갑자기 튀는 것은 망설임이나 오류 수정을 드러내며, 이는 성능과 작업 품질을 떨어뜨린다. 즉 로봇 말단 장치(TCP)의 속도 불안정성이 VLA 모델의 작업 품질을 재는 적절한 지표로 보인다.

> **발견 4 (Finding 4).** 불확실성 지표와 마찬가지로, 품질 지표의 성능도 구체적인 작업과 VLA 모델에 따라 다르다. 전반적으로 TCP-VI가 모델과 작업에 걸쳐 가장 일관된 지표로 보이므로 사용을 권한다.

> **발견 5 (Finding 5).** 제안한 지표는 *"Move near"* 작업에서 물체의 최종 방향을 제대로 포착하지 못한다. 저자들은 이 방향을 이 작업의 중요한 측면으로 본다. 후속 연구에서는 성능을 높이기 위해 물체 방향을 지표에 통합하는 방안을 탐구할 수 있다.

제안한 불확실성·품질 지표 전체 가운데, OT가 성공 작업과 실패 작업을 가장 강력하게 구별하는 단일 지표로 일관되게 나타났다. OT는 모든 모델과 작업에서 통계적으로 유의하고 큰 {{< katex >}}\hat{A}_{12}{{< /katex >}} 효과 크기를 보였다. 유일한 예외는 OpenVLA가 "*Pick up*" 작업에서 낸 저품질 실행이다. 여기서만 OT가 실패 작업과 비교해 통계적 유의성을 보이지 않았다. 이는 VLA 기반 로봇 시스템에서 OT 지표가 모델에 상관없이 실패를 알려 주는 지표로 유용하다는 점을 보여 준다.

> **역주.** 표 5\~7을 보면 OT 행의 모든 셀이 큰 효과로 칠해진 것은 아니다(예: 표 6의 *Pick up* Low는 0.27로 중간 효과, 표 7의 *Move Near* High는 0.40). 본문의 "모든 모델과 작업에서 크다"는 전반적인 경향을 말한 것으로 읽힌다.

> **발견 6 (Finding 6).** OT는 성공 작업과 실패 작업을 일관되게, 그리고 모델에 상관없이 알려 주는 지표다.

고품질로 분류된 작업을 보면, OT 말고도 여러 지표가 작업과 모델에 따라 구별 능력을 보였다. *"Pick up"* 작업에서는 모든 지표(품질 지표와 불확실성 지표 모두)가 고품질 작업과 실패 작업을 구별하는 능력을 보였다. 다만 다음 예외가 있다. OpenVLA에서는 구별 능력을 보인 지표가 하나도 없었다. {{< katex >}}\pi_0{{< /katex >}}에서는 TB-D가 통계적 유의성을 보이지 않았다. SpatialVLA에서는 EV가 통계적 유의성을 보이지 않았다. 마찬가지로 {{< katex >}}\pi_0{{< /katex >}} 모델의 *"Move near"* 작업에서는 EV를 뺀 모든 지표가 고품질 작업을 실패 작업과 믿을 만하게 구별했고, SpatialVLA의 TB 계열 지표(TB‑TP, TB‑PCS, TB‑D, TB‑E)도 비슷한 성능을 보였다. *"Put in"* 작업의 OpenVLA에서는 이 토큰 기반 지표들이 고품질 작업과 실패 작업을 구별하는 데 유용했다. 또한 {{< katex >}}\pi_0{{< /katex >}} 모델에서는 TPC-PI를 뺀 모든 품질 지표가, 모든 작업에서 고품질 성공 작업과 실패 작업 사이의 유의한 구별력을 유지했다.

> **역주.** "TPC-PI"는 원문 표기 그대로이며 TCP-PI를 가리킨다. 또 본문에는 OpenVLA의 *Pick up*에서 구별 능력을 보인 지표가 없다고 되어 있으나, 표 5에서는 OT의 High 셀(0.06)이 칠해져 있다. 문맥상 "OT 말고는"이라는 뜻으로 읽힌다.

이 결과를 바탕으로 두 가지 유망한 방향을 내다본다. 첫째, 제안한 품질 지표에 적절한 임곗값을 정하면, 설계 단계(design-time)에서 기호 오라클에 기대지 않고도 작업이 성공하고 있는지를 믿을 만하게 평가할 수 있다. 둘째, 불확실성 지표는 실행 중(runtime)에 모니터링에 믿을 만하게 쓸 수 있다. 즉 작업 품질이 충분히 높은지 확인하고, 실패하는 작업을 자동으로 탐지할 수 있다. 이런 응용은 위험 부담이 크고 안전이 중요한 작업에서 특히 쓸모가 있다. 그런 작업에서는 품질이 무엇보다 중요하기 때문이다.

> **발견 7 (Finding 7).** OT 말고도, OpenVLA 모델을 제외하면 대부분의 불확실성·품질 지표가 고품질 작업 실행과 실패 실행을 구별하는 데 유망한 결과를 보였다.

중품질 작업과 실패 작업의 구별을 보면, SpatialVLA의 *"Pick up"* 작업에서는 EV를 뺀 모든 지표가 구별 능력을 보였다. 마찬가지로 같은 작업에서 {{< katex >}}\pi_0{{< /katex >}} 모델은 모든 품질 지표와 일부 불확실성 지표, 즉 TB-TP, TB-PCS, TB-E가 구별 능력을 보였다. 또한 OpenVLA의 *"Move near"* 작업과 SpatialVLA의 *"Put on"* 작업에서는 TB 계열 지표가 중품질 작업과 실패 작업을 유의하게 구별했다. 이때 {{< katex >}}\hat{A}_{12}{{< /katex >}} 효과 크기는 적어도 중간 수준이었다.

그러나 SpatialVLA의 *"Move near"*\ 와 *"Put in"* 작업에서는 OT를 뺀 어떤 품질 지표도 중품질 작업과 실패 작업을 구별하지 못했다. 실패한 작업 대부분에서, 로봇은 작업을 시작했지만 곧 걸리거나 환경과 충돌해, 과정 초반부터 더 움직이지 못하는 *막힘(blocking)* 상태에 들어갔다. 반면 성공한 작업에서는 이 *막힘* 상태가 보통 작업이 이미 끝난 뒤에야 나타났다. 즉 실패 작업보다 실행 시간축에서 훨씬 늦게 나타났다. 그 결과 이 지표들의 평균값은 실패 작업보다 중품질 성공 작업에서 더 높은 경향이 있다.

> **역주.** 이 지표들은 실행 전체에 걸친 시간 단계별 값의 평균이다(5.7절). 실패 작업은 일찍 멈춰 움직임이 거의 없는 구간이 길어지므로 평균이 낮아지고, 그래서 오히려 "더 매끄럽다"는 값이 나온다는 설명이다. 표 7의 *Move Near* Medium 열이 빨간색인 것이 이 현상이다.

저품질 작업은 대체로 실패 작업과 구별되지 않았다. 예외는 OT, 그리고 {{< katex >}}\pi_0{{< /katex >}} 모델의 *"Pick up"*\ 과 *"Move near"* 작업에서 일부 지표뿐이다. 이는 저품질이지만 성공한 작업 중 상당수가, 제안한 지표로 보면 실패한 작업과 꽤 비슷하다는 것을 시사한다.

> **발견 8 (Finding 8).** 제안한 지표는 모델과 작업에 따라 통계적으로 유의한 차이를 드러냈지만, OT를 제외한 대부분의 지표는 중품질·저품질 성공 작업과 명백한 실패를 뚜렷이 구별하지 못했다. 이는 작업 품질이 낮아질수록 결과가 실패와 점점 비슷해진다는 것을 시사한다. 그리고 성공률만으로는 VLA 모델의 품질을 평가하기에 충분하지 않다는 결론을 뒷받침한다.

눈여겨볼 점이 또 있다. 일부 실패 실행은 지표 값이 오히려 좋게(고품질처럼) 나왔다. 예를 들어 불안정성이 낮게 나온 경우가 있었는데, VLA 모델이 대상 물체의 위치를 찾거나 물체를 탐지하지 못했기 때문일 수 있다. 이런 상황에서 로봇은 전혀 움직이지 않았고, 말단 장치의 가속도나 속도도 없었다. 이 특정 경우에 행동·움직임 기반 지표(예: A‑PI, A‑VI, A‑AI, TI, TCP‑PI, TCP‑VI, TCP‑AI)는 편차와 불안정성이 아주 작게 나왔다. 정상적인 상황이라면 이런 값은 고품질 거동을 뜻한다. 하지만 이 경우의 낮은 값은 작업을 잘 수행했다는 뜻이 아니라 단지 움직임이 없었다는 것을 반영할 뿐이다. 이런 상황은 로봇이 어느 정도 움직였는지를 재는 최소 임곗값을 정하면 쉽게 탐지할 수 있을 것이다.

> **발견 9 (Finding 9).** 일부 실패 작업은 불안정성이 탐지되지 않아 불확실성이 낮거나 품질이 높게 나왔다. 하지만 이는 로봇이 정지해 있었기 때문이다. 이런 상황은 로봇의 최소 움직임을 재는 임곗값을 정하면 쉽게 탐지할 수 있다.

### 6.4 RQ4 - Overhead

RQ4에서는 각 지표의 자원 소비와 추론 시간 오버헤드를 평가했다. 이 측면은 실제 운영 시스템에 붙일 불확실성 지표에서 특히 중요하다. 예를 들어 실행 중 스스로 문제를 고치는 자가 치유(self-healing) 용도가 그렇다. 표 8은 전체 추론 시간과 각 지표에 해당하는 오버헤드를 보여 준다. TB-TP, TB-PCS, TB-D, TB-D 지표의 오버헤드는 함께 측정했다. 오버헤드가 주로 토큰 확률을 얻는 과정에서 생기기 때문이다. 또한 A-AI를 계산하려면 A-PI와 A-VI를 먼저 계산해야 하므로, A-PI, A-VI, A-AI를 묶음 이름 AI(표 8의 AI 행)로 함께 측정했다. 마찬가지로 TCP-PI와 TCP-VI에 의존하는 TCP-AI는 이 둘과 함께 TCP로 묶었다.

> **역주.** 원문의 "TB-TP, TB-PCS, TB-D, TB-D"는 마지막 TB-D가 TB-E의 오기로 보인다. 즉 토큰 기반 지표 4개를 표 8의 TB 행 하나로 묶었다.

예상대로 EV 지표의 오버헤드가 가장 컸다. 여러 번의 추론 결과를 얻어 비교하려면 VLA 모델을 여러 번 인스턴스화해야 하기 때문이다. 실제로 이 오버헤드는 실용적으로 쓰기에는 너무 크다. 로봇 행동을 효과적으로 제어하려고 모델을 자주 실행해야 하는 시나리오에서는 특히 그렇다. EV 지표는 RQ2b 결과에서도 대부분 양의 상관이 없었다. 이를 함께 고려하면, 이 지표는 VLA 모델의 불확실성을 재는 데 적합하지 않다. 나머지 지표들은 오버헤드가 크지 않다. TB 지표의 오버헤드가 그중 가장 크지만, 그래도 실제로 적용할 수 있을 만큼 작다.

> **역주.** 예를 들어 표 8에서 OpenVLA의 1회 추론은 약 0.36초인데 EV 오버헤드는 약 1.06초로 추론 시간의 약 3배이고, TB 오버헤드는 약 0.013초다. "RQ2b"는 원문 표기 그대로이며, 본문에 RQ2b라는 하위 질문은 따로 정의되어 있지 않다. 6.2절(RQ2)의 EV 결과를 가리키는 것으로 보인다.

> **발견 10 (Finding 10).** EV 지표는 실용적으로 쓰기에는 오버헤드가 너무 크다. 반면 나머지 지표들의 오버헤드는 실제로 쓸 수 있을 만큼 낮다.

## 7 Threats to Validity

일부 지표에는 특정 파라미터가 필요하며, 이것이 **내적 타당성(internal validity)** 위협이 될 수 있다. 예를 들어 EV는 여러 번의 추론이 필요한데, 인프라의 하드웨어 성능 제약 때문에 그 수를 4로 제한했다. 그래도 이 설정은 여러 평가에서 안정적인 결과를 보였다. 또 시간 차분이 필요한 지표에는 8단계의 시간 윈도를 정했다. 이 값은 경험적 관찰로 골랐다. 더 작은 값은 추정을 덜 안정적으로 만들었고, 8단계가 시간적 맥락과 계산 비용 사이에서 가장 좋은 균형을 주었다. 또 다른 **내적 타당성** 위협은 모델 선택과 학습 방식의 차이와 관련될 수 있다. 이 위협은 각 작업에서 모든 모델이 같은 데이터셋으로 파인튜닝된 버전을 쓰도록 해서 줄였다.

평가의 **외적 타당성(external validity) 위협**은 이 접근법을 이 연구의 사례를 넘어 적용할 수 있는지와 관련된다. 평가는 VLA 모델 문헌에서 흔히 다루는 주요 작업 4개 [8, 24]를 아우르고, 구조 설계가 다양한 최신 모델 3개를 포함한다. 하지만 로봇 플랫폼의 다양성이 제한적이어서(시스템 2개) 일반화 가능성은 여전히 제약된다. 이 위협을 줄이기 위해, 작업마다 서로 다른 장면 500개로 평가했다.

작업 품질은 해당 분야 전문가가 작업의 품질 수준에 레이블을 다는 방식으로 측정했으며, 이는 **결론 타당성(conclusion validity) 위협**이 될 수 있다. 이 위협을 줄이기 위해 경험 많은 분야 전문가를 모두 3명 참여시켰고, 레이블이 엇갈리면 이를 찾아내는 절차와, 엇갈린 작업을 효과적으로 해결하는 절차를 마련했다. 또한 성공 작업을 쉽게 태깅할 수 있는 웹 기반 시스템을 개발했고, 레이블 작업을 모두 15일에 걸쳐 나눴으며, 한 번에 레이블할 작업 수를 최대 160개로 제한했다. 이 절차에서 처음 두 레이블러는 높은 일치도를 보였고, 코헨 카파 기준으로 평가자 간 일치도는 85%였다.

## 8 Related Work

### 8.1 Uncertainty in DL Models and Foundation Models

딥러닝(Deep Learning, DL) 모델은 폭넓은 작업에서 최고 수준의 성능을 내는 것으로 알려져 있지만, 불확실성과 신뢰성 측면에서는 큰 문제를 보이는 경우가 많다 [39]. 안전이 중요하거나 위험 부담이 큰 응용에서는 특히 그렇다. DL 모델의 불확실성을 정량화하면 모델 예측이 얼마나 믿을 만한지에 대한 통찰을 얻을 수 있다. 불확실성을 포착하기 위해 여러 접근법이 제안되었다 [40, 41, 42, 43]. 그중 베이지안 신경망(Bayesian Neural Network, BNN)은 DL 모델에 베이즈 추론을 적용해, 불확실성을 모델링하는 확률적 틀을 제공한다 [40].

그러나 BNN은 사후분포 추론이 복잡해 계산 비용이 크고 실제로 구현하기 어려운 경우가 많다. 실용적인 베이즈 근사로서, 몬테카를로 드롭아웃(Monte-Carlo Dropout, MC-Dropout, 추론 때도 드롭아웃을 켜고 여러 번 예측하는 방법)은 널리 쓰이는 불확실성 정량화(uncertainty quantification, UQ) 방법이다 [41]. 이 방법은 완전한 베이즈 추론보다 계산 비용을 크게 줄인다.

또 다른 대표적인 접근법은 딥 앙상블(Deep Ensembles, DE) [43]이다. 서로 다른 무작위 초기화로 신경망 여러 개를 독립적으로 학습한다. 앙상블 모델들의 예측이 얼마나 갈리는지(분산)가 불확실성의 척도가 된다.

위의 UQ 방법들은 로보틱스와 사이버 물리 시스템(Cyber-Physical System, CPS)의 DL 모델에 널리 적용되었다. 예를 들어 Xu et al. [44]은 CPS의 디지털 트윈을 발전시키기 위한 불확실성 인지 전이 학습 방법을 제안하면서 베이즈 방법과 앙상블 방법을 연구했다. Catak et al. [45]은 MC-Dropout 방법을 바탕으로 예측 검증기를 설계했다. 컴퓨터 비전 작업에서는 Feng et al. [46]이 3D 차량 탐지 모델에 MC-Dropout을 써서 불확실성을 포착했다. 이를 통해 차량 탐지 성능을 높이고 자율주행차의 안전을 보장하고자 했다. Kendall과 Gal [47]은 의미 분할과 깊이 회귀를 포함한 컴퓨터 비전 작업에서 여러 불확실성 유형을 조사했다. 로보틱스에서는 Lu et al. [48]이 로봇 팔에 들어간 스티커 탐지 소프트웨어(DL 기반)의 불확실성과 강건성을 평가하고, 그 평가 결과를 바탕으로 모델 선택 지침을 제시했다.

그러나 기존 UQ 방법은 계산 비용, 그리고 이미 사전학습된 모델이라는 특성 같은 실질적 제약 때문에 파운데이션 모델(Foundation Model, FM)의 맥락에 바로 적용할 수 없다. 예를 들어 DE는 모델 여러 개를 처음부터 학습해야 하는데, 대규모 FM은 학습 비용과 필요 자원이 막대해 이것이 거의 불가능하다. 그래서 이 연구에서는 VLA라는 특정 유형의 FM에 집중한다. 그리고 추론 중의 확률적 거동 같은 VLA의 비결정적 특성을 활용해, VLA의 성능을 평가하는 불확실성 지표들을 설계한다.

최근 FM의 발전은 DL 시스템의 능력을 크게 넓혔지만, 동시에 전통적인 DL 모델의 불확실성·신뢰성 문제도 물려받았다 [49, 50, 51, 52]. Felicioni et al. [53]은 전통적인 DL의 인식적(epistemic) 불확실성 추정 기법을 변형해, 자연어를 입력으로 받는 LLM의 의사결정에서 불확실성이 어떤 역할을 하는지 연구했다. 사전학습된 LLM의 불확실성을 이해하기 위해, Xiao et al. [54]은 불확실성 정량화 방법의 선택을 포함해 LLM의 폭넓은 설정을 다루는 대규모 실증 분석을 수행했다. FM 맥락에서 기존 UQ 접근법을 더 잘 이해하기 위해, Huang et al. [50]은 불확실성 추정 방법 12개로 LLM의 불확실성을 평가하는 탐색적 연구를 수행했다. Catak과 Kuzlu [55]는 볼록 껍질(convex hull) 분석으로 LLM 응답의 불확실성을 정량화하는 새로운 기하학적 접근법을 제안했다. LLM이 생성한 자연어 응답의 신뢰도를 재기 위해, Lin et al. [56]은 입력 데이터와 응답의 불확실성과 확신도를 포착하는 지표 집합을 설계했다. 불확실성 추정은 FM의 성능을 높이는 수단으로도 쓰였다. 예를 들어 Ji et al. [57]은 다중 모달 사전학습 비전-언어 모델의 불확실성 모델링을 조사하고, 다중 모달리티의 불확실성을 가우시안 분포로 모델링하는 새 모듈인 확률 분포 인코더(Probability Distribution Encoder)를 제안했다. Chen et al. [58]은 다중 모달 LLM에서 불확실성 보정(calibration)과 성능 사이의 상관을 조사했고, 평가 결과를 바탕으로 몇 가지 고급 다중 모달 LLM 보정 기법을 제안했다.

최근의 발전으로 VLA 모델이라는 새로운 종류의 FM이 등장했다. VLA 모델은 시각 인식, 자연어 이해, 행동 생성을 통합한다. 중요성이 커지고 있는데도, VLA 모델의 맥락에서 불확실성 정량화는 거의 탐구되지 않았다. 이 공백은 위험 부담이 크거나 안전이 중요한 VLA 응용에서 상당한 위험을 낳는다. 그래서 이 연구에서는 VLA 맥락에서 여러 UQ 방법을 설계하고 변형해, 로봇 제어에서 VLA의 확신도와 품질을 평가하고자 한다.

### 8.2 Quality Assessment in Robotics and VLA models

전통적으로 로보틱스의 품질 평가는 통제된 환경에서 성능을 정량화하는 작업별 지표에 의존해 왔다 [59, 60, 61, 62]. 예를 들어 내비게이션과 경로 계획은 흔히 경로 길이, 실행 시간, 에너지 소비로 평가한다 [61, 62]. 마찬가지로 조작과 잡기 성능은 성공률, 완료 시간, 잡기 신뢰도로 평가한다. 여기서 성공률은 잡기에 성공할 확률을 뜻한다 [59, 60]. 로보틱스와 나란히, 컴퓨터 비전과 자연어 처리도 시스템 품질을 평가하는 분야별 벤치마크를 확립했다. 비전에서는 ImageNet [63]과 Coco [64], 언어에서는 Bleu [65]와 Rouge [66]가 그 예다. 이런 단일 모달 지표는 유용하지만, 인식, 언어 이해, 행동 실행을 통합한 복잡한 다중 모달 시스템에 적용하기에는 부족하다.

확산 정책(diffusion policy)이나 VLA 모델 같은 로보틱스용 지능형 에이전트가 떠오르면서, 연구 커뮤니티는 이런 모델에 맞춘 평가 방법 [67, 8]과 벤치마크 [35, 24, 68, 69, 70, 71, 72, 73, 74]를 탐구하기 시작했다. 이 벤치마크 중 상당수는 주로 시뮬레이션 기반 로보틱스를 위해 설계되었고, 조작과 내비게이션 같은 매우 다양한 행동에 대해 다양한 장면을 제공한다. 이런 벤치마크는 보통 장면 구성과 작업 완료에 초점을 두며, 추론 품질이나 작업 수행 품질처럼 VLA 모델에 필요한 능력 전체를 포착하지는 못한다. 예를 들어 PaLM-E [75]와 RT-2 [76]의 저자들은 종단간 평가를 썼다. 이 평가는 복잡한 다중 모달 시나리오에서 체화 에이전트(embodied agent)가 최종적으로 작업을 해냈는지에 초점을 둔다. PaLM-E의 경우, 실제 장면에서 고수준 자연어 지시를 따라 로봇 조작과 내비게이션 작업을 완수하는 능력을 강조해 평가한다. 마찬가지로 RT-2는 시각적 근거를 둔 추론과 언어 이해가 필요한 다양한 로봇 작업 묶음에서의 성능으로 평가한다. 두 평가 방식 모두 전통적인 모듈별 평가에서 통합적이고 결과 중심적인 평가로 옮겨 간 것이다. 하지만 이들도 여전히 주로 최종 작업 성공률을 재며, 추론 품질, 모달리티 간 근거 연결(cross-modal grounding), 실시간 적응성 같은 세밀한 지표는 포착하지 못한다.

이런 접근법과 다른 축에서, Wang et al.은 VLA 모델을 테스트하기 위한 로봇 조작 장면을 생성하는 퍼징 프레임워크 VLATest [8]를 제안했다. VLATest도 작업 완료가 올바른지 판정하는 데 단순한 오라클을 쓴다. 이들은 또한 자연어 설명으로부터 테스트 환경을 자동 구성하는 플랫폼 LADEV [67]를 제안했다. LADEV는 바꿔 말하기(paraphrasing) 메커니즘으로 작업 지시를 여러 표현으로 바꿔, 테스트를 더 다양하게 만든다. 이런 접근법은 더 체계적인 평가로 나아가는 한 걸음이지만, 전통적인 로보틱스 평가처럼 작업 완료율과 총 실행 시간 같은 최종 결과에 주로 초점을 두었다. 이런 기존 접근법과 달리, 이 논문의 접근법은 VLA 기반 시스템 전체의 성능을 포괄적으로 평가한다. 작업 완료에만 초점을 두지 않고, 인식, 언어, 추론, 실행의 통합과 품질까지 아우른다.

## 9 Conclusion

VLA 모델은 로봇 조작 작업은 물론 다른 사이버 물리 시스템을 위한 차세대 AI 기반 제어 기법이다. 그런데 지금까지 이 모델의 품질을 깊이 탐구한 연구는 없었다. 그 품질을 형식적인 품질·불확실성 지표로 잴 수 있는지도 마찬가지다. 이 논문에서는 VLA 기반 로봇 시스템을 위한 여러 품질 지표와 불확실성 지표를 제안한다. 현재의 평가 프레임워크를 비판적으로 분석해, 성공 작업과 실패 작업을 가르는 데 널리 쓰이는 기호 오라클에 상당한 결함이 있음을 강조한다. 선도적인 VLA 모델 3개의 성공 실행 908건을 포괄적으로 수작업 분석한 결과, 작업 수행 품질에서 눈에 띄는 격차가 드러났다. 이는 특히 성공률에만 의존하는 것이 부적절하다는 점을 강조한다. 불확실성 지표 8개와 품질 지표 5개를 도입하고 평가한 결과, 여러 지표가 전문가 평가와 중간\~높은 상관을 보여 그 유용성이 드러났다. 그중 행동 속도 불안정성(A-VI), 행동 가속도 불안정성(A-AI), 궤적 속도 불안정성(TCP-VI)이 이 맥락에서 불확실성과 품질을 평가하는 데 특히 적절한 지표로 두드러졌다. 또한 최적 궤적 차이(OT)는 성공 작업과 실패 작업을 구별하는 데 가장 좋은 지표로 나타났다. 이 결과는 표준화된 VLA 평가·벤치마킹 프레임워크가 시급히 필요함을 강조하며, 로봇 시스템의 실시간 모니터링과 적응적 성능 개선을 위한 유망한 방향을 제시한다.

### A.1 Models Architecture and Details

**OpenVLA** [6]는 파라미터 70억(7B) 개의 VLA로, Open X-Embodiment 데이터셋 [24]의 로봇 시연 97만 건으로 사전학습되었다. OpenVLA의 구조는 세 부분으로 이루어진다(그림 4 (a) 참조). (1) 이미지 입력을 이미지 패치 임베딩으로 바꾸는 시각 인코더, (2) 시각 인코더의 출력 임베딩을 받아 언어 모델의 입력 공간으로 사영하는 프로젝터, (3) 대규모 언어 모델(LLM) 백본이다. 특히 OpenVLA는 Prismatic-7b VLM [77]을 바탕으로 만들어졌다. 이 VLM은 앞서 설명한 표준 구조를 따른다. 구성은 파라미터 6억 개짜리 시각 인코더, 2층짜리 작은 MLP 프로젝터, 파라미터 70억 개의 Llama 2 언어 모델 백본 [78]이다. Prismatic은 두 부분으로 된 시각 인코더를 쓴다는 점이 특징이다. 이 인코더는 사전학습된 SigLIP [79]과 DinoV2 [80] 모델로 이루어진다. 입력 이미지는 두 인코더를 각각 따로 통과하고, 그 결과로 나온 특징 벡터를 이어 붙인다.

(1) SigLIP [79]과 Gemma-2B [84]로 만든 대규모 VLM 백본, (2) 연속 행동을 모델링하는, 파라미터 3억 개짜리 전용 행동 전문가(action expert) Transformer [85, 86]다. 여러 시점의 RGB 이미지, 자연어 프롬프트, 고유수용 상태를 포함한 로봇 관측은 토큰화되어 VLM에서 처리된다. 미래 행동의 분포를 모델링하기 위해 {{< katex >}}\pi_0{{< /katex >}}은 조건부 플로 매칭을 쓴다. 여기서 행동 전문가는 디노이징 네트워크로 작동한다. 즉 노이즈가 섞인 입력에서 깨끗한 행동을 복원해, 일관되고 정밀한 궤적을 만든다. 고유수용 토큰과 행동 토큰은 행동 전문가만 통과하며, 행동 전문가는 양방향 어텐션 마스크로 작동한다. 추론할 때 행동 전문가는 무작위 노이즈에서 출발한다. 그리고 학습된 흐름장(flow field) [87]의 안내를 받아 여러 단계에 걸쳐 노이즈를 제거하며, 일관된 행동 시퀀스로 점차 다듬는다.

**SpatialVLA** [7]는 파라미터 30억(3B) 개의 비전-언어-행동(VLA) 모델로, Open X-Embodiment [24]와 RH20T [88] 데이터셋의 실제 로봇 시연 110만 건으로 사전학습되었다. SpatialVLA의 구조는 세 주요 구성 요소로 이루어진다(그림 6 (a) 참조). (1) Ego3D 위치 인코딩(카메라 기준 3D 위치 정보를 더하는 인코딩)으로 특징을 뽑는 시각 인코더, (2) 적응형 행동 격자(adaptive action grid)를 쓰는 공간 행동 토크나이저, (3) 백본인 대규모 언어 모델이다. 특히 SpatialVLA는 백본 비전-언어 모델로 PaliGemma 2(Gemma 2) [89]를 쓴다. 시각 특징을 뽑기 위해 SpatialVLA는 SigLIP [79]을 2D 시각 인코더로 써서 시각 입력과 언어 입력이 정렬되도록 한다. Ego3D 위치 특징을 위해서는 깊이를 추정해 각 픽셀의 3D 위치를 얻는 ZoeDepth [90]를 결합한다. 마지막으로 적응형 행동 격자는 로봇 에피소드 전체의 행동 통계 분포에 따라 연속적인 로봇 행동을 적응형 공간 격자로 이산화한다. 모델은 이 격자 위에서 공간 행동 토큰을 학습해, 서로 다른 로봇의 행동을 물리 세계의 3D 공간 구조에 맞춰 정렬한다. 그래서 로봇-카메라 외부 파라미터 보정(extrinsic calibration)이 필요 없고, 모델이 특정 로봇 구성에 얽매이지 않는다. 이는 실제 환경에 배치할 때 핵심적인 장점이다.

### A.2 Implementation of the token-based uncertainty metrics

토큰 기반 지표를 계산하려면, VLA의 최종 출력이 아니라 개별 토큰 수준에서 작업해야 한다. 따라서 각 VLA 안에서 토큰 수준 출력을 생성하는 모듈을 특정해야 한다. **OpenVLA**에서는 LLM 백본, 즉 70억 파라미터 Llama2 언어 모델의 토큰 출력을 가져온다(그림 4 (b) 참조). Llama2는 Llama2 토크나이저의 어휘로 토큰 7개를 출력하며, 각 토큰은 디토큰화해 제어 행동 하나로 바꿀 수 있다. 각 토큰의 생성은 분류 문제로 볼 수 있다. 모델은 가능한 모든 토큰에 대해 예측한 확률 분포를 바탕으로, 크기 32,064의 토큰 어휘에서 확률이 가장 높은 토큰 하나를 고른다. 토큰 확률을 얻으면 3절에서 정의한 대로 토큰 기반 불확실성 지표를 계산한다.

> **역주.** OpenVLA의 7개 토큰은 2절에서 말한 7차원 행동(위치 3, 방향 3, 그리퍼 1)에 하나씩 대응한다. 따라서 OpenVLA에서는 3.4\~3.7절의 {{< katex >}}TN{{< /katex >}}이 7이다. 같은 방식으로 아래의 {{< katex >}}\pi_0{{< /katex >}}은 {{< katex >}}TN=5{{< /katex >}}, SpatialVLA는 {{< katex >}}TN=13{{< /katex >}}이다.

**{{< katex >}}\pi_0{{< /katex >}}**의 토큰 출력은 PaliGemma 기반 백본에서 가져온다(그림 5 (b) 참조). 이 백본은 SigLIP 비전 인코더와 Gemma-2B 언어 모델로 이루어진다. **{{< katex >}}\pi_0{{< /katex >}}**은 Gemma-2B 모델을 불러오는 데 *GemmaForCausalLM* 모델을 쓴다. *GemmaForCausalLM*은 Gemma 모델에 언어 모델링 헤드를 결합한, 인과적 언어 모델링용 사전학습 모델이다. Gemma 모델은 입력 시퀀스를 인코딩해 맥락이 반영된 토큰 표현을 만들고, 언어 모델링 헤드는 이를 토큰 수준 예측으로 바꾼다. 언어 모델링 헤드는 토큰 5개를 출력하며, 각 토큰은 예측된 토큰 확률 분포를 바탕으로 크기 257,152의 어휘에서 선택된다. 이 토큰 수준 출력으로 토큰 기반 지표를 계산한다.

**SpatialVLA**에서도 **{{< katex >}}\pi_0{{< /katex >}}**과 비슷하게, PaliGemma2 기반 백본에서 토큰 출력을 가져온다(그림 6 (b) 참조). PaliGemma2는 PaliGemma와 모델 구조가 같지만, 더 높은 이미지 해상도와 더 큰 언어 모델 변형(예: Gemma-2B, 9B, 27B) 지원 등 몇 가지 핵심 개선을 도입했다. 그래서 토큰 확률 분포를 얻는 데 **{{< katex >}}\pi_0{{< /katex >}}**과 같은 구현을 따랐다. 토큰 출력은 Gemma2 모델에서 얻으며, 이 모델은 토큰 13개를 출력하고 각 토큰은 크기 265,347의 어휘에서 선택된다. 그다음 이 토큰 출력을 바탕으로 토큰 기반 지표를 계산한다.
