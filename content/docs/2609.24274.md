## Abstract

전용 GPU 없이 언어 조건부 조작(language-conditioned manipulation)을 로봇에 배포하려면 두 가지가 필요하다. 추론이 효율적이어야 하고, 행동 청크(action chunk)가 정책을 두 번 호출하는 사이의 지연을 메울 만큼 길어야 한다. 본 논문은 CPU 추론 엔진 `vla.simd`를 제시한다. 이 엔진은 여러 연산이 공유하는 SIMD 마이크로커널, 다시 계산할 필요가 없는 결과의 재사용, 그리고 대상 CPU별 최적화를 결합한다. 또한 쿼리 지연 시간과 실행 구간(execution horizon, 청크에서 실제로 실행할 행동 수)이 행동을 끊김 없이 공급할 수 있는지를 어떻게 좌우하는지 정리한다. 이 분석은 지연 실행(lagged)과 시간 정렬 실행(time-aligned)의 두 방식에 대해 이루어지며, 행동 공급(action supply)을 피드백 주파수와 구분한다. 정책 6개와 CPU 4종에서 `vla.simd`는 컴파일된 PyTorch 기준 구현보다 중앙값 기준 약 {{< katex >}}1.4\times{{< /katex >}} 빠르면서도 fp32 수치 정확도를 유지한다. 아울러 ACT 기반 정책 IMPACT를 소개한다. IMPACT는 텍스트 표현을 캐시해 두고, 언어로 시각 특징을 변조한다. 평가한 언어 조건부 정책 가운데 Raspberry Pi 5에서 초당 30개 이상의 행동을 공급하는 것은 IMPACT뿐이다. 90초 동안 연속 추론으로 기기를 달군 뒤(thermal soak)에도 fp32에서 초당 33.5개, int8에서 81.2개의 행동을 공급한다. 별도의 GPU 평가에서는 로봇 데이터 사전학습 없이 LIBERO 4개 스위트에서 평균 76.4%의 성공률을 얻었다. 지시문을 서로 뒤섞는 실험에서는 IMPACT가 익숙한 목표들 가운데 지시에 맞는 목표를 고른다는 것을 보였다. SO-101 로봇 팔에서 IMPACT를, Robotiq 그리퍼를 단 UR10e에서 SmolVLA를 시험해, 두 종류의 로봇에서 CPU 배포가 가능함을 보였다. 프로젝트 페이지: <https://vla-simd.github.io/>.

> **역주.** 행동 청크는 정책이 한 번 추론할 때 앞으로 실행할 행동 여러 개를 한꺼번에 내놓는 방식이다. 추론이 느려도, 받아 둔 청크를 실행하는 동안 다음 추론을 돌리면 로봇은 멈추지 않는다. SIMD(Single Instruction, Multiple Data)는 한 명령으로 벡터 레지스터 안의 여러 값을 동시에 계산하는 CPU 기능이다. 마이크로커널은 행렬 곱의 가장 안쪽 루프를 레지스터 수준에서 손으로 최적화한 작은 함수다.

## 1 Introduction

언어 조건부 조작 정책 [1, 2, 3, 4]을 전용 GPU가 없는 로봇에 배포하려 하면 실용적인 질문이 생긴다. 로봇에 있는 CPU가 로봇이 계속 움직일 수 있을 만큼 빠르게 행동을 내줄 수 있는가? 이 질문에 답하려면 모델 크기나 쿼리 지연 시간을 비교하는 것만으로는 부족하다. 조작 정책은 제어기의 타이밍 제약 안에서 행동을 내줘야 하고, 동시에 사용자가 지정한 목표를 고르는 능력도 유지해야 한다.

> **역주.** 그림에서 오른쪽(느린 쿼리)·아래쪽(짧은 윈도)으로 갈수록 불리하다. 한 쿼리가 {{< katex >}}T_{\mathrm{q}}{{< /katex >}}초 걸리는 동안 30Hz 제어기는 {{< katex >}}30T_{\mathrm{q}}{{< /katex >}}개의 행동을 소비하므로, 윈도 {{< katex >}}H{{< /katex >}}가 이보다 커야(C1 선 왼쪽 위) 행동이 바닥나지 않는다. C2는 그 두 배를 요구한다. 자세한 조건은 3절의 식 (1)에 나온다.

행동 청킹(action chunking)은 CPU 배포에 기회를 준다. 쿼리마다 미래 행동을 여러 개 예측하면 [5, 6], 정책은 추론과 실행을 겹쳐 진행할 수 있고, 제어기의 갱신 주파수보다 낮은 빈도로 동작할 수 있다 [7, 4]. 따라서 중요한 제약은 지금 실행 중인 청크가 바닥나기 전에 다음으로 쓸 수 있는 청크가 도착하느냐이다. 이는 추론 지연, 실행 구간, 그리고 늦게 도착한 행동을 어떻게 처리하느냐에 함께 달려 있다(3절, 그림 1). 쿼리가 더 빠르다고 행동 공급률이 반드시 더 높은 것은 아니다. 명목상의 연산 예산(nominal compute budget)을 맞춘다고 해서 반응성 있는 조작이나 성공적인 조작이 저절로 보장되는 것도 아니다. 그러므로 CPU 배포는 행동 공급 예산을 맞추면서 동시에 언어로 목표를 고르는 능력을 지켜야 한다.

`vla.simd`는 CPU 최적화와 행동 공급 분석을 결합해, 어떤 정책이 각 프로세서에서 실행을 계속 이어 갈 수 있는지 가려낸다. 선형 레이어, 합성곱, 어텐션 투영은 모두 행렬 연산을 공유한다. 이 연산들은 패킹된 패널(packed-panel) 마이크로커널을 통해 SIMD 명령을 활용할 수 있다 [8, 9]. 데이터 배치, 레지스터 사용, 메모리 재사용, 스레딩은 정책과 프로세서에 맞춰야 한다. 한 CPU에서 도움이 되는 설정이 다른 CPU에서는 오히려 해가 될 수 있기 때문이다. 본 논문의 엔진 `vla.simd`는 공유 SIMD 마이크로커널에 CPU별 설정 선택을 더한다. 또 계산 결과를 얼마나 오래 재사용할 수 있는지에 따라 *연산 수명(computation lifetime)*\ 을 나눈다. 가중치는 프로세스당 한 번 패킹하고, 지시문에만 의존하는 텐서는 에피소드마다 캐시하며, 관측에 의존하는 특징은 쿼리마다 계산한다.

> **역주.** 패킹(packing)은 행렬 곱에 쓸 가중치를 마이크로커널이 읽는 순서대로 메모리에 연속 배치해 두는 작업이다. GotoBLAS와 BLIS 같은 고성능 행렬 곱 라이브러리의 기본 기법이다. 패널은 이렇게 다시 배치한 행렬의 좁은 띠 하나를 말한다.

효율적으로 실행하는 것만큼, 과제를 고르는 데 필요한 정보를 지키는 것도 중요하다. ACT [5]는 효율적인 출발점이다. Pi 5에서 기본 30Hz 행동 공급 예산을 만족하지만, 언어 지시를 조건으로 받지 않는다. 다중 과제 환경에서는 같은 장면이 서로 다른 목표에 대응할 수 있다. 예를 들어 테이프를 상자에 넣을 수도 있고 컵에 넣을 수도 있다. 관측만으로는 사용자의 의도를 특정할 수 없다. 그래서 IMPACT(Instruction-Modulated Perception and Action Chunking with Transformers)를 제안한다. IMPACT는 ACT에 언어 조건을 더한 행동 청킹 정책이며, 캐시된 텍스트 표현, 지시문 토큰, 시각 변조(visual modulation)를 쓴다.

기여는 다음과 같다.

- **`vla.simd`**: 선형 레이어, 합성곱, 어텐션 투영이 공유하는 SIMD 마이크로커널을 갖춘 CPU 엔진. 대상별 타일링과 양자화를 더했다.
- **IMPACT**: 언어 조건부 행동 청킹 정책. SO-101 구성에서 언어 조건이 쿼리당 연산량의 약 2.6%만 차지한다. LIBERO, 지시문 섞기, 실제 SO-101 조작으로 평가했다.
- **정책 6개, CPU 4종, 로봇 2종에 대한 연구**: CPU 최적화로 어디서 행동 공급 예산을 맞출 수 있는지 보이고, 발열 영향, PyTorch 대비 수치 충실도, 로봇 배포를 평가했다.

## 2 Related Work

**Efficient vision-language-action policies.** 파라미터가 수십억 개인 비전-언어-행동(vision-language-action, VLA) 모델 [1, 2, 10]이 나오자, 이를 줄인 소형 설계들이 뒤따랐다. 언어 모델을 짧게 줄이거나 없애는 설계 [4, 11, 12], 전체 파라미터 수를 줄이는 설계 [13, 14], 정책을 양자화하는 설계 [15]가 있다. 이 분야의 서베이는 [16]을 참고하라. 최근 연구들은 GPU와 임베디드 가속기에서 VLA 지연 시간을 측정·분석했고 [17, 18], CPU까지 포함해 더 넓은 하드웨어를 비교한 연구도 있다 [19]. Lite VLA는 Pi 4에 CPU로 배포한 결과를 보고했는데, 추론에 수 초에서 수 분이 걸렸다 [20]. 본 논문은 정책 6개를 CPU 4종에서 비교하며, 모든 정책에 같은 시간 측정 구간을 쓰고 쿼리마다 공급되는 행동 수까지 함께 따진다.

**Chunked execution in real time.** ACT [5]와 Diffusion Policy [6]는 행동 청크를 예측한다. 실시간 청킹(real-time chunking) [7]은 추론을 동작과 겹쳐 진행하고, 새 청크가 이전 청크와 매끄럽게 이어지도록 생성을 유도한다. LeRobot은 비동기 서빙을 지원한다 [4, 21]. 양방향 디코딩(Bidirectional decoding) [22]은 유도 샘플링(guided sampling)으로 일관성과 반응성 사이의 트레이드오프를 다룬다. 본 논문은 [7]의 행동 가용성 조건(다음 청크가 올 때까지 실행할 행동이 남아 있어야 한다는 조건)을 CPU에서 쿼리를 하나씩 차례로 보내는 상황에 적용하고, 지연 실행과 시간 정렬 실행을 구분한다.

**Language conditioning.** 특징별 선형 변조(Feature-wise linear modulation, FiLM) [23]는 언어로 시각 특징을 스케일하고 이동시키는 기법으로, BC-Z [24], RT-1 [25], BAKU [26]에서 쓰였다. MT-ACT [27]는 ACT 정책에서 백본의 FiLM과 언어 토큰을 함께 쓰고, Octo [3]는 고정된(frozen) T5의 토큰을 읽는다. 동시기 연구인 DEM [28]도 별도 인코더로 만든 지시문 임베딩을 캐시하고, 분리된(decoupled) 정책을 GPU에서 평가한다. IMPACT는 이렇게 이미 확립된 메커니즘들을 결합하되, 지시문에만 의존하는 특징을 캐시해 CPU 쿼리마다 드는 언어 처리 비용을 제한한다.

**CPU inference.** 본 논문의 마이크로커널은 GotoBLAS와 BLIS [8, 9]를 따르며, 레지스터 제약은 Low et al. [29]에 근거하고 각 대상에서 실험으로 검증한다. XNNPACK [30], ONNX Runtime [31], OpenVINO [32], ExecuTorch [33], llama.cpp [34] 같은 실서비스용 런타임은 명령어 집합 구조(instruction set architecture, ISA)마다 커널을 골라 쓴다. `vla.cpp` [35]는 llama.cpp를 확장해 멀티모달 프리픽스를 캐시하고, 여러 번 반복 실행하는 행동 헤드(iterative action head)를 지원한다. 다만 보고된 평가는 외장 GPU와 임베디드 GPU를 사용한다. SIMD는 CPU에서 모션 플래닝을 가속하는 데도 쓰인다 [36, 37]. `vla.simd`는 여러 정책 계열에 걸친 CPU 실행에 초점을 맞추고, 커널·스레딩·정밀도 선택이 행동 공급 예산에 어떤 영향을 주는지 시험한다.

## 3 Action-Supply Budgets

먼저 추론 지연이 있어도 정책이 행동을 끊김 없이 공급할 수 있는 조건을 정한다. 주파수 {{< katex >}}f_{\mathrm{c}}{{< /katex >}}로 도는 제어기는 {{< katex >}}\Delta=1/f_{\mathrm{c}}{{< /katex >}}초마다 행동 하나를 소비한다. 정책은 가장 최근 관측으로부터 행동 {{< katex >}}N{{< /katex >}}개를 예측하고, 그중 {{< katex >}}H\le N{{< /katex >}}개의 윈도를 실행에 쓸 수 있다. 예를 들어 본 논문의 Diffusion Policy는 행동 64개를 예측하지만 32개짜리 윈도만 내놓는다. 나머지 설정은 예측한 청크 전체를 쓴다(표 2). 이 윈도의 번호는 관측이 이루어진 제어 스텝 {{< katex >}}t{{< /katex >}}부터 매긴다. 쿼리 지연 시간은 {{< katex >}}T_{\mathrm{q}}{{< /katex >}}로 쓰고, 이를 제어 스텝 수로 바꾼 값은 {{< katex >}}d=\lceil f_{\mathrm{c}}T_{\mathrm{q}}\rceil{{< /katex >}}이다. 분석은 지연이 일정하고 실행이 정상 상태(steady state)라고 가정한다. 또 쿼리는 제어 스텝 경계에 맞춰 차례로 시작하며, 쿼리 간격 {{< katex >}}s{{< /katex >}}는 {{< katex >}}d{{< /katex >}} 스텝 이상({{< katex >}}s\ge d{{< /katex >}})이라고 가정한다. 비율 {{< katex >}}f_{\mathrm{eff}}=H/T_{\mathrm{q}}{{< /katex >}}는 [35]에서 실효 제어율(effective control rate)이라 부른 값이다. 본 논문에서는 이것을 *행동 공급률(action-supply rate)*\ 로 본다. 이 값은 피드백 주파수를 재는 것이 아니다.

> **역주.** {{< katex >}}f_{\mathrm{eff}}{{< /katex >}}가 높다는 것은 "초당 쓸 수 있는 행동이 많이 생산된다"는 뜻일 뿐, 로봇이 새 관측을 그만큼 자주 반영한다는 뜻이 아니다. 예를 들어 Pi 5에서 ACT는 쿼리 한 번에 0.92초가 걸리지만 행동 100개를 내므로 {{< katex >}}f_{\mathrm{eff}}\approx109{{< /katex >}}이다(표 3). 그래도 새 관측이 반영되는 빈도, 즉 피드백 주파수는 1초에 한 번 남짓이다.

두 가지 실행 방식을 고려한다. *지연 실행(lagged execution)*\ 에서 로봇은 청크가 도착하면 그 첫 행동부터 실행을 시작한다. 행동이 바닥나지 않으려면 현재 청크를 다 쓰기 전에 다음 청크가 도착해야 하므로, {{< katex >}}s \le H{{< /katex >}}가 필요하다. *시간 정렬 실행(time-aligned execution)*\ 에서는 행동이 원래 의도된 제어 스텝을 유지하고, 이미 지나간(오래된) 행동은 버린다. 실시간 청킹 [7]과 본 논문의 로봇에 쓰는 LeRobot 클라이언트 [4, 21]가 이 방식이다. 청크가 도착한 순간에는 {{< katex >}}\max(0,H-d){{< /katex >}}개의 행동이 남아 있다. 따라서 다음 청크 도착까지 버티려면 {{< katex >}}s+d \le H{{< /katex >}}가 필요하며, 이는 [7]의 {{< katex >}}d \le H-s{{< /katex >}}와 같다.

이 요구 조건들을 {{< katex >}}s\ge d{{< /katex >}}와 함께 묶으면, 모든 조건을 만족하는 쿼리 간격 {{< katex >}}s{{< /katex >}}는 다음이 성립할 때 존재한다.

{{< katex display=true >}}
\text{(C1)}\quad d\le H, \qquad \text{(C2)}\quad 2d\le H,
\tag{1}
{{< /katex >}}

C1은 지연 실행, C2는 시간 정렬 실행의 조건이며, 두 경우 모두 {{< katex >}}s=d{{< /katex >}}를 쓸 수 있다. C1은 {{< katex >}}f_{\mathrm{eff}}\ge f_{\mathrm{c}}{{< /katex >}}와 같다. 제어 스텝 단위로의 올림을 무시하면 C2는 {{< katex >}}f_{\mathrm{eff}}\ge2f_{\mathrm{c}}{{< /katex >}}로 근사된다. 즉, 시간 정렬 실행에서는 현재 추론 지연과 다음 청크를 기다리는 시간을 모두 메울 만큼 행동이 있어야 한다. 이 조건들은 위 모델에서 행동이 끊기지 않음을 보장할 뿐이다. 청크 사이의 매끄러운 전환이나 과제 성공은 따로 평가해야 한다. 또 한 가지 한계로, 실행되는 각 행동은 적어도 {{< katex >}}d{{< /katex >}} 스텝 전의 관측을 바탕으로 한다.

> **역주.** 식 (1)이 나오는 과정: 쿼리를 가능한 한 촘촘히, 즉 {{< katex >}}s=d{{< /katex >}} 간격으로 보낸다고 하자. 지연 실행에서는 도착한 청크를 처음부터 실행하므로 다음 청크가 {{< katex >}}s=d{{< /katex >}} 스텝 뒤에 올 때까지 {{< katex >}}H\ge d{{< /katex >}}개만 있으면 된다(C1). 시간 정렬 실행에서는 도착 시점에 이미 {{< katex >}}d{{< /katex >}}개가 지나가 버려 {{< katex >}}H-d{{< /katex >}}개만 남으므로, 그 남은 양이 다시 {{< katex >}}d{{< /katex >}} 스텝을 버텨야 한다. 그래서 {{< katex >}}H-d\ge d{{< /katex >}}, 즉 {{< katex >}}2d\le H{{< /katex >}}이다(C2).

이 명목 예산은 엔진 지연 시간의 중앙값으로 평가하며, 카메라 촬영과 전송은 포함하지 않는다. 안정적으로 배포하려면 이런 추가 지연과 가끔 생기는 느린 쿼리까지 고려해야 한다. 제어 주파수는 {{< katex >}}f_{\mathrm{c}}=30{{< /katex >}}Hz를 쓴다. 이는 본 논문의 SO-101 제어기 [38]와, 그 학습 데이터셋의 프레임 레이트에 맞춘 값이다.

### 4.1 Computation Reuse

`vla.simd`는 원시 카메라 프레임, 관절 상태, 지시문을 받아 로봇 단위(정규화를 되돌린, 로봇이 실제로 쓰는 물리 단위)로 표현된 행동 청크를 내놓는다. 실행 중에 딥러닝 프레임워크는 쓰지 않는다. 크기 조정, 정규화, 토큰화도 엔진이 처리한다. 쿼리 시간 측정에는 카메라 촬영, 전송, 에피소드 초기화가 포함되지 않는다.

가중치는 오프라인에서 연속된 fp32 배열로 변환해 두고, 프로세스당 한 번 패킹한다. 지시문에만 의존하는 텐서는 에피소드마다 캐시한다. 각 쿼리는 관측에 의존하는 특징을 계산한다. 언어 특징이라도 이미지에 따라 값이 달라지는 것은 캐시할 수 없으므로 여기에 들어간다. 공유 연산자는 Intel AVX2, AMD AVX2, ARMv8 NEON, Apple silicon 백엔드로 분기한다. Apple 백엔드는 기본적으로 밀집 행렬 곱과 합성곱에 Accelerate [39]를 쓰고, 나머지 백엔드는 공유 마이크로커널(SMK)을 쓴다.

> **역주.** AVX2(x86)와 NEON(Arm)은 CPU의 SIMD 명령어 집합이다. AVX2의 벡터 레지스터는 256비트라 fp32 값 8개를, NEON은 128비트라 4개를 담는다. Accelerate는 Apple이 제공하는 수치 연산 라이브러리다.

### 4.2 Selecting a Register Tile for Each Target

선형 레이어는 {{< katex >}}Y = XW^{\top} + \mathbf{1}_m b^{\top}\in\mathbb{R}^{m\times n}{{< /katex >}}을 계산한다. 여기서 {{< katex >}}X\in\mathbb{R}^{m\times k}{{< /katex >}}, {{< katex >}}W\in\mathbb{R}^{n\times k}{{< /katex >}}, {{< katex >}}b\in\mathbb{R}^{n}{{< /katex >}}이고, {{< katex >}}\mathbf{1}_m{{< /katex >}}은 원소가 모두 1인 벡터다. GotoBLAS와 BLIS [8, 9]를 따라, {{< katex >}}W^{\top}{{< /katex >}}를 출력 열 {{< katex >}}n_{\mathrm{r}}{{< /katex >}}개 단위의 패널로 패킹한다. 마이크로커널은 {{< katex >}}m_{\mathrm{r}}\times n_{\mathrm{r}}{{< /katex >}} 출력 타일을 벡터 레지스터에 두고 깊이 {{< katex >}}k{{< /katex >}} 방향으로 누적한 다음, 메모리에 저장할 때 편향을 더한다. 곱셈-덧셈 융합(fused multiply-add, FMA) 명령은 깊이가 증가하는 순서로 실행된다. 그래서 타일을 어떤 크기로 나누든 각 출력의 누적 순서가 바뀌지 않는다.

> **역주.** 레지스터 타일은 출력 행렬 중 마이크로커널이 한 번에 맡는 {{< katex >}}m_{\mathrm{r}}{{< /katex >}}행 {{< katex >}}\times{{< /katex >}} {{< katex >}}n_{\mathrm{r}}{{< /katex >}}열 조각이다. 이 조각의 부분합을 내내 레지스터에 둔 채 {{< katex >}}k{{< /katex >}} 방향으로 곱셈-덧셈을 반복하면, 메모리 왕복 없이 계산할 수 있다. 누적 순서가 고정되므로 부동소수점 결과도 타일 크기와 무관하게 같아진다.

벡터 레지스터 하나에 fp32 값이 {{< katex >}}L{{< /katex >}}개 들어가고, 타일 한 행에 레지스터가 {{< katex >}}n_{\mathrm{v}} = n_{\mathrm{r}}/L{{< /katex >}}개 필요하다고 하자. 그러면 타일 하나에는 누적용 레지스터 {{< katex >}}m_{\mathrm{r}}n_{\mathrm{v}}{{< /katex >}}개, 가중치 레지스터 {{< katex >}}n_{\mathrm{v}}{{< /katex >}}개, 활성값 레지스터 {{< katex >}}q{{< /katex >}}개가 필요하다. AVX2는 입력값 하나를 레지스터 하나의 모든 레인에 브로드캐스트하고, 그 레지스터를 여러 행에 걸쳐 재사용한다. 따라서 {{< katex >}}q=1{{< /katex >}}이고, 깊이 스텝마다 {{< katex >}}\Lambda = n_{\mathrm{v}}{+}m_{\mathrm{r}}{{< /katex >}}번 로드한다. NEON은 이와 달리 행마다 벡터 하나를 두고, 그 레인들을 연속된 깊이 스텝 {{< katex >}}L{{< /katex >}}개에 걸쳐 차례로 읽는다. 그래서 {{< katex >}}q=m_{\mathrm{r}}{{< /katex >}}이고, 패킹되지 않은 활성값에 대해 스텝당 평균 {{< katex >}}\Lambda = n_{\mathrm{v}}{+}m_{\mathrm{r}}/L{{< /katex >}}번 로드한다. 대상 CPU의 벡터 레지스터 수를 {{< katex >}}R_{\max}{{< /katex >}}, 사이클당 벡터 FMA 처리량을 {{< katex >}}P_{\mathrm{fma}}{{< /katex >}}, 사이클당 벡터 로드 처리량을 {{< katex >}}P_{\mathrm{ld}}{{< /katex >}}, FMA 지연을 {{< katex >}}\tau{{< /katex >}} 사이클이라 하면, 다음을 요구한다.

{{< katex display=true >}}
m_{\mathrm{r}}n_{\mathrm{v}} + n_{\mathrm{v}} + q \le R_{\max}, \tag{2}
{{< /katex >}}

{{< katex display=true >}}
m_{\mathrm{r}}n_{\mathrm{v}} \ge P_{\mathrm{fma}}\,\tau, \tag{3}
{{< /katex >}}

{{< katex display=true >}}
m_{\mathrm{r}}n_{\mathrm{v}}\,P_{\mathrm{ld}} \ge \Lambda\,P_{\mathrm{fma}}, \tag{4}
{{< /katex >}}

식 (2)는 레지스터 사용량을 제한한다. 식 (3)은 서로 독립인 누적기를 충분히 두어 FMA 지연을 가리게 한다 [29]. 식 (4)는 로드가 산술 연산 속도를 따라가도록 요구한다. 타일 크기 선택은 오프라인에서 이루어진다. 알고리즘 1의 SPILLS 함수는 후보 타일을 컴파일한 뒤, 안쪽 루프에서 벡터 레지스터 값을 스택에서 다시 읽어 오는지(스필, spill) 확인한다.

> **역주.** 식 (3)의 의미: FMA 한 번의 결과가 나오기까지 {{< katex >}}\tau{{< /katex >}} 사이클이 걸리고, 매 사이클 {{< katex >}}P_{\mathrm{fma}}{{< /katex >}}개를 새로 시작할 수 있다. 같은 누적기에 연달아 더하면 앞 결과를 기다려야 하므로, 파이프라인을 꽉 채우려면 서로 독립인 누적 레지스터가 {{< katex >}}P_{\mathrm{fma}}\tau{{< /katex >}}개 이상 있어야 한다. 식 (4)는 FMA {{< katex >}}m_{\mathrm{r}}n_{\mathrm{v}}{{< /katex >}}번에 필요한 로드 {{< katex >}}\Lambda{{< /katex >}}번이 로드 처리량 안에서 끝나야 한다는 뜻이다.

**알고리즘 1.** 한 대상 CPU에 대한 오프라인 레지스터 타일 선택.

알고리즘 1은 폭 {{< katex >}}n_{\mathrm{r}}{{< /katex >}} 후보로 두 조건을 만족하는 값만 본다. {{< katex >}}L{{< /katex >}}의 배수여야 하고, {{< katex >}}g{{< /katex >}}의 약수여야 한다. {{< katex >}}g{{< /katex >}}는 패킹되는 레이어들의 출력 폭을 모두 나누는 최대공약수다. 점수 {{< katex >}}\phi(m_{\mathrm{r}},n_{\mathrm{r}})=m_{\mathrm{r}}n_{\mathrm{r}}/(n_{\mathrm{r}}+Lm_{\mathrm{r}}){{< /katex >}}은 {{< katex >}}n_{\mathrm{r}}{{< /katex >}}이 고정되면 {{< katex >}}m_{\mathrm{r}}{{< /katex >}}이 클수록 커진다. 그래서 가능한 첫 {{< katex >}}m_{\mathrm{r}}{{< /katex >}}에서 바로 루프를 빠져나와도 된다. 가능한 타일 가운데 점수가 가장 높은 것을 고르고, 없으면 패킹하지 않은 가중치로 대체한다. 이 점수는 AVX2 브로드캐스트 커널의 FMA 대 로드 비율이다. NEON에 이 점수를 쓰는 것은 경험적인 휴리스틱이다. NEON의 로드 모델만 보면 {{< katex >}}9{\times}8{{< /katex >}}과 {{< katex >}}8{\times}8{{< /katex >}}이 유리하지만, 실제로 선택된 {{< katex >}}4{\times}16{{< /katex >}} 타일이 Cortex-A76에서 각각 12%, 19% 더 빠르다.

> **역주.** {{< katex >}}\phi{{< /katex >}}가 FMA 대 로드 비율인 이유: AVX2에서 깊이 스텝 하나당 FMA는 {{< katex >}}m_{\mathrm{r}}n_{\mathrm{v}}{{< /katex >}}번, 로드는 {{< katex >}}n_{\mathrm{v}}+m_{\mathrm{r}}{{< /katex >}}번이다. {{< katex >}}n_{\mathrm{v}}=n_{\mathrm{r}}/L{{< /katex >}}을 대입해 나누면 {{< katex >}}m_{\mathrm{r}}n_{\mathrm{r}}/(n_{\mathrm{r}}+Lm_{\mathrm{r}}){{< /katex >}}이 된다. 로드 한 번당 계산을 많이 할수록 좋은 타일이다.

본 논문의 정책 폭({{< katex >}}g=64{{< /katex >}})에서 이 절차는 AVX2에서 {{< katex >}}6{\times}16{{< /katex >}}(레지스터 16개 중 15개 사용)을, NEON에서 {{< katex >}}4{\times}16{{< /katex >}}(32개 중 24개 사용)을 선택한다. AVX2의 선택은 BLIS가 Haswell과 Zen에서 쓰는 단정밀도 타일과 같다. Pi 5에서 선택된 타일은 4스레드로 106.9 GFLOP/s에 이르고, 데이터가 L2 캐시에 있을 때 코어 하나에서 최대 산술 처리량의 96%를 낸다. 두 ISA 모두에서, 벤치마크한 레이어 형태 6가지 전부에 대해 선택된 타일이 시험한 후보 중 가장 빨랐다.

### 4.3 Convolution and Attention

합성곱은 im2col [40]을 통해 같은 마이크로커널을 재사용한다. im2col은 합성곱을 행렬 곱으로 바꾸는 방법이다. 입력 행렬의 각 행에는 이미지 패치가, 패킹된 가중치에는 펼친 필터가 들어간다. 패치를 한 번에 패널 하나씩 만들면 스트라이드와 패딩을 지키면서도 전체 패치 행렬을 저장할 필요가 없다.

어텐션의 쿼리({{< katex >}}Q{{< /katex >}}), 키({{< katex >}}K{{< /katex >}}), 값({{< katex >}}V{{< /katex >}}), 출력 투영은 같은 선형 연산자를 쓴다. 키 투영은 저장할 때 타일을 전치해 {{< katex >}}K^{\top}{{< /katex >}}를 바로 써 넣는다. 어텐션 곱 {{< katex >}}QK^{\top}{{< /katex >}}와 {{< katex >}}\mathrm{softmax}(QK^{\top}/\sqrt{d_{\mathrm{h}}})V{{< /katex >}}는 백엔드별 별도 커널을 쓴다. 여기서 {{< katex >}}d_{\mathrm{h}}{{< /katex >}}는 헤드 폭이고, 소프트맥스는 키 방향으로 행마다 적용한다. 별도 커널을 쓰는 이유는 이렇다. 이 두 곱은 두 피연산자가 모두 쿼리마다 바뀌고, 키 개수가 {{< katex >}}n_{\mathrm{r}}{{< /katex >}}의 배수가 아닐 수도 있다. 출력 폭이 {{< katex >}}n_{\mathrm{r}}{{< /katex >}}의 배수가 아닌 선형 레이어(예: 행동 헤드)는 행 단위로 블록을 나누는 커널을 쓴다.

> **역주.** 여기서 {{< katex >}}Q{{< /katex >}}, {{< katex >}}K{{< /katex >}}는 어텐션의 쿼리와 키 행렬이다. 4.2절의 활성값 레지스터 수 {{< katex >}}q{{< /katex >}}, 그리고 정책을 호출하는 "쿼리"와는 다른 것이다. 별도 커널을 쓰는 이유는 패킹이 가중치처럼 고정된 행렬을 미리 재배치해 두는 기법이기 때문이다. 두 피연산자가 매번 바뀌면 미리 패킹해 둘 수 없다.

### 4.4 Runtime Settings and Quantization

백엔드와 레지스터 타일은 빌드할 때 고정된다. 실행 시 설정은 가중치 패킹, 합성곱 패널, 행렬 곱 블로킹, 어텐션 커널, 스레딩을 제어한다(표 4). 선택적으로 양자화를 켜면 가중치와 활성값을 모두 부호 있는 8비트 정수로 표현한다(W8A8). 이 경로는 값을 0을 중심으로 대칭인 정수로 양자화해 곱하고, 결과를 32비트 정수로 누적한 뒤 fp32로 재스케일한다. 정수 곱에는 Arm `dotprod`나 x86 AVX-VNNI 명령을 쓴다. 가중치 스케일은 출력 채널마다 둔다. 활성값 스케일은 실행 중에 동적으로 계산하는데, 선형 레이어는 토큰마다, 합성곱은 입력 텐서마다 계산한다. 스케일은 절댓값의 최댓값을 127로 나눈 값이다(최댓값이 0이면 1). 이 경로는 선택된 연산자 그룹에만 적용하며, 정규화, 비선형 함수, 지원하지 않는 출력 폭은 fp32로 남긴다. IMPACT의 캐시된 텍스트 인코더도 fp32로 남는다. 6.4절에서 이 선택들을 대상별로 평가한다.

**그림 3.** IMPACT. 고정된 T5-small이 에피소드마다 한 번 지시문을 인코딩해, 트랜스포머용 토큰과 ResNet-18 각 단계용 FiLM 계수를 만든다. 각 쿼리는 변조된 백본과 인코더-디코더를 실행해 50스텝 행동 청크를 예측한다.

IMPACT(Instruction-Modulated Perception and Action Chunking with Transformers)는 행동 청킹 정책에 언어 기반 과제 선택을 더한다. 이때 언어 연산의 대부분은 반복되는 추론 루프 밖에 둔다. ACT [5]를 따라, IMPACT는 카메라 두 대의 영상, 로봇 상태, 지시문을 입력받아 행동 50개짜리 청크를 출력한다(그림 3).

**Visual and state inputs.** 두 시점의 영상은 ImageNet으로 초기화한 ResNet-18 [41] 하나를 공유한다. 추론 시에는 배치 정규화를 합성곱 안에 접어 넣는다(folding). SO-101 구성은 {{< katex >}}480{\times}640{{< /katex >}} 이미지를 써서 두 시점 합쳐 시각 토큰 600개를 만들고, 6차원 관절·그리퍼 명령을 예측한다. LIBERO 구성은 {{< katex >}}256{\times}256{{< /katex >}} 이미지를 써서 시각 토큰 128개를 만들며, 8차원 엔드이펙터 상태와 7차원 상대 행동을 쓴다. 선형 투영으로 시각 특징과 로봇 상태를 폭 512로 맞춘다.

**Language conditioning.** 고정된 T5-small 텍스트 인코더 [42]가 지시문을 {{< katex >}}E\in\mathbb{R}^{n_\ell\times512}{{< /katex >}}로 변환한다. 여기서 {{< katex >}}1\le n_\ell\le32{{< /katex >}}는 패딩이 아닌 토큰의 개수다. 더 긴 입력은 잘라 내고, 패딩은 T5 안에서 마스킹한다. 이 텍스트 은닉 상태 {{< katex >}}E{{< /katex >}}는 두 가지 방식으로 정책에 조건을 준다. 첫째, 투영한 텍스트 토큰을 트랜스포머 인코더 시퀀스 뒤에 붙인다. 이때 패딩은 뺀다. 둘째, 토큰 평균 {{< katex >}}\bar e=n_\ell^{-1}\sum_{j=1}^{n_\ell}E_{j,:}^{\top}{{< /katex >}}로 백본 각 단계 {{< katex >}}i{{< /katex >}}의 특징 맵 {{< katex >}}F_i{{< /katex >}}를 변조한다. 변조는 그 단계의 잔차 덧셈과 ReLU 뒤에 적용한다.

{{< katex display=true >}}
[\gamma_i; \beta_i] = G_i \bar e + b_i, \qquad F_i \leftarrow (1+\gamma_i) \odot F_i + \beta_i ,
\tag{5}
{{< /katex >}}

채널이 {{< katex >}}c_i{{< /katex >}}개일 때 {{< katex >}}G_i\in\mathbb{R}^{2c_i\times512}{{< /katex >}}와 {{< katex >}}b_i\in\mathbb{R}^{2c_i}{{< /katex >}}는 학습되는 파라미터다. {{< katex >}}[\gamma_i;\beta_i]{{< /katex >}}는 채널별 스케일과 이동량을 이어 붙인 것으로, 모든 픽셀에 똑같이 브로드캐스트된다. 기호 {{< katex >}}\odot{{< /katex >}}는 원소별 곱셈이다. {{< katex >}}G_i{{< /katex >}}와 {{< katex >}}b_i{{< /katex >}}를 0으로 초기화하면 학습 초기에 FiLM은 항등 연산이 된다. 엔진은 투영된 텍스트 토큰과 FiLM 계수를 지시문마다 캐시해 두고, 각 쿼리의 특징에 변조만 적용한다.

> **역주.** 식 (5)는 지시문 평균 임베딩 {{< katex >}}\bar e{{< /katex >}}를 선형 변환해 채널마다 곱할 값 {{< katex >}}1+\gamma_i{{< /katex >}}와 더할 값 {{< katex >}}\beta_i{{< /katex >}}를 만든다. 같은 이미지라도 지시문에 따라 어떤 채널을 강조할지가 달라진다. {{< katex >}}\gamma_i{{< /katex >}}, {{< katex >}}\beta_i{{< /katex >}}는 지시문에만 의존하므로 에피소드당 한 번 계산하면 된다. 여기서 {{< katex >}}b_i{{< /katex >}}는 FiLM의 편향이며, 4.2절 선형 레이어의 편향 {{< katex >}}b{{< /katex >}}와는 별개다.

**Action prediction and training.** 6층 트랜스포머 인코더와 4층 디코더가 청크를 한 번에 예측한다. 디코더 입력은 학습되는 행동 쿼리(action query) 벡터 50개이며, 각 벡터가 행동 하나를 출력한다. 어텐션 헤드는 8개, 피드포워드 폭은 3200이다. 인코더는 시각 토큰과 텍스트 토큰, 상태 토큰 하나, 잠재(latent) 토큰 하나를 입력받는다. 시각 토큰은 2차원 사인파 위치 인코딩을 쓰고, 상태·잠재·텍스트 토큰의 위치는 학습한다. 학습은 ACT의 조건부 변분 오토인코더(conditional variational autoencoder, CVAE) 방식을 따른다. 학습 때만 쓰는 별도의 4층 CVAE 인코더가 시연 행동, 상태, 지시문을 받아 32차원 잠재 변수 {{< katex >}}z{{< /katex >}}의 분포를 예측한다. 목적 함수는 L1 행동 재구성 손실에 쿨백-라이블러(Kullback–Leibler) 페널티를 가중치 10으로 더한 것이다. 이 페널티는 {{< katex >}}z{{< /katex >}}의 분포를 표준 정규 사전분포 쪽으로 당긴다. 추론 때는 {{< katex >}}z=0{{< /katex >}}으로 둔다. 상태와 행동은 학습 데이터의 평균과 표준편차로 정규화하며, 예측값은 실행 전에 로봇 단위로 되돌린다. IMPACT에서 쿼리마다 실행되는 정책 부분은 파라미터가 60M이고, 고정된 T5-small 인코더는 35.3M이다. 인코더의 출력은 에피소드마다 캐시된다.

> **역주.** ACT의 CVAE 구조에서 잠재 변수 {{< katex >}}z{{< /katex >}}는 같은 상황에서도 시연자마다 달랐던 동작 "스타일"을 담는 용도다. 학습 때만 별도 인코더가 정답 행동을 보고 {{< katex >}}z{{< /katex >}}를 추정하고, 추론 때는 사전분포의 평균인 {{< katex >}}z=0{{< /katex >}}을 넣어 결정적인 행동을 얻는다. 따라서 이 4층 인코더는 추론 비용에 들어가지 않는다.

**Computational cost.** SO-101 구성에서 곱셈-덧셈 한 번을 부동소수점 연산 2번으로 세면, 쿼리당 약 88 GFLOP이다. 텍스트 인코딩, 투영, FiLM 계수 생성은 에피소드당 한 번, 약 1.2 GFLOP을 더한다. 언어가 없는 같은 6층 인코더·4층 디코더와 비교하면, 최대 32개의 텍스트 토큰이 쿼리당 약 2.3 GFLOP을, FiLM이 9 MFLOP을 더한다. 이는 전체 연산량의 약 2.6%다. 표 2에 있는 더 얕은 ACT와 비교하면, IMPACT는 CPU 4종에서 쿼리당 {{< katex >}}1.20{{< /katex >}}–{{< katex >}}1.33\times{{< /katex >}}의 시간이 걸린다.

**Measurement protocol.** 쿼리 하나의 시간은 관측 전처리 시작부터, 예측한 행동을 로봇 단위로 변환하기까지로 잰다(4절에서 정의한 범위). 명목 지연 시간은 워밍업 뒤 쿼리 15개의 중앙값이다. 측정은 새 프로세스에서, CPU가 처음에 유휴 온도인 상태로 한다. 설정 A와 B를 비교할 때는 열에 의한 변동을 줄이기 위해 한 세션 안에서 A–B–B–A 순서로 번갈아 측정한다. fp32 구현의 시간을 재기 전에는 출력이 해당 기준 정책과 일치하는지 확인한다. 양자화는 따로 평가한다.

**그림 4.** CPU 4종에서 여섯 가지 구성(100스텝 DP를 뺀 정책 구성)에 대해, 같은 세션에서 번갈아 잰 `vla.simd`와 `torch.compile`의 fp32 행동 공급률을 짝지어 비교한다. 패널마다 세로축 스케일이 다르다. 회색 막대는 두 공급률 중 낮은 쪽이고, 파란색/빨간색 연장 부분은 `torch.compile` 대비 엔진의 이득/손실을 나타낸다. 점선은 초당 30개 행동을 표시하며, 피드백 주파수를 뜻하지 않는다. Ryzen에서 Octo-Small과 SmolVLA는 `vla.simd`를 쓰면 이 선을 넘는다. 100스텝 Diffusion Policy는 그림에서 생략했다.

`vla.simd`의 비교 대상은 컴파일된 PyTorch다. 컴파일에는 `torch.compile` [45]을 기본 모드로 쓰고, Inductor CPU 백엔드를 쓴다. 컴파일하지 않은(eager) 실행도 측정하는데, 정책 5개는 PyTorch 2.11, TurboVLA는 2.13을 쓴다. 모든 구현은 fp32를 쓰고, 같은 쿼리 시간 측정 경계를 쓰며, 워밍업 뒤 번갈아 실행한 블록 6개에서 시간을 잰다. 컴파일 시간은 제외한다. 두 구현 모두 지원되는 경우 지시문에만 의존하는 인코딩을 캐시하고, 같은 스레드 수를 쓰며, PyTorch는 인터옵(inter-op) 스레드를 하나로 둔다. 수치 충실도는 각 정책의 PyTorch 기준 구현과 비교해 확인한다. 관측과 확률적 입력을 동일하게 주고, 미리 정한 허용 오차(절대 오차 {{< katex >}}10^{-2}{{< /katex >}}, 행동 크기 대비 상대 오차 {{< katex >}}10^{-4}{{< /katex >}})를 쓴다. 짝지은 측정값은 같은 세션에서 수집하므로, 표 3의 명목 측정값과 다를 수 있다.

> **역주.** "확률적 입력"은 확산·플로 매칭 정책이 시작점으로 쓰는 노이즈 같은 난수 입력을 말한다. 이를 두 구현에 똑같이 넣어야 출력끼리 비교할 수 있다.

구성–CPU 쌍마다 속도 향상은 블록 안에서 잰 비율 {{< katex >}}T_{\mathrm{compile}}/T_{\mathrm{engine}}{{< /katex >}}의 중앙값으로 정의한다. 28개 쌍(정책 6개 중 DP는 샘플러 2종이라 구성 7개, CPU 4종)의 중앙값은 약 {{< katex >}}1.4\times{{< /katex >}}이며, 범위는 {{< katex >}}0.83{{< /katex >}}–{{< katex >}}3.37\times{{< /katex >}}이다. 대부분의 설정에서 eager 실행과 컴파일된 실행의 지연 시간은 비슷하다. 컴파일 효과가 가장 큰 경우는 M4의 Octo-Small이다. Ryzen에서는 Octo-Small과 SmolVLA가 C1 기준을 넘는다(그림 4). M4에서는 엔진이 오히려 느린 경우가 있다. 이 경우에도 C1 만족 여부는 바뀌지 않지만, 10스텝 Diffusion Policy는 C2를 만족하던 여유를 잃는다.

> **역주.** 그림 4의 빨간 부분(엔진 손실)이 M4에서 느려진 경우로, TurboVLA와 10스텝 DP에서 보인다. 속도 향상이 {{< katex >}}1{{< /katex >}}보다 작은 쌍이며, 표 1대로 M4는 SMK 대신 Apple Accelerate를 커널로 쓴다.

정책별로 관측 2–12개에 대해 따로 수치 비교를 하면, 행동의 최대 절대 차이는 로봇 단위로 많아야 {{< katex >}}8.8{\times}10^{-5}{{< /katex >}}이다. 이 작은 차이는 부동소수점 누적 순서가 바뀐 결과와 들어맞는다. Intel과 AMD 백엔드는 시험한 입력에서 비트 단위로 똑같은 fp32 행동을 낸다. IMPACT의 기준 구현은 저자들이 만든 PyTorch 구현이다. 과제 성능은 아래에서 따로 평가한다.

**표 4.** ACT에서 개별 실행 설정의 효과. A/B: 일관되게 더 빠른 설정, =: 일관된 차이 없음. 값은 {{< katex >}}100(T_B/T_A-1){{< /katex >}}(%)의 중앙값이며 양수면 A가 유리하다. 아래쪽: {{< katex >}}T_{\mathrm{fp32}}/T_{\mathrm{W8A8}}{{< /katex >}}로, 1보다 크면 W8A8이 더 빠르다. n/a: 지원 안 함, –: 측정 안 함.

> **역주.** 예를 들어 i9의 Convolution 행 "A +156"은 타일 방식(A) 대비 평평한 방식(B)이 156% 더 오래 걸렸다는 뜻이다. 즉 타일 방식이 약 2.56배 빠르다. "B −6.2"처럼 B가 붙은 값은 B 설정이 더 빨랐음을 뜻한다.

ACT에서 짝지은 측정 방식으로 설정 11가지를 하나씩 바꿔 본다. 한 설정이 모든 쌍에서(많아야 한 쌍만 예외) 더 빠르고, 효과의 중앙값이 기준선의 변동보다 클 때만 일관된 개선으로 보고한다. 표 4에서 bf16 확장(bf16 expansion)은 bfloat16 가중치를 fp32로 변환하는 것이다. 병렬 컷오프(parallel cutoff)는 병렬로 실행하기 위한 최소 원소 수다. 스레드 수의 많음/적음은 M4에서 10/4, i9에서 32/8, Ryzen에서 12/6, Pi 5에서 4/2이다. 지원되는 정책–CPU 쌍에서는 W8A8과 fp32도 비교하고, 합성곱 레이어와 어텐션 레이어만 골라 양자화하는 경우도 살펴본다. W8A8 비교에서는 지원되는 연산자 그룹을 모두 양자화한다. IMPACT의 경우 ResNet 합성곱, 토큰 투영, 인코더/디코더 선형 레이어가 여기에 해당하며, 텍스트 인코더는 fp32로 둔다. 설정을 한 번에 하나씩 바꾸므로 각 설정의 개별 효과만 측정되고, 설정 사이의 상호작용은 평가하지 않는다.

표 4를 보면, 유용한 설정은 대상 CPU에 따라 다르다. 타일 방식 합성곱은 Apple 이외의 백엔드에 도움이 된다. 카메라 시점마다 스레드를 더 주면 M4에서는 도움이 되지만 다른 기기에서는 오히려 느려진다. 양자화 효과도 고르지 않다. Pi 5에서는 크게 빨라지지만, M4에서는 일부 정책이 느려진다. M4의 IMPACT에서는 합성곱만 양자화하는 편이 모든 레이어를 양자화하는 것보다 빠르다. 이 결과들은 설정과 양자화할 레이어를 각 대상에서 직접 측정해 골라야 한다는 주장을 뒷받침한다.

**LIBERO.** IMPACT를 LIBERO 시뮬레이션 스위트 4개 [46]에서 평가한다. 각 스위트에는 조작 과제가 10개씩 있다. 로봇 데이터 사전학습 없이 스위트마다 정책 하나를 학습하고, 각 과제를 GPU 호스트에서 초기 상태 20개로 평가한다. 학습에는 AdamW를 쓰며, 배치 크기 64, 시드 1000, 고정 학습률 {{< katex >}}10^{-4}{{< /katex >}}, 가중치 감쇠 {{< katex >}}10^{-4}{{< /katex >}}이다. 평가에서는 {{< katex >}}256{\times}256{{< /katex >}} 시점 두 개를 쓰고, 상대 엔드이펙터 행동 50개를 모두 실행한 뒤에 정책에 다시 쿼리한다. 30,000스텝 최종 체크포인트는 평균 성공률 76.4%를 얻는다(표 5). 같은 평가 롤아웃으로 체크포인트를 고르면 78.6%가 된다. 다만 이렇게 고르면 추정치가 부풀려질 수 있으므로, 이 탐색적 결과는 따로 보고한다. 공개된 DP, Octo-Base, OpenVLA 결과는 스위트마다 롤아웃 500개를 시드 3개로 평균한 것이다. TurboVLA는 500개, SmolVLA는 100개를 쓴다 [47, 11, 4]. 이 공개 결과들은 관측 입력과 실행 구간이 서로 달라서, 통제된 비교라기보다 참고용 맥락이다.

> **역주.** 76.4%와 78.6%의 차이: 최종 체크포인트는 학습이 끝난 시점의 모델을 그대로 쓴 값이다. 78.6%는 평가에 쓸 바로 그 에피소드에서 성적이 좋은 체크포인트를 사후에 고른 값이라, 시험 문제를 보고 모델을 고른 것과 같은 낙관적 편향이 있다. 초록과 결론은 76.4%를 쓴다.

**Instruction following.** IMPACT가 언어를 써서 과제를 고르는지 시험하려고, LIBERO-Goal 환경은 그대로 두고 지시문만 바꾼다. 이때 앞에서 평가 성적으로 고른 25,000스텝 체크포인트를 쓴다. 10개 과제는 모두 같은 장면과 물체를 공유한다. 원래 지시문을 모두 다른 과제의 지시문으로 바꾸는 순열 3가지를 평가해, 총 600번 롤아웃한다. 원래 목표와 새로 지시된 목표를 모두 LIBERO의 성공 조건으로 채점한다. IMPACT는 새로 지시된 목표를 91%의 시행에서 달성했고, 원래 목표는 한 번도 달성하지 않았다. 올바른 지시문을 준 대조 실험의 성공률은 88.5%다. 이 개입 실험은 익숙한 목표들 사이에서 언어로 과제를 고른다는 것을 뒷받침한다. 반면 처음 보는 표현으로의 일반화나, 두 조건 경로(텍스트 토큰과 FiLM) 각각의 기여는 아직 시험하지 않았다.

> **역주.** 이 실험에서 장면은 바뀌지 않으므로, 정책이 이미지만 보고 행동한다면 원래 과제를 계속 수행해야 한다. 지시문을 바꿨을 때 원래 목표 달성이 0%이고 새 목표가 91%라는 것은, 정책이 실제로 지시문을 읽고 목표를 바꾼다는 증거다.

**SO-101.** SO-101 로봇 팔(그림 5)에서, 한 장면을 공유하는 지시문 3개에 대해 시연 44개를, 별도의 서랍 과제에 대해 시연 20개를 쓴다. LeRobot의 비동기 인터페이스 [21]는 M4, Pi 5, i5-12400F의 `vla.simd`에 연결하거나, GPU의 PyTorch에 연결한다. 시험은 장면 하나와 조작자 한 명으로 진행한다. IMPACT 결과는 이 CPU·GPU 서버들의 시행을 합친 것이다. 표 6의 각 행은 20회 시행과 윌슨(Wilson) 95% 신뢰구간을 보고한다. IMPACT는 집을 물체를 바꾸는 것보다 놓을 목적지를 고르는 데서 더 잘한다(표 6). fp32와 int8의 성공 횟수는 비슷하지만, 조건마다 20회 시행으로는 두 성능이 같다고 단정하기에 부족하다.

> **역주.** 표 6의 세 과제 중 tape→box와 tape→cup은 같은 물체(테이프)를 다른 곳에 놓는 과제(목적지 선택)이고, cup→box는 집는 물체 자체가 다르다(잡을 대상 변경). IMPACT의 성공률은 앞의 두 과제가 90%, 85%, 마지막이 60%다.

언어가 없는 대조군으로, IMPACT와 같은 청크 길이, 트랜스포머 깊이, 공유 ResNet-18을 쓰되 텍스트와 FiLM을 뺀 ACT를 학습한다. 이 대조군은 CPU 벤치마크에 쓴 ACT보다 깊다. 세 과제 모두에 대한 정책 하나와, 과제 하나씩만 맡는 전문 정책 3개를 학습한다. 모두 배치 크기 8로 19,000스텝 학습하고, 동기 방식으로 실행해 추론과 동작이 겹치지 않는다. 모두 같은 스텝 수로 학습하므로, 각 전문 정책은 더 작은 자기 데이터셋을 더 여러 번 보게 된다. 다중 과제 대조군은 20회 중 4회 성공한 반면, 전문 정책들은 60회 중 46회 성공했다. 조작자는 다중 과제 시행 20회 가운데 9회를 목표의 모호함 탓으로, 7회를 잡기 실패 탓으로 판정했다. 이 관찰은 과제의 모호함이 실패 원인 중 하나임을 시사한다. 하지만 데이터 노출량과 실행 방식이 달라서, 성공률 차이를 언어 조건 하나의 효과로 돌릴 수는 없다.

## 7 Conclusion

본 논문은 두 가지를 제시했다. 하나는 공유 SIMD 커널과 대상별 최적화를 결합한 추론 엔진 `vla.simd`이고, 다른 하나는 반복 연산을 거의 늘리지 않고 언어 기반 과제 선택을 더한 ACT 기반 정책 IMPACT다. 실행 구간이 추론 지연을 메우고, 구현이 프로세서를 효율적으로 쓸 때 CPU 배포가 가능해진다. Ryzen에서 `vla.simd`는 Octo-Small과 SmolVLA를 30Hz 기준 위로 끌어올린다. Pi 5에서는 평가한 언어 조건부 정책 가운데 IMPACT만 이 예산을 만족하며, int8 경로는 발열 후에도 더 엄격한 시간 정렬 예산까지 만족한다. 지시문 섞기 실험과 실제 로봇 시험은 IMPACT가 언어로 목표를 고른다는 것을 보여 준다. 이로써 IMPACT는 ACT를 지시 기반 조작으로 확장한다.

## 8 Limitations

평가는 파라미터 450M 이하의 정책까지 다루며, CPU 추론을 eager PyTorch 및 컴파일된 PyTorch와 비교한다. GPU, 임베디드 가속기, 그리고 ONNX Runtime이나 OpenVINO 같은 전용 런타임은 벤치마크하지 않았다. 예산은 엔진 지연 시간의 중앙값을 쓰지만, 끊김 없는 배포는 관측부터 행동까지 전체 지연의 꼬리(가장 느린 경우들)에 좌우된다. 발열 특성은 90초 가열 한 번으로만 측정했다. int8 경로는 SO-101 다중 과제 환경에서 검증했지만, 시뮬레이션 성공률과 장기 과제에 미치는 영향은 측정하지 않았다. LIBERO 평가는 시드 하나만 쓰고, SO-101 시행은 여러 서버의 결과를 합쳤으므로, 개별 CPU에서의 동작에 대해서는 결론이 제한된다.
