## Abstract

비전-언어-행동(vision-language-action, VLA) 모델은 범용 로봇 정책(generalist robot policy)으로서 큰 가능성을 보여 왔다. 하지만 처음 보는 과제에 적응시키려면 대개 비용이 큰 파라미터 갱신이 필요하다. RICL 같은 최근 연구는 다른 길을 택한다. 테스트 시점에 현재 VLA 관측을 기준으로 전문가 시연(expert demonstration)을 검색하고, 이를 추가 문맥으로 넣어 주어 문맥 내 적응 능력을 부여한다. 검색된 시연이 곧 VLA의 추가 입력이 되므로, 이런 적응이 얼마나 효과적인지는 검색 방식에 크게 좌우된다. 본 논문은 RICL 프레임워크 안에서 검색 방식에 따라 검색 품질과 과제 성능이 각각 어떻게 달라지는지를 체계적으로 조사한다. 구체적으로 네 가지 방식을 비교한다. 이미지 기반 검색, VLA의 상태 정보를 더한 검색, VLA 백본에서 뽑은 특징을 쓰는 검색, 그리고 무작위 검색이다. 실험에서 세 가지 주요 결과를 얻었다. 첫째, 과제 성공률에서 다른 방식들을 일관되게 앞서는 검색 방식은 없었다. 놀랍게도 무작위 검색조차 무시할 수 없는 성공률을 달성했다. 둘째, 표준적인 검색 품질 진단 지표는 실제 VLA 성능을 신뢰할 만하게 반영하지 못했다. 셋째, 서로 다르지만 관련된 과제의 시연도 전이 가능한 유용한 정보를 줄 수 있었다. 이 결과들은 검색 방식이 VLA 모델의 문맥 내 학습 능력과 실제 과제 성능을 어떻게 좌우하는지 이해하는 첫걸음이다. 동시에, 신뢰할 수 있는 테스트 시점 적응을 위해서는 검색 방식을 더 신중하게 설계하고 평가해야 함을 보여 준다.

> **역주.** *문맥 내 학습(in-context learning, ICL)*\ 은 모델 파라미터를 바꾸지 않고, 입력에 함께 넣어 준 몇 개의 예시만 보고 새 과제를 수행하는 능력이다. RICL은 이 아이디어를 로봇에 옮겨, 지금 상황과 비슷한 전문가 시연 프레임을 버퍼에서 찾아(검색) VLA 입력에 예시로 붙인다. 본 논문의 질문은 "무엇을 기준으로 비슷한 시연을 찾아야 하는가"이다.

## 1 Introduction

최근 비전-언어-행동(VLA) 모델 [1, 2, 3, 4, 5, 6, 7, 8]이 발전하면서, 하나의 정책으로 다양한 로봇 조작 과제를 수행할 수 있게 되었다. 이는 VLA가 범용 로봇 제어 정책이 될 수 있음을 보여 준다. 그러나 강력한 사전 학습 VLA라도 분포 변화(distribution shift)가 생기면 상당한 파인튜닝이나 재학습이 필요한 경우가 많다. 새로운 환경, 처음 보는 물체, 새로운 과제 지시가 그런 예이다 [9]. 이 때문에 배포 현장에서 빠르게 적응하기가 어렵다. 반면 대규모 언어 모델(LLM) [10, 11, 12, 13, 14, 15, 16, 17, 18]은 추론 시점에 문맥 내 학습(ICL)으로 새 과제에 적응하는 경우가 많다. 입력-출력 예시 몇 개만 문맥으로 주면, 파라미터를 갱신하지 않고도 새 과제에 적응한다 [19, 20, 21]. 이 패러다임에서 착안해, RICL [22]은 사전 학습된 VLA가 미리 수집한 전문가 시연을 조건으로 행동을 예측하게 만든다. 이렇게 VLA에 문맥 내 적응 능력을 부여해, 테스트 시점에 파라미터를 갱신하지 않고도 처음 보는 과제에 적응하게 한다. 구체적으로 RICL은 전문가 시연을 담은 작은 검색 버퍼(retrieval buffer)를 유지한다. 그리고 현재 관측이 주어지면 관련된 시연을 검색해 VLA 정책에 추가 문맥으로 제공한다. 테스트 시점에 VLA가 받는 과제 특화 정보는 검색된 예시가 결정한다. 따라서 이런 검색 기반 문맥 내 적응의 효과는 검색 버퍼에서 어떤 시연을 고르느냐에 크게 좌우된다.

본 논문은 다음 질문을 다룬다. 처음 보는 과제에 적응하는 데 가장 유용한 시연을 돌려받으려면, 검색할 때 현재 관측을 어떻게 표현해야 하는가? 원래 RICL 프레임워크는 현재 이미지의 임베딩만으로 검색한다. 본 논문은 여기에 추가 정보를 넣으면 검색이 더 효과적이 되고 과제 성능도 좋아지는지 조사한다. 추가 정보로는 로봇의 고유수용 상태(proprioceptive state, 관절 각도·그리퍼 상태 같은 로봇 자신의 상태)와 VLA 백본에서 직접 뽑은 특징을 시험한다. 주요 결과는 다음 세 가지이다. 첫째, **어떤 검색 표현도 확실히 우세하지 않다.** 놀랍게도 무작위 검색조차 무시할 수 없는 성공률을 보였다. 이는 현재 관측과의 유사도로 고르지 않은 시연에서도 VLA가 여전히 도움을 받을 수 있음을 시사한다. 둘째, **검색 품질이 좋다고 해서 실제 제어 성능이 반드시 좋아지지는 않는다.** 셋째, **서로 다르지만 관련된 과제에서 검색한 시연도 전이 가능한 유용한 정보를 줄 수 있다.** 종합하면, VLA 적응을 위한 검색을 개선하려면 현재 관측과 저장된 시연 사이의 단순한 유사도 매칭을 넘어서야 한다. 추가 정보를 그대로 덧붙이는 식의 단순한 확장으로도 충분하지 않다. 더 중요한 점은, 검색 품질 지표가 실제 VLA 실행에서의 효과를 더 잘 반영하도록 설계되어야 한다는 것이다.

## 2 Preliminaries: RICL Framework

본 논문은 선행 연구 [9, 22]를 따라 일반적인 로봇 조작 설정을 고려한다. 사전 학습된 VLA 정책 {{< katex >}}\pi_\theta{{< /katex >}}는 테스트 시점에 파라미터를 전혀 갱신하지 않은 채, 처음 보는 환경에서 새로운 과제를 수행해야 한다. 각 과제는 자연어 지시 {{< katex >}}x^{\mathrm{text}}{{< /katex >}}로 주어진다. 타임스텝 {{< katex >}}t{{< /katex >}}에서 에이전트는 다중 뷰 이미지 {{< katex >}}I_t=(I_t^{\mathrm{top}},I_t^{\mathrm{side}},I_t^{\mathrm{wrist}}){{< /katex >}}와 고유수용 상태 {{< katex >}}s_t{{< /katex >}}를 관측한다. 세 이미지는 각각 위쪽, 옆쪽, 손목 카메라로 찍은 것이다. 표준 VLA 정책은 {{< katex >}}\hat a_t \sim \pi_\theta(\cdot \mid I_t,s_t,x^{\mathrm{text}}){{< /katex >}}에 따라 행동을 예측한다. 즉, 현재 이미지, 상태, 지시를 보고 다음 행동의 분포를 내놓는다.

사전 학습 VLA 정책은 범용 로봇 제어에서 유망한 능력을 보여 왔지만, 분포 변화 아래에서는 성능이 여전히 불안정한 경우가 많다 [1, 2]. [22]는 Re-training for In-Context Learning(RICL)을 제안했다. RICL은 검색한 전문가 시연을 VLA 정책이 문맥 내 예시로 쓰게 해서 테스트 시점 적응력을 높인다. {{< katex >}}\mathcal D=\{m_i\}_{i=1}^{N}{{< /katex >}}을 {{< katex >}}N{{< /katex >}}개의 전문가 시연 프레임으로 이루어진 작은 검색 버퍼라 하자. 각 항목은 {{< katex >}}m_i=(I_i,s_i,x_i^{\mathrm{text}},a_i){{< /katex >}}이다. 여기서 {{< katex >}}I_i=(I_i^{\mathrm{top}},I_i^{\mathrm{side}},I_i^{\mathrm{wrist}}){{< /katex >}}는 시연 상태의 다중 뷰 이미지, {{< katex >}}s_i{{< /katex >}}는 그에 대응하는 고유수용 상태, {{< katex >}}x_i^{\mathrm{text}}{{< /katex >}}는 과제 지시이다. {{< katex >}}a_i{{< /katex >}}는 전문가 행동 또는 행동 청크(action chunk, 즉 여러 타임스텝에 걸친 행동의 배열)이다. 이 시연들은 테스트 시점에 VLA 파라미터를 갱신하는 데 쓰이지 않는다. 대신 현재 과제에 정책을 적응시키는 외부 문맥 역할을 한다. 매 타임스텝 {{< katex >}}t{{< /katex >}}마다 RICL은 시연 버퍼 {{< katex >}}\mathcal D{{< /katex >}}에서 관련 항목 몇 개를 검색한다. {{< katex >}}f_{\mathrm{DINO}}{{< /katex >}}를 고정된(frozen) DINOv2 이미지 인코더 [23]라 하자. RICL은 위쪽 카메라 이미지 {{< katex >}}I_t^{\mathrm{top}}{{< /katex >}}을 검색 쿼리로 쓰고, 이를 각 시연 항목의 위쪽 카메라 이미지와 비교한다. 구체적으로 각 항목 {{< katex >}}m_i\in\mathcal D{{< /katex >}}에 대해 거리 {{< katex >}}d_t(i)=\lVert f_{\mathrm{DINO}}(I_t^{\mathrm{top}})-f_{\mathrm{DINO}}(I_i^{\mathrm{top}})\rVert_2{{< /katex >}}를 계산한다. 그다음 가장 가까운 {{< katex >}}M{{< /katex >}}개 항목을 {{< katex >}}(j_1,\ldots,j_M)=\operatorname{TopM}_{i\in\{1,\ldots,N\}}^{\mathrm{smallest}} d_t(i){{< /katex >}}로 고른다. 이때 {{< katex >}}d_t(j_1)\le d_t(j_2)\le \cdots \le d_t(j_M){{< /katex >}}이다. 검색된 문맥은 {{< katex >}}\mathcal M_t=(m_{j_1},\ldots,m_{j_M}){{< /katex >}}이며, 가장 가까운 이웃부터 가장 먼 이웃 순으로 정렬된다. RICL 정책은 검색된 문맥과 현재 상태를 함께 조건으로 다음 행동을 예측한다: {{< katex >}}\hat a_t \sim \pi_\theta^{\mathrm{RICL}}(\cdot \mid \mathcal M_t,I_t,s_t,x^{\mathrm{text}}){{< /katex >}}. 이렇게 RICL은 원래의 VLA 행동 예측 문제를 *검색 조건부* 행동 예측 문제로 바꾼다. 정책은 현재 관측을 소수의 검색된 전문가 예시와 비교해 적절한 행동을 추론해야 한다. VLA 모델의 문맥 내 학습에 관한 자세한 관련 연구는 부록 C에 정리했다.

> **역주.** 정리하면 RICL의 검색은 "현재 위쪽 카메라 이미지를 DINOv2로 임베딩하고, 버퍼에 있는 모든 시연 프레임의 위쪽 이미지 임베딩과의 유클리드 거리가 가장 작은 {{< katex >}}M{{< /katex >}}개를 고른다"는 최근접 이웃 탐색이다. 이름의 "Re-training"은 VLA가 검색된 예시를 활용하도록 미리 한 번 사후 학습한다는 뜻이며, 테스트 시점에는 파라미터를 바꾸지 않는다.

## 3 Empirical Study of Retrieval for VLA Adaptation

이 절에서는 실험을 통해 다음 연구 질문에 답한다. (1) 어떤 검색 표현이 가장 잘 작동하는가? (2) 표준적인 검색 품질 진단 지표가 실제 제어 성능을 신뢰할 만하게 예측하는가? (3) 다른 과제의 시연을 검색하는 것이 반드시 해로운가?

### 3.1 Experimental Setup

모든 실험은 대체로 RICL [22]의 설정을 따르며, 중요한 세부 사항과 몇 가지 변경점은 아래에 밝힌다. 추가 구현 세부 사항은 부록 D에 있다.

**Evaluation Benchmark.** 모든 방법을 **LIBERO** 벤치마크 [24]에서 평가한다. LIBERO는 원래 RICL 연구에서 다루지 않은 벤치마크로, Franka Panda 로봇 팔을 중심으로 만든 시뮬레이션 로봇 조작 벤치마크이다. 검색용으로는 과제당 전문가 시연 20개를 담은 공용 시연 버퍼를 만들고, 모든 검색 방식이 이 같은 버퍼를 사용한다. 평가에는 25개 과제를 고른다. 각 과제는 고정된 초기 장면 10개에서 테스트하며, 이 장면들은 검색 버퍼를 만드는 데 쓴 시연 장면과 겹치지 않는다.

> **역주.** 본문은 "과제당 20개"의 과제가 어느 과제인지 따로 밝히지 않는다. 부록 D에서 무작위 검색의 동일 과제 검색률 기댓값을 {{< katex >}}1/25{{< /katex >}}로 계산하므로, 평가 과제 25개 각각의 시연 20개씩이 버퍼에 들어 있는 것으로 읽힌다.

**Model Architecture.** RICL 설정을 따라, 모든 검색 방식을 같은 {{< katex >}}\pi_0{{< /katex >}}-FAST VLA 모델 [3] 하나로 평가하며, 평가 중에는 이 모델의 파라미터를 바꾸지 않는다(고정). 원래의 RICL 모델은 다른 벤치마크용으로 학습되었으므로, 평가에 앞서 이에 상응하는 RICL 사후 학습(post-training) 절차로 모델을 LIBERO에서 추가 학습해 둔다.

**Retrieval Methods.** 네 가지 검색 방식을 비교한다.

- `RICL-Image`는 원래 RICL 설정을 따른다. 위쪽 카메라 이미지의 DINOv2 임베딩만으로 시연을 검색한다.
- `RICL-ImageState`는 이미지 기반 검색에 고유수용 상태 {{< katex >}}s_t{{< /katex >}}를 더한다. 그래서 검색 점수가 시각적 유사도와 로봇 상태 유사도를 함께 반영한다. 상태 정보를 넣으면 검색이 나아지는지 평가하려고 이 방식을 포함했다.
- `RICL-VLAFeat`는 {{< katex >}}\pi_0{{< /katex >}}-FAST 모델에서 직접 뽑은 특징으로 검색한다. 입력은 위쪽 카메라 이미지와 고유수용 상태이다. 이 방식은 VLA가 스스로 학습한 표현이 범용 시각 특징보다 더 효과적인 검색을 가능하게 하는지 시험한다.
- `RICL-Random`은 시연 버퍼에서 항목을 균등하게 무작위 추출하며, 비교를 위한 기준선(baseline) 역할을 한다.

모든 방식은 같은 시연 버퍼에서 {{< katex >}}M=4{{< /katex >}}개 항목을 검색한다.

### 3.2 Results

**표 1.** 네 가지 검색 방식의 주요 결과와, 방식을 두 개씩 짝지은 쌍별 비교. *{{< katex >}}\Delta{{< /katex >}}*는 두 방식 사이의 차이를 뜻한다. McNemar-{{< katex >}}p{{< /katex >}}가 작을수록 두 방식의 성공률이 유의하게 다르다는 근거가 강하다. **No retrieval representation clearly dominates.** 표 1은 네 가지 검색 방식의 주요 결과이다. 전체 성공률과 함께 과제 계층 부트스트랩 신뢰구간(task-hierarchical bootstrap confidence interval, 표에서 *task-hier. CI*)도 보고한다. 이 구간은 과제 단위의 불확실성을 담는다. 어떤 방식은 일부 과제에서 잘하고 다른 과제에서 실패하면서도 평균 성공률은 높게 나올 수 있다. 개별 시행이 아니라 과제 단위로 부트스트랩하면 과제 간 편차가 구간에 반영된다. 그래서 검색 방식이 여러 과제에 걸쳐 얼마나 안정적으로 작동하는지를 시행 단위보다 더 보수적으로 추정할 수 있다. 부트스트랩 절차의 자세한 내용은 부록 D에 있다. 검색 방식끼리 쌍별 비교도 수행한다. 각 비교에는 McNemar 검정(exact paired McNemar test, 같은 장면에서 나온 두 방식의 결과를 짝지어 근사 없이 계산하는 정확 검정) [25, 26]을 쓰고(부록 D 참조) 그 {{< katex >}}p{{< /katex >}}값을 보고한다. {{< katex >}}p{{< /katex >}}값이 작을수록 두 방식의 성공률이 다르다는 근거가 강하다. 표 1을 보면, 성공률만 놓고 볼 때 `RICL-VLAFeat`가 {{< katex >}}40.4\%{{< /katex >}}로 가장 높다. `RICL-Image`({{< katex >}}40.0\%{{< /katex >}})와 `RICL-ImageState`({{< katex >}}36.8\%{{< /katex >}})를 근소하게 앞선다. 이는 VLA 백본에서 뽑은 특징이 별도의 DINOv2 인코더 없이도 효과적인 검색 표현이 될 수 있음을 시사한다. 눈여겨볼 점은, 이미지 기반 검색에 고유수용 상태를 더해도 성능이 나아지지 않고 오히려 수치상 성공률이 낮아졌다는 것이다. 그러나 이 차이들은 작다. 세 검색 방식 간 쌍별 비교의 McNemar-{{< katex >}}p{{< /katex >}} 값은 모두 크다. 따라서 어느 검색 방식도 다른 방식보다 통계적으로 우수하다고 입증할 수 없다. 또 하나 주목할 점은 `RICL-Random`의 성능이 비교적 높다는 것이다. 시연을 완전히 무작위로 균등하게 뽑았는데도 성공률이 {{< katex >}}26.0\%{{< /katex >}}이다. 이는 현재 쿼리와의 유사도로 고르지 않은 시연에서도 VLA가 여전히 도움을 받을 수 있음을 시사한다. 혹은 관련 없는 시연이 문맥에 들어와도 VLA의 행동이 어느 정도 견고하게 유지된다는 뜻일 수도 있다. 세 검색 방식 모두 평균 성공률은 `RICL-Random`보다 높다. 하지만 쌍별 비교에서 확실히 양(+)의 개선을 보인 것은 `RICL-VLAFeat`뿐이다. {{< katex >}}\Delta{{< /katex >}} Succ.{{< katex >}}=14.4{{< /katex >}}%p, {{< katex >}}\Delta{{< /katex >}} Task-hier. CI {{< katex >}}=[2.8,26.0]{{< /katex >}}, McNemar-{{< katex >}}p=0.000044{{< /katex >}}이다. 반면 `RICL-Image`와 `RICL-ImageState`의 해당 신뢰구간은 0을 포함한다. 즉, 이 두 방식이 `RICL-Random`보다 나은 정도가 과제 전반에서 일관되게 양수는 아니다. 이 결과는 본 논문의 평가 설정에서 VLA 백본 특징이 무작위 검색 대비 더 일관되게 유용한 검색 신호를 줄 수 있음을 시사한다. 다만 다른 검색 방식보다 뚜렷하게 우세하다는 것까지 보여 주지는 않는다.

> **역주.** 표 1(b)에서 `RICL-Image`와 `RICL-ImageState`는 `RICL-Random` 대비 McNemar-{{< katex >}}p{{< /katex >}}가 각각 0.000425, 0.003으로 작은데도, 과제 계층 신뢰구간은 0을 포함한다. 두 값이 보는 단위가 다르기 때문이다. McNemar 검정은 250개(25과제 × 10장면) 개별 시행을 짝지어 비교하고, 과제 계층 신뢰구간은 25개 과제를 표본 단위로 다시 뽑으므로 과제별 편차가 크면 구간이 넓어진다. 본문이 "확실히 양의 개선"이라는 표현을 두 기준을 모두 만족한 `RICL-VLAFeat`에만 쓰는 이유이다.

**표 2.** 검색 품질 분석. NDCG 값이 높을수록 검색된 시연이 쿼리와 더 관련이 깊다는 뜻이다. 동일 과제 검색률(exact-task retrieval rate)은 오프라인(Offline)과 온폴리시(On-Policy) 두 설정에서 측정했다.

| 방식 | 동일 과제 검색률 (Offline) | 동일 과제 검색률 (On-Policy) | NDCG |
|---|---|---|---|
| `RICL-Image` | 87.2% | 51.8% | 0.7461 |
| `RICL-ImageState` | 87.9% | 48.9% | 0.7897 |
| `RICL-VLAFeat` | 83.1% | 38.7% | 0.7280 |
| `RICL-Random` | 4.0% | 4.1% | 0.0199 |

**Retrieval quality does not reliably predict control performance.** 검색 품질이 VLA의 실제 행동과 어떤 관계인지 이해하기 위해, 서로 보완적인 두 가지 측정을 쓴다. 둘 다 같은 과제의 시연이 직접 관련된 정보를 줄 가능성이 더 높다는 가정에 바탕을 둔다. 첫째는 동일 과제 검색률(exact-task retrieval rate)이다. 검색된 항목 중 과제가 쿼리의 과제와 일치하는 비율로 정의한다. 이 지표를 두 설정에서 평가한다. 오프라인(offline) 설정에서는 평가 장면마다 전문가가 성공한 시연에서 뽑은 상태를 쿼리로 쓴다. 온폴리시(on-policy) 설정에서는 실행 중 VLA가 실제로 방문한 상태를 쿼리로 쓴다. 이 비교는 쿼리를 성공한 전문가 궤적의 상태에서 정책 자신이 마주친 상태로 바꾸면 검색 결과가 어떻게 달라지는지 보여 준다. 둘째로, 오프라인 설정에서 검색 관련도를 평가하려고 Normalized Discounted Cumulative Gain(NDCG) [27]을 추가로 쓴다. 여기서는 검색된 프레임이 같은 과제에서 왔고, 그 뒤에 이어지는 행동 청크가 쿼리 상태의 행동 청크와 더 비슷할수록 더 관련 있다고 본다. 추가 구현 세부 사항은 부록 D에 있다. 표 2를 보면 오프라인과 온폴리시 동일 과제 검색률 사이에 큰 격차가 있다. 전문가 프레임으로 오프라인 쿼리를 하면, 세 검색 방식 모두 검색된 항목의 {{< katex >}}80\%{{< /katex >}} 이상이 같은 과제의 시연이다. 그러나 실행 중 VLA가 실제로 방문한 상태로 쿼리하면 이 비율이 크게 떨어진다. 이는 오프라인에서 잘 되던 검색이, 정책이 실제로 실행하며 만나는 상태에서는 같은 정도로 되지 않음을 시사한다. 오프라인 NDCG와 과제 성공률을 비교해도 비슷한 불일치가 나타난다. 오프라인 NDCG는 `RICL-ImageState`가 {{< katex >}}0.7897{{< /katex >}}로 가장 높고, `RICL-Image`({{< katex >}}0.7461{{< /katex >}})와 `RICL-VLAFeat`({{< katex >}}0.7280{{< /katex >}})가 뒤를 잇는다. 그러나 표 1에서 보듯 `RICL-ImageState`는 세 검색 방식 중 성공률이 가장 낮고, `RICL-VLAFeat`가 수치상 가장 높은 성공률을 보인다. 이 결과는 검색 품질이 좋다고 해서 실제 제어 성능이 반드시 좋아지지는 않음을 보여 준다.

> **역주.** 표 2의 `RICL-Random` 오프라인 값 4.0%는 실제 측정값이 아니라 기댓값(무작위로 뽑은 항목이 쿼리와 같은 과제일 확률 1/25)이다. 부록 D에서 저자들은 `RICL-Random`의 오프라인 설정은 평가하지 않았다고 밝힌다.

**Retrieval from different tasks can provide useful information.** 다른 과제의 시연을 검색하는 것이 곧 검색 실패를 뜻하는지 알아보기 위해, 대표적인 검색 기록을 더 살펴본다. 그림 1은 `RICL-Image`가 Task 52에서 성공한 예시이다. 과제를 실행하는 동안 주로 검색되는 출처가 Task 50, Task 49, Task 46을 거쳐 마지막에는 같은 과제인 Task 52로 바뀐다. 이 예시는 VLA가 동일 과제 검색에만 의존하지 않음을 보여 준다. 여러 관련 과제가 전이 가능한 조작 구조를 공유하면, VLA는 그 과제들의 시연도 활용할 수 있다. 추가 예시는 부록 E에 있다. 한편, 장면 구조는 비슷하지만 목표가 다른 두 과제가 일관되게 서로의 시연을 검색하는 경우도 관찰된다. Task 24(검은 그릇을 캐비닛 맨 아래 서랍에 넣기)와 Task 25(검은 그릇을 캐비닛 위에 올려놓기)가 그 예이다(부록 E의 그림 3). 두 과제는 같은 물체와 같은 환경을 다루지만 목표 위치가 다르다. 이는 다른 과제에서 검색했다고 해서 자동으로 잘못된 검색으로 봐서는 안 됨을 시사한다. 그런 검색이 유용한지는, 검색된 시연이 현재 과제 목표에 맞는 행동 정보를 주는지에 달려 있다.

## A Conclusion

본 논문은 RICL 프레임워크 안에서 검색 방식이 비전-언어-행동 모델의 문맥 내 적응에 어떤 영향을 주는지 연구했다. 결과에 따르면, 실제 과제 성공률에서 다른 방식들을 일관되게 앞서는 검색 표현은 없었고, 무작위 검색조차 무시할 수 없는 성공률을 보였다. 또한 표준적인 검색 품질 진단 지표는 실제 제어 성능을 신뢰할 만하게 예측하지 못했다. 쿼리가 전문가 상태에서 VLA가 실제로 마주친 상태로 바뀌면 검색 행동이 크게 달라지기 때문이다. 마지막으로 정성적 분석에서는, 서로 다르지만 관련된 과제의 시연도 전이 가능한 유용한 정보를 줄 수 있음을 확인했다. 종합하면, VLA 적응을 위한 효과적인 검색에는 단순한 유사도 매칭이나 관측 정보를 그대로 덧붙이는 것 이상이 필요하다. 앞으로의 검색 방식은 검색된 시연이 현재의 제어 결정에 실제로 유용한지를 더 잘 고려해야 한다. 그리고 검색 품질 지표는 실제 실행 중 VLA의 행동을 더 충실히 반영해야 한다.

## C Related Work

OpenVLA [2]나 {{< katex >}}\pi_0{{< /katex >}} [1] 같은 최근 비전-언어-행동(VLA) 모델은 크고 다양한 로봇 데이터셋으로 사전 학습해 강한 일반화 능력을 보여 주었다. 그러나 새 과제에 적응시키려면 여전히 과제별 파인튜닝이나 재학습이 필요한 경우가 많고, 이 때문에 진정한 범용 에이전트처럼 행동하기 어렵다. 반면 사람은 이전 경험을 끌어와 새 과제에 빠르게 적응할 수 있다 [28, 29, 30]. 이 능력에서 착안해, 최근 연구들은 *문맥 내 모방 학습(in-context imitation learning)*\ 을 탐구해 왔다. 새 과제의 시연을 추론 시점에 VLA에 직접 넣어 주어, 모델 파라미터를 갱신하지 않고 적응하게 하는 방식이다. ICRT [31]는 초기의 대표적인 접근이다. ICRT는 로봇 제어를 시각 관측, 고유수용 상태, 행동으로 이루어진 시퀀스에 대한 다음 토큰 예측 문제로 정식화한다. 사람이 원격 조작한 궤적을 하나 이상 트랜스포머의 문맥에 넣으면, ICRT는 테스트 시점 파라미터 갱신 없이도 처음 보는 과제를 추론해 수행할 수 있다. 이는 자기회귀 모델의 문맥 내 학습 능력이 언어에서 연속적인 로봇 제어로 확장될 수 있음을 보여 준다. 더 최근에 RICL [22]은 이런 능력이 사전 학습된 VLA에서 저절로 생기지 않음을 보였다. 그래서 사전 학습된 {{< katex >}}\pi_0{{< /katex >}}-FAST 정책이 검색된 시연을 활용하도록 명시적으로 사후 학습하는 방법을 제안했다. 배포 시점에 RICL은 작은 시연 버퍼에서 관련된 상태와 행동을 검색해 모델 문맥에 넣는다. 이렇게 하면 모델 파라미터를 갱신하지 않고 대략 10\~20개의 시연만으로 새로운 조작 과제에 적응할 수 있다.

이와 나란히, 기존의 고정된(frozen) VLA가 ICL을 위한 추가 사후 학습 없이도 시연의 도움을 받을 수 있는지 조사하는 연구 방향도 있다. Retrieval-VLA [9]는 관련된 과거 경험을 찾아내고, 그 정보를 고정된 VLA의 예측에 직접 반영해 학습 없이(training-free) 적응하게 한다. 이 방식은 검색된 시연을, VLA가 해석법을 스스로 배워야 하는 문맥 형태로 주지 않는다. 그래서 ICL 전용 사후 학습도 필요 없다. 이후 연구들은 시연이 주는 정보를 더 풍부하게 만든다. 예를 들어 StellaVLA [32]는 단순한 궤적 유사도에만 의존하는 대신, 검색된 궤적을 구조화된 과제 계획, 하위 목표, 동작 설명으로 바꾼 뒤 VLA에 조건으로 준다. 종합하면, 이 연구들은 시연과 검색이 유망한 인터페이스임을 보여 주었다. 과제별 파라미터 갱신 없이도 VLA를 빠르게 적응시킬 수 있다는 것이다.

## D Additional Implementation Details

**Evaluation Benchmark.** LIBERO에서 과제 ID 20\~69 범위의 평가 과제 25개를 골랐다(표 3). 지시문이 같은 과제가 있지만, 이는 LIBERO에서 서로 다른 과제 ID와 장면에 해당한다. 과제 0\~19는 VLA 모델의 사후 학습에 쓰였으므로 평가에서 제외했다. 이렇게 하면 평가하는 모든 과제가 사후 학습 중에 보지 못한 과제가 된다. 그래서 검색 덕분에 일어나는 테스트 시점 적응을 측정할 수 있다. 또한 고정된 VLA가 기본적인 수행 능력을 전혀 보이지 않는 과제도 제외했다. 후보 과제마다 원래 RICL 검색 설정으로 VLA를 10번 실행하고, 한 번이라도 성공하면 그 과제를 남겼다. 이는 현재 VLA의 능력을 넘어서는 과제를 피하기 위해서이다. 그런 과제에서는 검색 방식을 바꿔도 측정 가능한 차이가 생기기 어렵다. 결과적으로 본 평가는 VLA가 최소한의 능력은 갖춘 과제, 그래서 검색 설계의 효과를 의미 있게 비교할 수 있는 과제에 집중한다.

**Model Architecture.** RICL 설정을 따라, 모든 검색 방식을 파라미터가 고정된 같은 {{< katex >}}\pi_0{{< /katex >}}-FAST VLA 모델 [3]로 평가한다. 원래의 RICL 모델은 다른 벤치마크에서 학습되었으므로, 평가에 앞서 VLA를 LIBERO에 맞게 추가로 적응시킨다. 구체적으로 Physical Intelligence의 공식 `pi0_fast_libero` 체크포인트[^2]로 모델을 초기화하고, LIBERO의 처음 20개 과제(ID 0\~19)에서 과제당 시연 20개로 10,000스텝 사후 학습한다. 이 학습 설정은 원래 RICL 연구 [22]에서 쓴 10k스텝 사후 학습 프로토콜과 같다.

[^2]: <https://huggingface.co/Fisher-Wang/pi0-fast-libero-jax>

**Hardware.** 모든 실험은 Aalto 대학의 고성능 컴퓨팅 클러스터인 Triton에서 수행했다. {{< katex >}}\pi_0{{< /katex >}}-FAST VLA의 LIBERO 파인튜닝(위의 사후 학습)에는 NVIDIA H100 GPU 2장을 썼다. 모든 검색 방식의 평가는 메모리 32 GB의 NVIDIA GeForce RTX 5090 GPU 1장에서 수행했다.

**Retrieval Methods** `RICL-ImageState`: 이 방식은 원래의 이미지 기반 검색 방식인 `RICL-Image`에 로봇의 고유수용 상태 {{< katex >}}s{{< /katex >}}를 더한다. 구체적으로 {{< katex >}}s_t\in\mathbb{R}^8{{< /katex >}}을 현재 쿼리의 상태, {{< katex >}}s_i\in\mathbb{R}^8{{< /katex >}}을 검색 버퍼의 시연 항목 {{< katex >}}m_i\in\mathcal D{{< /katex >}}에 딸린 상태라 하자. 각 상태 벡터는 8차원이다. 먼저 VLA 사후 학습에 쓴 LIBERO 데이터에서 계산한 평균과 표준편차로 상태의 각 차원을 정규화한다. 즉, {{< katex >}}\mu_k{{< /katex >}}와 {{< katex >}}\sigma_k{{< /katex >}}를 상태의 {{< katex >}}k{{< /katex >}}번째 차원의 평균과 표준편차라 할 때, 정규화된 상태를 {{< katex >}}\tilde s^{(k)}=(s^{(k)}-\mu_k)/\sigma_k{{< /katex >}} ({{< katex >}}k=1,\ldots,8{{< /katex >}})로 정의한다. 그러면 현재 쿼리와 항목 {{< katex >}}m_i{{< /katex >}} 사이의 상태 거리는 {{< katex >}}d_t^{\mathrm{state}}(i)=\lVert\tilde s_t-\tilde s_i\rVert_2{{< /katex >}}이다. 이미지 거리는 원래 RICL의 것을 그대로 쓴다: {{< katex >}}d_t^{\mathrm{img}}(i)=\lVert f_{\mathrm{DINO}}(I_t^{\mathrm{top}})-f_{\mathrm{DINO}}(I_i^{\mathrm{top}})\rVert_2{{< /katex >}}. 이미지 거리와 상태 거리는 수치 범위가 다를 수 있다. 그래서 쿼리마다 두 거리를 검색 버퍼 전체에서의 중앙값으로 각각 나눠 스케일을 맞춘다. 구체적으로 {{< katex >}}m_t^{\mathrm{img}}=\operatorname{median}_{j\in\{1,\ldots,N\}} d_t^{\mathrm{img}}(j){{< /katex >}}, {{< katex >}}m_t^{\mathrm{state}}=\operatorname{median}_{j\in\{1,\ldots,N\}} d_t^{\mathrm{state}}(j){{< /katex >}}로 정의한다. 그러면 정규화된 거리는 {{< katex >}}\bar d_t^{\mathrm{img}}(i)=\frac{d_t^{\mathrm{img}}(i)}{m_t^{\mathrm{img}}}{{< /katex >}}, {{< katex >}}\bar d_t^{\mathrm{state}}(i)=\frac{d_t^{\mathrm{state}}(i)}{m_t^{\mathrm{state}}}{{< /katex >}}이다. 두 항을 더해 최종 검색 점수를 얻는다.

{{< katex display=true >}}
d_t^{\mathrm{ImageState}}(i)=\bar d_t^{\mathrm{img}}(i)+\bar d_t^{\mathrm{state}}(i).
{{< /katex >}}

{{< katex >}}d_t^{\mathrm{ImageState}}(i){{< /katex >}}가 가장 작은 {{< katex >}}M{{< /katex >}}개 항목을 문맥 내 시연으로 검색한다.

> **역주.** 여기서 {{< katex >}}m_t^{\mathrm{img}}{{< /katex >}}, {{< katex >}}m_t^{\mathrm{state}}{{< /katex >}}는 거리의 중앙값(median)으로, 2절에서 버퍼 항목을 가리키던 {{< katex >}}m_i{{< /katex >}}와는 다른 기호이다. 중앙값으로 나누면 두 거리 모두 "버퍼에서 보통 수준의 거리"가 1이 되므로, 어느 한쪽이 수치 범위만으로 점수를 지배하지 않는다.

**표 3.** 평가에 사용한 LIBERO 과제 25개(과제 ID와 과제 지시문).

`RICL-VLAFeat`: 이 방식은 VLA 모델에서 직접 뽑은 특징이 DINOv2가 만드는 범용 시각 특징보다 더 효과적인 검색 표현이 되는지 조사한다. 특징 추출기로는 Physical Intelligence의 `pi0_fast_libero` 체크포인트를 쓴다. 위쪽 카메라 이미지 {{< katex >}}I_t^{\mathrm{top}}{{< /katex >}}과 정규화된 고유수용 상태 {{< katex >}}\tilde{s}_t{{< /katex >}}가 주어지면, 먼저 이를 {{< katex >}}\pi_0{{< /katex >}}-FAST가 쓰는 토큰 표현으로 인코딩하고 트랜스포머 백본으로 처리한다. 최종 행동 예측을 쓰는 대신, 첫 번째 트랜스포머 블록에서 중간 표현을 뽑는다. 구체적으로는 첫 블록의 셀프 어텐션 출력에 출력 투영(output projection)까지 적용한 값을 쓴다. 그중 마지막 유효 입력 토큰(패딩이 아닌 마지막 토큰) 위치의 벡터를 가져온다. 이 표현은 이후의 트랜스포머 처리 전에 입력 관측의 정보를 모아 담고 있다. 그 결과 2,048차원 특징 벡터가 나오며, 이를 다시 {{< katex >}}L_2{{< /katex >}} 정규화한다. 이렇게 얻은 특징 추출기를 {{< katex >}}f_{\pi_0}{{< /katex >}}로 쓴다. 각 시연 항목 {{< katex >}}m_i\in\mathcal D{{< /katex >}}의 특징은 {{< katex >}}z_i=f_{\pi_0}(I_i^{\mathrm{top}},\tilde{s}_i){{< /katex >}}로 미리 계산해 둔다. 타임스텝 {{< katex >}}t{{< /katex >}}의 쿼리 특징도 마찬가지로 {{< katex >}}z_t=f_{\pi_0}(I_t^{\mathrm{top}},\tilde{s}_t){{< /katex >}}로 계산한다. 그다음 유클리드 거리로 검색한다.

{{< katex display=true >}}
d_t^{\mathrm{VLAFeat}}(i)=\lVert z_t-z_i\rVert_2,
{{< /katex >}}

그리고 거리가 가장 작은 {{< katex >}}M{{< /katex >}}개 항목을 검색된 문맥으로 고른다.

모든 검색 방식에서, 원래 RICL 프레임워크 [22]에 있던 거리 가중 보간(distance-weighted interpolation) 단계는 생략했다. 이 보간의 가중치가 DINO 검색 거리를 바탕으로 정의되기 때문이다. 서로 다른 검색 표현을 공정하게 비교하고 DINO에만 유리한 요소가 끼어들지 않도록, 모든 방식에서 이 보간 단계를 뺐다.

> **역주.** 본문은 이 단계가 무엇을 섞는지 따로 설명하지 않고, 자세한 정의는 RICL 원 논문 [22]에 있다. 이 보간 단계는 검색 거리에 따라 가중치를 정하는데, 그 가중치가 DINO 거리의 척도에 맞춰 정의되어 있다. 상태 거리나 VLA 특징 거리에는 그대로 맞지 않으므로, 한 방식만 이득을 보지 않도록 네 방식 모두에서 빼고 실험했다는 뜻이다.

**Task-hierarchical bootstrap confidence interval.** 전체 과제 성공률의 불확실성을 정량화하기 위해 과제 계층 부트스트랩 절차를 쓴다. 이 절차는 개별 평가 시행이 아니라 과제를 기본 표본 단위로 취급한다. 평가 과제 25개는 각각 고정된 초기 장면 10개에서 테스트한다. 검색 방식 하나에 대해, 먼저 과제마다 10개 평가 장면의 성공/실패(이진) 결과를 평균해 과제별 성공률을 계산한다. 그러면 과제 단위 성공률 25개가 나온다. 이 25개 결과에서 복원 추출로 과제 25개를 뽑아 부트스트랩 표본 하나를 만든다. 뽑힌 과제들의 과제 단위 성공률을 평균하면 전체 성공률의 부트스트랩 추정치 하나가 된다. 이 과정을 부트스트랩 표본 10,000개만큼 반복해 전체 과제 성공률의 경험적 분포를 얻는다. *task-hier. CI*는 이 부트스트랩 분포의 2.5번째와 97.5번째 백분위수로 정의하며, 95% 신뢰구간에 해당한다.

**McNemar test.** 같은 평가 조건에서 두 검색 방식을 비교하기 위해 정확 McNemar 검정(exact McNemar test) [25, 26]을 쓴다. 모든 방식을 같은 과제와 같은 고정 초기 장면에서 평가하므로, 성공/실패 결과를 짝지어 비교할 수 있다. 두 방식 {{< katex >}}A{{< /katex >}}와 {{< katex >}}B{{< /katex >}}에 대해, {{< katex >}}n_{10}{{< /katex >}}을 {{< katex >}}A{{< /katex >}}는 성공하고 {{< katex >}}B{{< /katex >}}는 실패한 평가의 수, {{< katex >}}n_{01}{{< /katex >}}을 {{< katex >}}A{{< /katex >}}는 실패하고 {{< katex >}}B{{< /katex >}}는 성공한 평가의 수라 하자. 두 방식이 모두 성공하거나 모두 실패한 평가는 상대적 성능에 대한 근거가 되지 않으므로 McNemar 검정에 쓰이지 않는다. 두 방식의 성공률이 같다는 귀무가설 아래에서는, 결과가 엇갈리는 두 경우가 똑같이 일어날 법해야 한다. 즉 "{{< katex >}}A{{< /katex >}} 성공·{{< katex >}}B{{< /katex >}} 실패"와 "{{< katex >}}B{{< /katex >}} 성공·{{< katex >}}A{{< /katex >}} 실패"의 가능성이 같아야 한다. 결과가 엇갈린 경우는 모두 {{< katex >}}n_d=n_{10}+n_{01}{{< /katex >}}번이다. 이 {{< katex >}}n_d{{< /katex >}}개의 엇갈린 경우를 조건으로 하면, 귀무가설 아래에서 방식 {{< katex >}}A{{< /katex >}}에 유리한 경우의 수는 이항 분포를 따른다.

{{< katex display=true >}}
N_{10}\sim\mathrm{Binomial}(n_d,1/2),
{{< /katex >}}

따라서 양측 정확 McNemar {{< katex >}}p{{< /katex >}}값은 다음과 같다.

{{< katex display=true >}}
p=2\min\left\{\Pr(N_{10}\le n_{10}),\Pr(N_{10}\ge n_{10})\right\},
{{< /katex >}}

단, 1을 넘으면 1로 자른다. {{< katex >}}p{{< /katex >}}값이 작으면 {{< katex >}}n_{10}{{< /katex >}}과 {{< katex >}}n_{01}{{< /katex >}}의 차이가 통계적으로 유의하다는 뜻이고, 방식 {{< katex >}}A{{< /katex >}}와 {{< katex >}}B{{< /katex >}}의 성공률이 다르다는 근거가 된다.

> **역주.** 대문자 {{< katex >}}N_{10}{{< /katex >}}은 귀무가설 아래의 확률 변수이고, 소문자 {{< katex >}}n_{10}{{< /katex >}}은 실제로 관측된 횟수이다. 관측값이 이항 분포 {{< katex >}}\mathrm{Binomial}(n_d,1/2){{< /katex >}}의 어느 쪽 꼬리에 있든 그 꼬리 확률을 두 배 한 것이 양측 {{< katex >}}p{{< /katex >}}값이다.

**Retrieval-quality analysis.** 검색 품질이 VLA의 실제 행동에 어떤 영향을 주는지 이해하기 위해, 먼저 두 가지 쿼리 설정에서 동일 과제 검색률을 측정한다. 구체적으로, 주어진 쿼리에 대한 동일 과제 검색률은 검색된 {{< katex >}}M{{< /katex >}}개 항목 중 과제가 쿼리 과제와 일치하는 비율로 정의한다. 이 지표는 검색기가 같은 과제의 시연을 얼마나 자주 돌려주는지를 나타낸다. 같은 과제의 시연이 목표 과제를 수행하는 데 직접 관련된 정보를 줄 가능성이 더 높다는 가정이 깔려 있다. 먼저 *오프라인(offline)* 설정을 본다. 과제마다 고정된 평가 장면 10개 각각에 대해, 해당 장면의 성공한 전문가 시연에서 뽑은 상태를 검색 쿼리로 쓰고 동일 과제 검색률을 계산한다. 다음으로 같은 초기 장면을 쓰는 *온폴리시(on-policy)* 설정을 본다. 여기서는 실행 중 VLA가 실제로 방문한 상태로 검색 버퍼에 쿼리한다. 전문가 쿼리와 온폴리시 쿼리가 같은 초기 장면에서 나오므로, 이 비교는 "성공한 전문가 궤적에서 정책 자신이 마주친 상태로 옮겨 갈 때 검색 행동이 어떻게 바뀌는가"만을 분리해 보여 준다. `RICL-Random`의 오프라인 설정은 평가하지 않았다. 이 방식은 검색 버퍼에서 항목을 균등하게 무작위 추출하므로 동일 과제 검색률의 기댓값이 {{< katex >}}1/25=4\%{{< /katex >}}이기 때문이다.

또한 오프라인 설정에서 검색 품질을 평가하려고 Normalized Discounted Cumulative Gain(NDCG)을 쓴다. 여기서 쿼리 상태는 검색 버퍼에 포함되지 않은 별도(held-out) 전문가 시연에서 뽑는다. 기본 생각은 이렇다. 검색된 프레임이 쿼리와 같은 과제에서 왔고, 그 뒤에 이어지는 행동 청크가 쿼리 상태의 행동 청크와 비슷하면 더 관련 있다고 본다. 구체적으로 쿼리마다, 쿼리 뒤에 이어지는 행동 청크를 검색 버퍼의 각 후보 프레임에 딸린 행동 청크와 비교한다. 각 행동 청크는 다음 10개 행동을 담고, 각 행동은 7차원 벡터이다. 차이를 계산하기 전에, 차원마다 값의 범위가 달라 생기는 치우침을 줄이려고 각 행동 차원을 정규화한다. {{< katex >}}\tilde A_q\in\mathbb{R}^{10\times 7}{{< /katex >}}와 {{< katex >}}\tilde A_i\in\mathbb{R}^{10\times 7}{{< /katex >}}를 각각 쿼리와 후보 항목의 정규화된 미래 행동 청크라 하자. 두 청크의 행동 차이는 평균 제곱근 오차(root mean squared error)로 잰다.

{{< katex display=true >}}
e(q,i)=\sqrt{\frac{1}{70}\sum_{\tau=1}^{10}\sum_{k=1}^{7}\left(\tilde A_q^{(\tau,k)}-\tilde A_i^{(\tau,k)}\right)^2}.
{{< /katex >}}

{{< katex >}}e(q,i){{< /katex >}}가 작을수록, 후보 프레임 뒤에 이어지는 행동 시퀀스가 쿼리 상태의 미래 행동 시퀀스와 더 비슷하다는 뜻이다.

행동 차이 {{< katex >}}e(q,i){{< /katex >}}가 주어지면, 이제 검색 버퍼의 각 후보 프레임에 관련도 점수를 매긴다. 쿼리와 다른 과제에서 온 후보 프레임의 관련도는 0이다. 같은 과제의 후보 프레임들은 행동 차이가 작은 것부터 큰 것 순으로 순위를 매긴다. {{< katex >}}r_i\in\{1,\ldots,N_q\}{{< /katex >}}를 같은 과제 후보 {{< katex >}}N_q{{< /katex >}}개 중 후보 {{< katex >}}i{{< /katex >}}의 순위라 하자. {{< katex >}}r_i=1{{< /katex >}}이 행동 차이가 가장 작은 후보이다. 관련도는 다음과 같이 정의한다.

{{< katex display=true >}}
\mathrm{rel}_i=1-\frac{r_i-1}{N_q-1}.
{{< /katex >}}

즉, 미래 행동 청크가 더 비슷한 같은 과제 후보일수록 관련도 점수가 크고(1등은 1, 꼴찌는 0), 다른 과제 후보는 관련도가 0이다. {{< katex >}}i_1,\ldots,i_4{{< /katex >}}를 검색 점수 순으로 정렬한 검색 항목 4개라 하자. 다음을 계산한다.

{{< katex display=true >}}
\mathrm{DCG}=\sum_{j=1}^{4}\frac{\mathrm{rel}_{i_j}}{\log_2(j+1)},
{{< /katex >}}

이렇게 하면 관련도가 높은 항목이 검색 순위에서 앞쪽에 있을수록 더 큰 점수를 받는다. 그다음 다음과 같이 정의한다.

{{< katex display=true >}}
\mathrm{NDCG}=\frac{\mathrm{DCG}}{\mathrm{IDCG}},
{{< /katex >}}

여기서 {{< katex >}}\mathrm{IDCG}{{< /katex >}}는 이상적인 순위의 DCG이다. 이상적인 순위란 미래 행동 차이가 가장 작은 같은 과제 후보 프레임 4개로 이루어진 순위이다. 따라서 {{< katex >}}\mathrm{NDCG}{{< /katex >}}가 클수록, 검색된 상위 4개 항목이 과제 일치와 미래 행동 유사도 두 측면 모두에서 이 이상적인 순위에 더 가깝다는 뜻이다.
