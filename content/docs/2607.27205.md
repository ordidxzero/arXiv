## Abstract

비전-언어-행동(vision-language-action, VLA) 모델은 흔히 LLM을 중심에 둔 {{< katex >}}V\rightarrow \boldsymbol{L}\rightarrow A{{< /katex >}} 경로를 따른다. 즉 시각 관측과 언어 지시를 먼저 대규모 언어 모델(LLM)로 처리한 뒤 로봇 행동을 예측한다. 이 설계는 효과적이지만 계산량과 메모리 부담이 크다. 본 논문은 직접적인 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 매핑에 기반한 소형 VLA 구조 **TurboVLA**를 제안한다. TurboVLA는 LLM을 지각과 행동 사이의 중심 인터페이스로 쓰지 않는다. 대신 시각 관측과 언어 지시를 따로 인코딩하고, 가벼운 양방향 비전-언어 상호작용으로 두 정보를 직접 주고받게 한 다음, 작은 디코더로 연속적인 행동 청크(action chunk)를 예측한다. 이 단순한 설계는 과제에 맞춘 표현을 직접 만들어 내면서 LLM 중심 실행 경로의 부담을 피한다. LIBERO에서 TurboVLA는 소비자용 RTX 4090 위에서 0.2B 파라미터, 31.2 ms 추론 지연 시간, 0.9 GiB 추론 VRAM만으로 평균 성공률 97.6%를 달성한다. 특히 0.4B 크기의 TurboVLA는 RoboTwin 2.0에서 88.06%의 성공률을 기록하며, 훨씬 큰 VLA 정책과 대등하거나 이를 앞선다. 이 결과는 TurboVLA의 단순한 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 설계가 LLM 중심 실행 경로 없이도 높은 성능을 낼 수 있음을 보여 준다. 또한 효율적인 로봇 조작을 위해 비전·언어·행동을 어떻게 연결할지에 대한 새로운 관점을 제시한다.

> **역주.** VLA 모델은 카메라 이미지와 언어 지시를 받아 로봇 행동을 직접 출력하는 모델이다. {{< katex >}}V\rightarrow \boldsymbol{L}\rightarrow A{{< /katex >}}는 비전(V) 정보가 언어 모델(굵은 L)을 거쳐 행동(A)이 된다는 뜻이고, {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}}는 비전과 언어를 나란히 처리해 바로 행동으로 잇는다는 뜻이다. 행동 청크는 한 번의 추론으로 여러 스텝의 행동을 한꺼번에 예측한 묶음을 말한다.

## 1 Introduction

비전-언어-행동(VLA) 모델은 언어 조건 로봇 조작을 위한 강력한 프레임워크가 되었다. VLA 모델은 시각 관측, 언어 지시, 로봇 행동을 하나의 정책 안에서 연결한다 (Brohan et al., 2023; Octo Model Team et al., 2024; Black et al., 2025b; Black et al., 2025a; Liu et al., 2025; Li et al., 2024; Fu et al., 2025; Fang et al., 2026). 흔한 설계는 이 과정의 중심에 대규모 언어 모델을 두는 것이다. 이런 시스템은 사실상 간접적인 {{< katex >}}V\rightarrow \boldsymbol{L} \rightarrow A{{< /katex >}} 경로를 따른다. 시각 관측과 언어 지시를 LLM에 맞춘 토큰으로 바꾸고, 이 토큰을 다시 로봇 행동으로 디코딩한다 (Driess et al., 2023; Zitkovich et al., 2023; Kim et al., 2024). 이 설계는 대규모 사전학습에서 얻은 폭넓은 의미 지식을 로봇 제어로 옮겨 주며, 의미 수준의 일반화와 고수준 추론을 돕는다.

그러나 LLM 중심 VLA 모델은 실시간 로봇 실행에서 큰 계산 병목이 될 수 있다. 실시간 실행에서는 낮은 지연 시간이 필수다. 그래야 빠르게 반응하고, 높은 처리량으로 조작하고, 자원이 제한된 로봇 플랫폼에도 배포할 수 있다. 그림 2(a)에 정리했듯이, 이런 모델은 보통 두 방식 중 하나로 행동을 만든다. 하나는 행동 토큰을 자기회귀적으로 생성하는 방식이고 (Kim et al., 2024; Zitkovich et al., 2023), 다른 하나는 연속적인 행동 청크를 예측하는 행동 전문가(action expert)를 쓰는 방식이다 (Black et al., 2025b; Black et al., 2025a; Kim et al., 2025; Li et al., 2024; Shukor et al., 2025). 행동 전문가 설계는 자기회귀 언어 생성처럼 토큰을 하나씩 디코딩하는 부담은 피한다. 하지만 시각 관측과 지시를 처리하는 데는 여전히 대형 언어 모델 또는 멀티모달 백본에 의존한다. 그 결과 생기는 계산·메모리 부담이 추론 지연 시간을 늘리고 제어 주파수를 제한한다. 그래서 더 근본적인 질문이 생긴다. *대규모 언어 모델을 중심에 두지 않는 VLA, 즉 실행 수준 조작(execution-level manipulation, 고수준 계획 없이 지시된 동작을 수행하는 것)을 위해 비전과 언어를 행동으로 직접 매핑하는 VLA를 단순하고 우아하며 효율적으로 설계하려면 어떻게 해야 할까?*

**그림 2.** (a) LLM 중심 VLA는 대규모 언어 모델의 표현으로부터 행동을 예측한다. 반면 TurboVLA는 시각 특징과 지시 특징을 직접 융합해 연속 제어를 수행한다. (b) TurboVLA는 훨씬 낮은 지연 시간과 작은 모델 크기로 LIBERO에서 매우 경쟁력 있는 성능을 낸다.

핵심 관찰은 실행 수준 제어(execution-level control)가 대규모 언어 모델을 중심에 둘 필요가 없다는 것이다. 지시가 수행할 조작 기술을 이미 명시한다면, 실행 정책은 명시적인 고수준 추론이나 하위 과제 생성을 할 필요가 없다. 대신 정책은 주로 지시를 현재 시각 관측에 그라운딩(grounding, 언어 표현을 이미지 속 대상과 연결하는 것)하고, 이 정보로 행동을 이끄는 데 집중하면 된다. LLM 중심 VLA 모델에서는 지시와 시각 관측을 잇는 이 과정이 범용 언어 모델 표현을 거쳐 이루어진다. 저자들은 BERT (Devlin et al., 2019) 같은 가벼운 텍스트 인코더만으로도 실행에 필요한 지시의 의미를 담을 수 있다고 주장한다. 그리고 작은 교차 모달 상호작용만으로도 시각 특징과 언어 특징이 서로에게 정보를 줄 수 있다고 본다 (Lynch and Sermanet, 2020; Shridhar et al., 2022; Jang et al., 2022; Mees et al., 2022b). 이 생각에서 직접적인 비전-언어 상호작용 설계가 나왔다. 이 설계는 시각과 언어가 직접 정보를 주고받아, 연속 행동 예측에 쓸 제어용 표현을 만든다.

이에 따라 실시간 언어 조건 조작을 위한 단순하면서 효율적인 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 모델 **TurboVLA**를 제안한다. 그림 2(a)에서 보듯이, TurboVLA는 시각 인코더와 가벼운 텍스트 인코더로 시각 관측과 과제 지시를 따로 인코딩한다. Grounding DINO (Liu et al., 2024)의 효율적인 교차 모달 상호작용에서 착안해, 작은 교차 어텐션 모듈로 시각 특징과 언어 특징을 융합한다. 그다음 이렇게 얻은 표현을 연속 행동 청크로 디코딩한다 (Zhao et al., 2023). 시각·언어 특징을 행동 예측에 직접 연결하므로 LLM 중심 실행 경로의 부담이 없고, 추론 지연 시간과 GPU 메모리 사용량이 크게 줄어든다.

> **역주.** Grounding DINO는 텍스트로 지정한 물체를 이미지에서 찾는 개방형 객체 검출 모델로, 이미지 특징과 텍스트 특징이 교차 어텐션으로 서로를 갱신하는 특징 강화 모듈을 쓴다. TurboVLA의 상호작용 모듈은 이 부분의 사전학습 가중치로 초기화된다(4.1절, 부록 A.1). Zhao et al. (2023)은 ACT(Action Chunking with Transformers)를 제안한 논문으로, 트랜스포머 디코더가 여러 스텝의 행동을 한꺼번에 예측하는 방식이다.

광범위한 실험에서 TurboVLA는 성능과 효율 사이에서 유리한 균형을 보인다. LIBERO (Liu et al., 2023)에서 TurboVLA는 소비자용 RTX 4090 위에서 0.2B 파라미터, 31.2 ms 정책 추론 지연 시간, 1 GB 미만의 추론 VRAM으로 평균 성공률 97.6%를 달성한다. RoboTwin 2.0 (Chen et al., 2026)에서는 0.4B 변형이 평균 성공률 88.06%를 기록해, 훨씬 큰 LLM 중심 VLA 시스템과 대등하거나 이를 앞선다. 실제 로봇 실험도 TurboVLA의 효과와 효율을 뒷받침한다. TurboVLA는 지연 시간에 민감하고 자원이 제한된 로봇 시스템에 언어 조건 조작 정책을 배포할 때 필요한 계산량과 메모리를 크게 줄인다. 이 결과는 LLM 중심 정책 없이도 가벼운 언어 인코딩과 직접적인 비전-언어 상호작용만으로 경쟁력 있고 효율적인 실행 수준 조작이 가능함을 시사한다. 본 논문의 기여는 다음과 같다.

- LLM 중심 VLA 모델의 계산·메모리 비용을 다시 살펴본다. 그리고 지각과 행동 사이에 대규모 언어 모델을 두지 않아도 된다는 점을 강조한다. 가벼운 지시 인코딩과 직접적인 양방향 비전-언어 상호작용만으로도, 실행 수준 제어에 필요한 지시의 의미를 잃지 않을 수 있다.
- 단순하고 효율적인 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 모델 TurboVLA를 제안한다. TurboVLA는 시각 관측과 과제 지시를 따로 인코딩한다. 그리고 두 모달리티가 직접적인 양방향 비전-언어 상호작용으로 정보를 주고받아, 과제에 맞춘 제어용 표현을 함께 만든다. 이 표현으로 연속 행동을 예측한다.
- 시뮬레이션 벤치마크와 실제 조작 과제에서 TurboVLA를 검증한다. 더 적은 계산량과 메모리로 경쟁력 있는 조작 성능을 보인다. 이 결과는 로봇 배포의 문턱을 낮출 가능성을 보여 주며, LLM 중심 구조를 넘어서는 효율적인 정책 설계에 대한 통찰을 준다.

## 2 Related Work

**Vision-language-action models.** 비전-언어-행동(VLA) 모델은 시각 관측과 과제 지시를 로봇 행동으로 매핑한다. 의미 수준의 일반화를 위해 대규모 비전-언어 사전학습을 활용하는 경우가 많다. RT-1 (Brohan et al., 2023)은 트랜스포머 기반 제어를 대규모로 확장할 수 있음을 보였다. RT-2 (Zitkovich et al., 2023)와 OpenVLA (Kim et al., 2024)는 사전학습된 비전-언어 모델이 행동 토큰을 출력하도록 적응시킨다. {{< katex >}}\pi_0{{< /katex >}} (Black et al., 2025b)와 {{< katex >}}\pi_{0.5}{{< /katex >}} (Black et al., 2025a) 같은 연속 제어 모델은 사전학습된 멀티모달 백본에 전용 행동 전문가를 붙인다. 다른 범용 정책들은 재사용 가능한 정책 표현 (Octo Model Team et al., 2024), 확산(diffusion) 기반 행동 생성 (Liu et al., 2025; Li et al., 2024), 다양한 로봇 형태를 위한 파운데이션 모델 (Bjorck et al., 2025; Bu et al., 2025; Wang et al., 2026d)을 탐구한다. 최근 연구는 시각적 미래 예측 (Yang et al., 2026b), 예측적 세계 지식 (Zhang et al., 2025), 잠재 추론 (Bai et al., 2026)으로 정책 표현을 더 풍부하게 만든다. TurboVLA는 실행 수준 제어에 쓰이는 구조 자체에 초점을 둔다. LLM 중심 정책과 달리 TurboVLA는 과제 텍스트와 시각 관측을 따로 인코딩하고, 두 특징을 직접 융합하며, 대형 생성형 언어 백본 없이 로봇 상태를 조건으로 행동을 예측한다.

**Efficient execution in VLA policies.** 기존 연구는 여러 수준에서 VLA의 효율을 높인다. 행동 쪽 방법은 병렬 디코딩이나 행동 청크 예측 (Kim et al., 2025; Liang et al., 2026b; Liu et al., 2025), 그리고 압축적인 행동 토큰화 (Pertsch et al., 2025; Liu et al., 2026)로 행동 생성을 개선한다. TinyVLA (Wen et al., 2025), SmolVLA (Shukor et al., 2025), Evo-1 (Lin et al., 2026) 같은 소형 구조는 모델 크기나 추론 비용을 줄인다. 이와 상보적인 연구들은 백본 추론 비용을 줄인다. 그 수단은 양자화 (Xu et al., 2026), 토큰 재사용과 가지치기 (Xu et al., 2025; Jiang et al., 2025), 적응적 깊이와 구조적 가지치기 (Yang et al., 2025; Wang et al., 2026a), 증류 (Jeon et al., 2026) 등이다. 또 다른 방법들은 비동기 행동 청크 실행 (Black et al., 2025c), 예측 지평(horizon, 한 번에 예측하는 행동 스텝 수)을 고려한 플로 매칭 샘플링을 쓰는 스트리밍 추론 (Lu et al., 2026), 추측(speculative) 추론 (Niu et al., 2026)으로 추론이나 실행 효율을 높인다. 이 방법들은 기존 정책 프레임워크 안에서 계산이나 실행을 최적화한다. 반면 TurboVLA는 표현이 흘러가는 경로 자체를 겨냥한다. 즉 대형 생성형 언어 백본을 빼고, 그 자리에 작은 인코더를 둔다. 그리고 시각과 언어가 제어를 위해 직접 상호작용하게 한다.

**Language interfaces for robot control.** 자연어 지시는 오래전부터 로봇 조작의 과제 명세로 쓰여 왔다. 초기 모방 학습 방법들은 지시 조건 로봇 제어를 위한 언어 그라운딩을 탐구했다 (Lynch and Sermanet, 2020; Stepputtis et al., 2020). CLIPort (Shridhar et al., 2022)와 BC-Z (Jang et al., 2022)는 언어 조건 조작을 더 발전시켰다. CALVIN (Mees et al., 2022b)은 장기(long-horizon) 언어 조건 제어 벤치마크를 제공하고, HULC (Mees et al., 2022a)는 이 설정을 위한 정책을 개발한다. TurboVLA는 실행 수준 VLA 설정에서 다음 질문을 탐구한다. 압축적인 지시 인코딩과 직접적인 비전-언어 상호작용만으로, 효율을 유지하면서 LLM 중심 표현 경로만큼의 성능을 낼 수 있는가?

## 3 TurboVLA

실행 수준의 언어 조건 조작을 위한 단순하고 깔끔한 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 모델 **TurboVLA**를 소개한다. 그림 3(a)에서 보듯이, TurboVLA는 관측과 지시를 따로 인코딩한다. 그리고 양방향 교차 모달 상호작용으로 두 모달리티가 정보를 주고받게 한 뒤, 그 결과 표현을 로봇 상태와 결합해 연속 행동 청크를 예측한다. 이 설계는 지각과 행동 사이의 중심 인터페이스로 대규모 언어 모델을 두지 않는다. 대신 가벼운 언어 인코더로 과제 관련 의미를 보존하며, 이 덕분에 효율적인 추론으로 경쟁력 있는 조작 성능을 낼 수 있다.

### 3.1 Problem Formulation and Approach Overview

실행 스텝 {{< katex >}}t{{< /katex >}}에서 언어 조건 조작 정책은 세 가지 입력을 받는다. 다중 시점 시각 관측 {{< katex >}}\mathcal{O}_t{{< /katex >}}, 과제 지시 {{< katex >}}x{{< /katex >}}, 현재 로봇 상태 {{< katex >}}s_t{{< /katex >}}이다. 정책은 이로부터 {{< katex >}}H{{< /katex >}}개의 연속 행동으로 이루어진 청크 {{< katex >}}\hat{\mathbf{A}}_t=\pi_{\theta}(\mathcal{O}_t,x,s_t)\in\mathbb{R}^{H\times d_a}{{< /katex >}}를 예측한다. 여기서 {{< katex >}}d_a{{< /katex >}}는 행동 차원이다. 예측된 행동은 차례로 실행되고, 그다음에 정책이 다음 상태를 관측해 새 행동 청크를 예측한다.

**LLM-centric VLA implementation.** 기존 LLM 중심 VLA 모델은 시각 관측과 과제 지시를 사전학습된 대규모 언어 모델로 처리한다.

{{< katex display=true >}}
H_t^L
=
F_L\!\left(
\left[
P_v\!\left(E_v(\mathcal{O}_t)\right);
\operatorname{Tok}(x)
\right]
\right),
\tag{1}
{{< /katex >}}

여기서 {{< katex >}}E_v{{< /katex >}}는 시각 인코더이고, {{< katex >}}P_v{{< /katex >}}는 시각 특징을 언어 모델의 임베딩 공간으로 투영한다. {{< katex >}}\operatorname{Tok}(x){{< /katex >}}는 지시를 임베딩하고, {{< katex >}}F_L{{< /katex >}}은 대규모 언어 모델이다. 즉 이미지 특징을 언어 모델이 읽을 수 있는 형태로 바꿔 지시 토큰 앞에 이어 붙이고, 이 전체를 LLM에 통과시킨다. 이렇게 얻은 멀티모달 표현은 자기회귀 행동 토큰 예측 (Kim et al., 2024)에 쓰이거나, 행동 모듈을 통한 연속 행동 생성 (Black et al., 2025b; Black et al., 2025a)에 쓰인다. 이 경로를 {{< katex >}}V\rightarrow\boldsymbol{L}\rightarrow A{{< /katex >}}로 요약한다. 여기서 {{< katex >}}\boldsymbol{L}{{< /katex >}}은 단순한 텍스트 인코딩을 넘어, 시각 정보와 언어 정보를 행동 예측용 표현으로 통합하는 LLM 중심 멀티모달 인터페이스를 뜻한다. 따라서 자기회귀 방식이든 행동 모듈 방식이든, 지각과 행동 사이에서 표현을 이어 주는 역할은 여전히 언어 모델 백본이 맡는다.

> **역주.** 식 (1)의 {{< katex >}}H_t^L{{< /katex >}}은 LLM이 출력한 표현을 가리키며, 행동 청크 길이 {{< katex >}}H{{< /katex >}}와는 다른 기호다. 또 경로 표기의 굵은 {{< katex >}}\boldsymbol{L}{{< /katex >}}은 'LLM 중심 인터페이스'를 뜻하는 반면, {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}}의 {{< katex >}}\boldsymbol{L}{{< /katex >}}은 가벼운 인코더로 처리한 언어 입력을 가리킨다. 3.3절에 나오는 {{< katex >}}L_t^\ell{{< /katex >}}은 이와 또 다른 기호로, 상호작용 모듈의 {{< katex >}}\ell{{< /katex >}}번째 레이어를 지난 지시 특징을 뜻한다.

**Our approach.** LLM 중심 VLA와 달리, TurboVLA는 시각 관측과 과제 지시를 따로 인코딩하고 직접적인 양방향 비전-언어 상호작용으로 두 특징을 통합한다. 구체적으로 지시, 시각 관측, 로봇 상태를 각각 {{< katex >}}Z^l=\Phi_l(x){{< /katex >}}, {{< katex >}}Z_t^v=\Phi_v(\mathcal{O}_t){{< /katex >}}, {{< katex >}}Z_t^s=\Phi_s(s_t){{< /katex >}}로 인코딩한다. 여기서 {{< katex >}}\Phi_l{{< /katex >}}은 가벼운 지시 인코더다. 이렇게 얻은 비전-언어 표현을 로봇 상태 특징과 결합해 행동 청크를 예측한다.

{{< katex display=true >}}
\begin{aligned}
Z_t^{vl} &= \Phi_{vl}(Z_t^v,Z^l),\quad
\hat{\mathbf{A}}_t
=
D_{\theta}\!\left(
Q_a,\left[Z_t^{vl};Z_t^s\right]
\right).
\end{aligned}
\tag{2}
{{< /katex >}}

여기서 {{< katex >}}\Phi_l{{< /katex >}}, {{< katex >}}\Phi_v{{< /katex >}}, {{< katex >}}\Phi_s{{< /katex >}}는 각각 지시·시각·로봇 상태 인코더이고, {{< katex >}}\Phi_{vl}{{< /katex >}}은 직접적인 비전-언어 상호작용 모듈, {{< katex >}}D_{\theta}{{< /katex >}}는 행동 디코더다. 식 (1)과 비교하면, 시각과 언어가 LLM 하나를 함께 통과하는 대신 각자 인코딩된 뒤 {{< katex >}}\Phi_{vl}{{< /katex >}}에서만 만난다.

{{< image src="/2607.27205/figures/pipeline-crop.png" alt="TurboVLA 전체 구조도(DINOv3·BERT 인코더, V-L 상호작용 모듈, 행동 청크 디코더)와 상호작용 모듈 내부(레이어 정규화와 두 방향 교차 어텐션) 확대도" title="그림 3. TurboVLA 개요. (b) 상호작용 모듈은 최대한 단순하게 설계했다. 양방향 교차 어텐션을 여러 층 쌓아, 시각을 반영한 지시 특징과 지시를 조건으로 한 시각 특징을 만든다." loading="lazy" >}}

**그림 3.** TurboVLA 개요. (a) TurboVLA는 작은 모달리티별 인코더, 비전-언어 상호작용, 행동 청크 디코더를 거쳐 시각 관측과 언어 지시를 연속 행동 청크로 단순하고 효율적으로 매핑한다. (b) 상호작용 모듈은 최대한 단순하게 설계했다. 양방향 교차 어텐션을 여러 층 쌓아, 시각을 반영한 지시 특징과 지시를 조건으로 한 시각 특징을 만든다.

### 3.2 Multimodal Feature Encoding

**Lightweight instruction encoding.** TurboVLA는 그림 3(a)처럼 과제 지시와 시각 관측을 따로 인코딩한다. LLM 중심 실행 경로의 부담은 줄이고, 지시는 단순하지만 충분히 이해하기 위해서다. 과제 지시 {{< katex >}}x{{< /katex >}}가 주어지면, BERT (Devlin et al., 2019) 같은 가벼운 텍스트 인코더가 토큰 단위의 지시 특징을 추출한다.

{{< katex display=true >}}
Z^l=P_l\left(f_{\mathrm{text}}(x)\right)\in\mathbb{R}^{N_l\times d},
\tag{3}
{{< /katex >}}

여기서 {{< katex >}}P_l{{< /katex >}}은 인코더 출력을 은닉 차원 {{< katex >}}d{{< /katex >}}로 투영하고, {{< katex >}}N_l{{< /katex >}}은 지시 토큰 수다. 이 가벼운 인코딩이 과제 지시의 압축된 의미 표현을 제공한다.

**Multi-view visual encoding.** 각 카메라 관측 {{< katex >}}I_t^{(i)}{{< /katex >}}에 대해, 이미지 인코더가 공간적 시각 특징을 추출한다. 이 특징을 투영한 뒤 위치 임베딩과 카메라 시점 임베딩을 더한다.

{{< katex display=true >}}
Z_t^{v,(i)}=P_v\left(f_{\mathrm{img}}\left(I_t^{(i)}\right)\right)+E_{\mathrm{pos}}^{(i)}+e_{\mathrm{view}}^{(i)}, \qquad
Z_t^v=\left[Z_t^{v,(1)};\ldots;Z_t^{v,(K)}\right].
\tag{4}
{{< /katex >}}

여기서 {{< katex >}}E_{\mathrm{pos}}^{(i)}{{< /katex >}}는 한 시점 안의 공간 구조를 보존하고, {{< katex >}}e_{\mathrm{view}}^{(i)}{{< /katex >}}는 어느 카메라에서 온 특징인지 알려 준다. {{< katex >}}K{{< /katex >}}개 스트림을 이어 붙이면 여러 시점의 상보적인 단서를 함께 유지할 수 있다.

> **역주.** 식 (4)의 {{< katex >}}P_v{{< /katex >}}는 TurboVLA의 시각 특징을 공유 차원 {{< katex >}}d{{< /katex >}}로 투영하는 층이다. 식 (1)에서 같은 이름의 {{< katex >}}P_v{{< /katex >}}는 시각 특징을 LLM 임베딩 공간으로 보내는 투영이었으므로, 역할은 비슷하지만 다른 모듈이다. {{< katex >}}K{{< /katex >}}는 카메라 수로, LIBERO에서는 2(주 시점·손목), RoboTwin 2.0에서는 3(머리·양 손목)이다(부록 A.2).

**Robot state encoding.** 현재 로봇 상태 {{< katex >}}s_t{{< /katex >}}는 따로 인코딩한다. {{< katex >}}f_{\mathrm{state}}{{< /katex >}}는 가벼운 투영 네트워크이고 {{< katex >}}N_s{{< /katex >}}는 상태 토큰 수다.

{{< katex display=true >}}
Z_t^s=f_{\mathrm{state}}(s_t)\in\mathbb{R}^{N_s\times d},
\tag{5}
{{< /katex >}}

이 상태 특징은 행동 디코더에 바로 들어가, 로봇의 현재 자세를 조건으로 행동을 예측하게 한다.

### 3.3 Vision-Language Interaction Module

따로 인코딩된 시각 특징과 텍스트 특징만으로는 아직 어떤 시각 내용이 현재 지시와 관련 있는지 알 수 없다. LLM 중심 VLA는 시각 내용과 지시를 이렇게 맞대어 연결하는 일(정렬)을 대형 언어 백본 안에서 수행한다. 반면 TurboVLA는 그림 3(b)의 단순하고 효율적인 비전-언어 상호작용 모듈을 써서 두 스트림이 정보를 직접 주고받게 한다.

{{< katex >}}V_t^0=Z_t^v{{< /katex >}}와 {{< katex >}}L_t^0=Z^l{{< /katex >}}을 초기 시각 특징과 지시 특징이라 하자. 상호작용 모듈은 {{< katex >}}N{{< /katex >}}개의 양방향 교차 모달 레이어를 거치며 두 스트림을 점차 갱신한다.

{{< katex display=true >}}
\left(V_t^\ell,L_t^\ell\right)
=
\operatorname{FusionLayer}_{\ell}
\left(V_t^{\ell-1},L_t^{\ell-1}\right),
\qquad
\ell=1,\ldots,N.
\tag{6}
{{< /katex >}}

각 융합 레이어 안에서 두 스트림은 양방향 교차 어텐션으로 정보를 교환한다. 표기를 단순하게 하려고, 아래 어텐션 안의 투영 행렬에는 레이어 번호를 붙이지 않는다.

{{< katex display=true >}}
{V}_t^\ell
=
V_t^{\ell-1}
+
\operatorname{Attn}_{v\leftarrow l}
\!\left(V_t^{\ell-1},L_t^{\ell-1}\right),
\qquad
{L}_t^\ell
=
L_t^{\ell-1}
+
\operatorname{Attn}_{l\leftarrow v}
\!\left(L_t^{\ell-1},V_t^{\ell-1}\right).
\tag{7}
{{< /katex >}}

시각 특징이 지시를 참조하는 어텐션(visual-to-instruction attention)은 시각 특징이 과제 의미를 조건으로 삼게 한다. 지시 특징이 시각을 참조하는 어텐션(instruction-to-visual attention)은 장면 맥락을 지시 스트림에 주입한다. 즉 시각 토큰은 지시 토큰을 참조해 갱신되고, 지시 토큰은 시각 토큰을 참조해 갱신되며, 두 갱신 모두 잔차 연결로 원래 특징에 더해진다. 마지막 레이어를 지나면 갱신된 두 스트림을 이어 붙인다.

{{< katex display=true >}}
Z_t^{vl}
=
\left[
V_t^{N};
L_t^{N}
\right].
\tag{8}
{{< /katex >}}

이 작은 상호작용 모듈을 통해 목표 물체, 속성, 공간 관계 같은 정보가 관련 시각 특징을 조절하고, 동시에 지시 표현도 현재 장면에 맞게 조정된다. 이 단순한 상호작용 설계는 행동 예측에 필요한 과제별 멀티모달 정보를 효율적으로 제공한다. 대규모 언어 모델의 폭넓은 생성·추론 능력에 기댈 필요가 없다.

> **역주.** 식 (7)의 {{< katex >}}\operatorname{Attn}_{v\leftarrow l}(V, L){{< /katex >}}은 {{< katex >}}V{{< /katex >}}에서 쿼리를, {{< katex >}}L{{< /katex >}}에서 키·값을 만드는 교차 어텐션으로 읽힌다. 즉 식의 아래 첨자 화살표는 정보가 흘러 들어가는 방향(오른쪽 → 왼쪽)이다. 반면 본문과 그림의 이름 'visual-to-instruction'은 쿼리(시각)에서 참조 대상(지시) 쪽으로 읽은 이름이므로, {{< katex >}}\operatorname{Attn}_{v\leftarrow l}{{< /katex >}}과 같은 어텐션을 가리킨다. 그림 3(b)에서는 두 어텐션이 위아래로 쌓인 블록처럼 그려져 있지만, 식 (7)에서는 둘 다 이전 레이어의 {{< katex >}}V_t^{\ell-1}{{< /katex >}}, {{< katex >}}L_t^{\ell-1}{{< /katex >}}을 입력으로 쓴다. 본문은 그림의 순차 배치와 식 (7)의 병렬 계산이 어떤 관계인지 따로 설명하지 않는다.

### 3.4 Continuous Action Chunk Prediction

가벼운 ACT 방식의 트랜스포머 디코더 (Zhao et al., 2023)를 써서, 융합된 멀티모달 표현과 로봇 상태 특징을 연속 행동 시퀀스로 매핑한다.

{{< katex display=true >}}
\hat{\mathbf{A}}_t=D_{\theta}\!\left(Q_a,\left[Z_t^{\mathrm{vl}};Z_t^s\right]\right)\in\mathbb{R}^{H\times d_a},
\tag{9}
{{< /katex >}}

여기서 {{< katex >}}Q_a=[q_1,\ldots,q_H]{{< /katex >}}는 학습 가능한 행동 쿼리 {{< katex >}}H{{< /katex >}}개이고, {{< katex >}}H{{< /katex >}}는 예측 지평(prediction horizon), {{< katex >}}d_a{{< /katex >}}는 행동 차원, {{< katex >}}D_\theta{{< /katex >}}는 행동 디코더다. 즉 디코더는 행동 스텝마다 쿼리 하나를 두고, 이 쿼리들이 융합 특징과 상태 특징을 교차 어텐션으로 참조해 각 스텝의 행동을 한 번에 출력한다. TurboVLA는 행동 복제(behavior cloning, 전문가 시연을 지도 학습으로 따라 하는 방식)로 학습한다. 손실은 예측 청크 {{< katex >}}\hat{\mathbf{A}}_t{{< /katex >}}와 전문가 시퀀스 {{< katex >}}\mathbf{A}_t^*=[a_t^*,\ldots,a_{t+H-1}^*]{{< /katex >}} 사이의 {{< katex >}}\ell_1{{< /katex >}} 손실이다.

## 4 Experiments

이 절에서는 TurboVLA가 LLM 중심 VLA 정책보다 모델 크기, 추론 지연 시간, 메모리 부담을 크게 줄이면서도 강한 언어 조건 조작 성능을 유지할 수 있는지 평가한다. 실험은 LIBERO (Liu et al., 2023)의 단일 팔 조작, RoboTwin 2.0 (Chen et al., 2026)의 양팔 조작, 실제 로봇 배포를 다룬다. 이어서 언어 조건화와 비전-언어 상호작용에 대한 어블레이션(ablation, 구성 요소를 빼거나 바꿔 보는 실험)을 수행한다.

### 4.1 Experimental Setup

시각 백본으로 DINOv3 (Siméoni et al., 2025)를, 지시 인코더로 BERT (Devlin et al., 2019)를 쓴다. 시각 특징과 언어 특징은 차원 {{< katex >}}d=256{{< /katex >}}으로 투영되고, {{< katex >}}N=6{{< /katex >}}개의 양방향 상호작용 레이어에서 처리된다. 이 레이어들은 사전학습된 Grounding DINO 가중치 (Liu et al., 2024)로 초기화한다. 그 결과 표현에서 연속 행동 청크를 예측하는 데는 ACT 방식의 디코더 (Zhao et al., 2023)를 쓴다. 학습 세부 사항은 부록 A에 있다.

> **역주.** DINOv3는 레이블 없이 자기지도 학습으로 사전학습된 비전 트랜스포머(ViT) 계열 이미지 인코더다. ViT-B, ViT-L은 각각 Base, Large 크기를 뜻한다.

**LIBERO**는 네 개의 스위트로 이루어지며, 각 스위트에는 언어 조건 조작 과제가 10개씩 있다. OpenVLA (Kim et al., 2024)와 함께 공개된 수정판 `no_noops` RLDS 데이터셋을 쓰고, 네 스위트의 데이터를 합쳐 DINOv3 ViT-B 백본의 모델 하나를 학습한다(스위트마다 따로 학습하지 않는다). 모델은 배치 크기 128로 40k 스텝 학습한다. VLA-Adapter의 롤아웃 프로토콜 (Wang et al., 2026c)을 따라 과제당 50회 롤아웃(rollout, 정책을 환경에서 한 번 실행해 보는 시행)을 수행하고, 총 2,000회 시행에 대한 스위트별 성공률과 평균 성공률을 보고한다.

> **역주.** `no_noops`는 시연 데이터에서 로봇이 거의 움직이지 않는 '무동작' 스텝을 제거한 버전을 뜻하고, RLDS는 로봇 학습용 에피소드 데이터를 저장하는 표준 형식이다. 네 스위트는 Spatial(공간 배치), Object(물체 종류), Goal(같은 장면에서 다른 목표), Long(여러 단계로 된 장기 과제)이다.

**RoboTwin 2.0**은 두 팔의 협응 제어가 필요한 언어 조건 양팔 조작 과제 50개로 이루어진다. 선행 연구 (Bi et al., 2026; Yang et al., 2026a; Wang et al., 2026b; Wu et al., 2026a)를 따라, DINOv3 ViT-L 백본의 TurboVLA를 깨끗한(clean) 시연 2,500개와 무작위화(randomized) 시연 25,000개로 함께 학습한다. 학습은 배치 크기 512로 150k 스텝 진행한다. StarVLA (StarVLA Community, 2026) 평가 프레임워크를 따라, 깨끗한 설정과 무작위화 설정 각각에서 과제당 100회 롤아웃을 수행한다.

> **역주.** RoboTwin 2.0의 무작위화 조건은 배경, 조명, 탁자 높이, 방해 물체 등을 무작위로 바꾼 환경이고, 깨끗한 조건은 이런 교란이 없는 기본 환경이다.

**Real-world evaluation.** 그림 4의 AgileX Piper 플랫폼으로 실제 로봇 실험을 수행했다. 대표적인 언어 조건 조작 과제 네 가지를 다룬다. *grab roller*(롤러 집기), *move playing card away*(카드 치우기), *press stapler*(스테이플러 누르기), *stack three bowls*(그릇 세 개 쌓기)다. 이 과제들에는 정확한 물체 그라운딩, 여러 물체 조작, 정밀한 상호작용이 모두 필요하다. 정책은 LIBERO에서 사전학습한 TurboVLA로 초기화하고, 원격 조작으로 수집한 실제 시연 {{< katex >}}4\times65{{< /katex >}}개로 12.5k 스텝 파인튜닝한다. 각 과제는 40회씩 평가한다. 같은 플랫폼, 같은 파인튜닝 데이터, 같은 평가 프로토콜에서 {{< katex >}}\pi_{0.5}{{< /katex >}}와 비교한다.

**1) Lightweight instruction encoding and direct vision-language interaction enable competitive and efficient manipulation.** 표 1에 정리했듯이, TurboVLA는 LIBERO (Liu et al., 2023)에서 0.2B 파라미터, 31.2 ms 추론 지연 시간, 0.9 GiB 추론 VRAM으로 평균 성공률 97.6%를 달성한다. 표 1은 비교 대상을 능력 지향(capability-oriented, 성능을 우선하는 대형 모델), 가속 지향, 경량 VLA로 나눈다. 능력 지향 VLA와 비교하면, 평균 성공률 96.9%인 {{< katex >}}\pi_{0.5}{{< /katex >}}보다 높다. 그러면서도 파라미터는 약 6%만 쓰고 추론은 {{< katex >}}8\times{{< /katex >}} 빠르다. 이런 유리한 균형은 가속 지향 VLA나 경량 VLA와 비교해도 유지된다. OpenVLA-OFT (Kim et al., 2025)와 DDVLA (Liang et al., 2026b)의 추론 지연 시간은 각각 112.2 ms와 60.8 ms다. TurboVLA는 전용 가속 기법 없이도 이 둘보다 평균 성공률이 높고 지연 시간이 낮다. 경량 VLA 중에서는 Evo-1 (Lin et al., 2026)과 SmolVLA (Shukor et al., 2025)보다 적은 파라미터와 빠른 추론으로 더 높은 성능을 낸다. 종합하면, 이 비교는 가벼운 지시 인코딩이 직접적인 비전-언어 상호작용에 과제 관련 의미를 공급할 수 있음을 시사한다. 그래서 LLM 중심 정책의 계산·메모리 비용 없이도 경쟁력 있는 실행 수준 조작이 가능하다.

> **역주.** 초록과 서론은 같은 메모리를 '1 GB 미만'이라고 쓰고, 표 1은 0.9 GiB라고 쓴다. GiB는 {{< katex >}}1024^3{{< /katex >}} 바이트(부록 B.2)이므로 0.9 GiB는 약 0.97 GB로, 두 표현은 서로 맞는다. 또 '{{< katex >}}8\times{{< /katex >}} 빠르다'는 표 1의 238.8 ms 대 31.2 ms(약 7.7배)를 반올림한 값으로 보인다.

**2) This simple and lightweight design extends to challenging bimanual multi-task control.** 단일 팔 조작을 넘어, TurboVLA가 RoboTwin 2.0 (Chen et al., 2026)에서 두 팔의 협응 제어를 지원할 수 있는지 평가한다. Qwen-VLA (Wang et al., 2026b)와 LingBot-VLA (Wu et al., 2026a) 같은 최근 모델은 대규모 체화 사전학습의 혜택을 받아 강한 성능을 낸다. 그런데도 표 2에서 보듯이 TurboVLA는 0.4B 파라미터와 43.4 ms 추론 지연 시간만으로 88.06%에 도달해, 두 모델보다 평균 성공률이 높다. 또 모델 크기가 훨씬 큰 Motus (Bi et al., 2026), ABot-M0 (Yang et al., 2026a)과도 대등한 성능을 낸다. LingBot-VLA와 비교하면 추론 지연 시간을 164.4 ms에서 43.4 ms로 줄여 약 {{< katex >}}3.8\times{{< /katex >}} 빠르다. {{< katex >}}\pi_{0.5}{{< /katex >}} (Black et al., 2025a)보다도 성능이 높으면서 약 {{< katex >}}5.7\times{{< /katex >}} 빠르다. 이 결과는 단순한 TurboVLA 설계가 훨씬 적은 계산량으로, 체화 사전학습 없이도 어려운 양팔 조작에서 매우 효과적임을 보여 준다.

> **역주.** RoboTwin 2.0에서의 지연 시간(43.4 ms)이 LIBERO(31.2 ms)보다 긴 것은 설정이 다르기 때문이다. RoboTwin 2.0 모델은 더 큰 ViT-L 백본을 쓰고, 카메라가 세 대이며, 행동 청크 길이가 {{< katex >}}H=50{{< /katex >}}이다(LIBERO는 ViT-B, 카메라 두 대, {{< katex >}}H=12{{< /katex >}}; 부록 A, B.2).

### 4.3 Ablation Study

LIBERO에서 어블레이션을 수행해 세 가지를 살펴본다. 의미를 담은 언어 조건화가 어떤 역할을 하는지, 지시 인코더를 무엇으로 고를지, 비전-언어 상호작용을 어떻게 설계할지다. LIBERO와 RoboTwin 2.0에 대한 추가 어블레이션은 부록 C.1에 있다.

**Semantic language conditioning.** 먼저 언어 자체의 역할을 살펴본다. 표 3을 보면, 언어를 제거하면 평균 성공률이 97.6%에서 68.5%로 떨어지며, LIBERO-Goal에서 하락 폭이 가장 크다. 이 성능 저하는 같은 장면이 서로 다른 지시 목표에 대응할 수 있을 때 시각 관측만으로는 부족하다는 것을 보여 준다. 학습된 과제 ID 임베딩을 쓰면 평균 성공률이 96.6%로 회복되지만, 의미를 담은 지시보다는 여전히 1.0% 낮다. 이 차이는 의미를 담은 지시 특징이 과제 식별자만 주는 것보다 더 효과적인 조건화를 제공함을 시사한다.

> **역주.** 과제 ID 임베딩(task-ID embedding)은 지시 문장 대신 과제 번호마다 학습 가능한 벡터를 하나씩 두어 조건으로 넣는 방식이다. 과제를 구별할 수는 있지만 '빨간 그릇', '왼쪽' 같은 단어의 의미는 담지 못한다. 여기서 '1.0% 낮다'는 97.6%와 96.6%의 차이, 즉 퍼센트포인트 차이다.

**Instruction encoder.** 다음으로, 제안한 구조가 특정 텍스트 백본에 의존하는지 살펴본다. 표 4에서 보듯이, 다른 설정을 모두 같게 두었을 때 T5-Base (Raffel et al., 2020)는 97.6%의 경쟁력 있는 평균 성공률을 내고, SigLIP (Zhai et al., 2023) 텍스트 인코더는 97.3%에 이른다. 이 결과는 실행 수준 제어에서 가벼운 지시 인코딩이 효과적임을 뒷받침하며, TurboVLA가 텍스트 백본 선택에 강건함을 보여 준다.

**Vision-language interaction design.** 의미를 담은 지시 특징이 중요함을 확인했으므로, 이제 행동 디코딩 전에 시각 특징과 언어 특징이 어떻게 상호작용해야 하는지 살펴본다. 그림 5처럼 네 가지를 비교한다. 상호작용 없음, 한쪽 방향으로만 어텐션하는 비대칭(단방향) 교차 어텐션 변형 두 가지, 그리고 제안한 양방향 상호작용이다. 이때 나머지 구조와 학습 설정은 모두 그대로 둔다. 표 5에서 보듯이, 상호작용 없이 두 특징을 이어 붙이기만 하면 평균 성공률이 96.3%이고, 두 단방향 교차 어텐션 변형은 이를 96.8%와 97.2%로 끌어올린다. 이 향상은 디코더가 이미 두 모달리티를 모두 볼 수 있는 경우에도, 행동 디코딩 전에 명시적으로 상호작용시키는 것이 도움이 됨을 시사한다. 양방향 상호작용이 97.6%로 가장 좋으며, 이는 시각 특징과 지시 특징이 서로를 조건으로 삼게 하는 것이 행동 예측에 유리함을 보여 준다.

전체적으로 이 어블레이션들은 제안한 직접 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 경로를 뒷받침한다. 가벼운 의미 지시 인코딩과 양방향 비전-언어 상호작용이 함께 작동해, LLM 중심 정책 없이도 효과적인 실행 수준 제어를 가능하게 한다.

### 4.4 Runtime Acceleration of TurboVLA

**표 6.** TurboVLA의 런타임 가속.

| Method | No Graph | CUDA Graph |
|---|---|---|
| TurboVLA | 31.2 ms | 11.3 ms |
| **TurboVLA + Opt.** | **30.3 ms** | **7.42 ms** |

TurboVLA는 이미 지연 시간이 낮지만, 여기에 더해 정책에 CUDA Graph 재실행(replay)을 적용하고 몇 가지 런타임 최적화(Opt.)를 더했다. 표 6에서 보듯이, 이렇게 구현하면 RTX 4090에서 정책 추론 지연 시간이 7.42 ms까지 크게 줄어든다. 이 개선은 데이터 변환, 메모리 할당, 쓰이지 않는 중간 출력을 겨냥한 것이며, 전체 시각·언어 인코더와 원래 행동 지평은 그대로 유지한다. 이 지연 시간은 초당 130회가 넘는 정책 추론 속도에 해당하므로, 정책 추론 자체가 실시간 조작의 병목이 될 가능성은 낮아 보인다. 이 수준에서는 실제 제어 주파수가 실행 정책보다는 센서, 통신, 구동기 동역학에 의해 제한될 가능성이 크다. 이는 지연 시간에 민감한 로봇 시스템에서 TurboVLA의 배포 가능성을 한층 더 보여 준다.

> **역주.** CUDA Graph는 GPU에서 실행할 커널들의 순서를 한 번 기록해 두고, 이후에는 그 기록을 통째로 다시 실행하는 기능이다. CPU가 커널을 하나씩 실행 요청하는 부담이 사라지므로, TurboVLA처럼 연산량은 작고 커널 수가 많은 모델에서 효과가 크다. 130 Hz는 1/7.42 ms ≈ 135회/초에서 나온 값이다. 제목의 32 Hz와 본문의 주요 지연 시간(31.2 ms)은 이 가속을 적용하기 전 기준이다.

## 5 Conclusion

본 논문은 단순하고 효율적인 {{< katex >}}\boldsymbol{V}+\boldsymbol{L}\rightarrow A{{< /katex >}} 모델 TurboVLA를 제안했다. TurboVLA는 실행 수준 조작을 위해 가벼운 지시 인코딩과 직접적인 양방향 비전-언어 상호작용을 결합한다. LIBERO, RoboTwin 2.0, 실제 조작 과제에서의 실험은 TurboVLA가 언어 지시에 따른 조작 능력을 유지하면서 모델 크기, 추론 지연 시간, 메모리 사용량을 크게 줄임을 보여 준다. 이 결과는 실행 수준 제어라면 범용 LLM을 지각과 행동 사이의 중심 인터페이스로 꼭 둘 필요는 없음을 시사한다. 또한 효율적인 로봇 제어를 위해 비전과 언어를 어떻게 구성할지에 대한 통찰을 준다.

**Limitations and future work.** 그렇지만 TurboVLA는 현재 구체적인 실행 수준 조작에 초점을 두며, "방 청소해(clean the room)" 같은 열린 명령을 위해 설계된 것은 아니다. 이런 명령에서는 로봇이 관련 하위 목표를 찾고 그 실행 순서를 짜기 위해 고수준 추론과 과제 분해에 의존해야 한다. 향후 연구에서는 효율적인 실행 경로를 유지하면서 더 지능적인 조작을 목표로, TurboVLA를 고수준·장기 과제로 확장할 계획이다. 또한 평가 범위를 시뮬레이션 벤치마크와 탁자 위 시나리오를 넘어 더 다양한 실제 환경으로 넓힐 것이다. 여기에는 어수선한 가정 환경, 사무실 환경, 산업 작업 공간, 그리고 다른 형태의 로봇이 포함된다.

## A Implementation and Training Details

### A.1 Architecture and Initialization

TurboVLA는 LIBERO에서는 DINOv3 ViT-B/16을, RoboTwin 2.0에서는 ViT-L/16을 시각 인코더로 쓴다 (Siméoni et al., 2025). 지시 인코딩에는 두 경우 모두 BERT-base-uncased (Devlin et al., 2019)를 쓴다. 비전-언어 상호작용 모듈은 Grounding DINO Swin-T OGC 체크포인트 (Liu et al., 2024)의 사전학습된 특징 강화(feature-enhancement) 가중치로 초기화한다. 두 구성 모두 공유 특징 차원 {{< katex >}}d=256{{< /katex >}}, 양방향 상호작용 레이어 6개, 3층짜리 ACT 방식 행동 디코더 (Zhao et al., 2023)를 쓴다. 현재 로봇 상태는 {{< katex >}}N_s=2{{< /katex >}}개의 토큰으로 투영되고, 융합된 비전-언어 특징과 이어 붙여져 디코더의 메모리(교차 어텐션으로 참조하는 입력)가 된다. 표 7에 구조 구성을 정리했다.

> **역주.** ViT-B/16의 '/16'은 이미지를 16×16 픽셀 패치로 잘라 토큰으로 만든다는 뜻이다. Swin-T OGC는 Grounding DINO가 공개한 체크포인트 중 Swin-Tiny 백본을 쓰고 O365·GoldG·Cap4M 데이터로 학습한 버전을 가리킨다.

### A.2 Data Processing

**LIBERO.** OpenVLA (Kim et al., 2024)와 함께 공개된 수정판 `no_noops` RLDS 스위트 네 개로 함께 학습한다. 각 샘플에는 주 시점 RGB 이미지, 손목 시점 RGB 이미지, 과제 지시, 8차원 로봇 상태가 들어 있다. 원래 이미지 해상도 {{< katex >}}256\times256{{< /katex >}}을 크기 조정이나 자르기 없이 그대로 쓰고, 사전학습된 시각 인코더가 쓰는 픽셀 정규화를 적용한다. 로봇 상태는 합친 학습 데이터 전체에서 계산한 통계로 표준화한다. 각 행동은 7차원이다. 연속적인 팔 행동 좌표 6개는 {{< katex >}}[-1,1]{{< /katex >}}로 최소-최대 정규화한 뒤 이 범위로 잘라 내고, 그리퍼 명령은 원래의 이진 인코딩 {{< katex >}}\{-1,+1\}{{< /katex >}}을 유지한다. 각 목표 청크는 관측 시점부터 시작하는 연속 행동 {{< katex >}}H=12{{< /katex >}}개로 이루어진다. 에피소드 경계에서 길이가 모자라는 청크는 마지막 행동을 반복해 채우고, 채운 항목은 손실에서 제외한다.

**RoboTwin 2.0.** 학습에는 50개 과제에 걸친 깨끗한 시연 2,500개와 무작위화 시연 25,000개를 함께 쓴다. 과제는 균등하게 샘플링하고, 각 과제 안에서는 무작위화 시연과 깨끗한 시연을 {{< katex >}}10:1{{< /katex >}} 비율로 샘플링한다. 각 샘플에는 머리 시점 RGB 이미지, 손목 시점 RGB 이미지 두 장, 과제 지시, 현재 양팔 상태가 들어 있다. 세 이미지의 해상도는 모두 {{< katex >}}224\times224{{< /katex >}}다. 상태와 행동은 모두 14차원으로, 왼팔 관절 위치, 오른팔 관절 위치, 그리퍼 좌표 두 개로 이루어진다. 연속 관절 좌표는 {{< katex >}}[-1,1]{{< /katex >}}로 최소-최대 정규화하고, 그리퍼 좌표는 임계값 0.49로 이진화한다. 각 관측에는 연속 행동 {{< katex >}}H=50{{< /katex >}}개로 된 목표 청크가 짝지어진다. 각 행동은 절대 관절 위치와 그리퍼 값이다.

> **역주.** 14차원은 팔 하나당 관절 6개와 그리퍼 1개로 나누어 읽을 수 있다(6+6+2). '절대(absolute)' 관절 위치는 현재 위치에서의 변화량이 아니라 목표 관절 각도 자체를 행동으로 쓴다는 뜻이다.

### A.3 Training Configurations

두 정책 모두 AdamW로 {{< katex >}}\ell_1{{< /katex >}} 행동 복제 손실을 최소화하도록 학습한다. BERT는 고정(frozen)하고, 시각 인코더와 나머지 정책 모듈은 모두 행동 예측에 맞게 최적화한다. LIBERO는 NVIDIA RTX 4090 4장에서 유효 배치 크기 128로 40,000 스텝 학습하고, RoboTwin 2.0은 NVIDIA H100 8장에서 유효 배치 크기 512로 150,000 스텝 학습한다. 두 벤치마크 모두 학습률을 선형으로 올리는 워밍업 뒤에 일정한 학습률을 쓴다. 학습 가능한 파라미터의 지수 이동 평균(exponential moving average, EMA)을 감쇠 계수 0.999로 유지한다. 표 8에 학습 구성을 정리했다.

## B Evaluation Protocols and Efficiency Measurement

### B.1 Evaluation Protocols

**LIBERO.** 함께 학습한 정책을 VLA-Adapter 롤아웃 프로토콜 (Wang et al., 2026c)에 따라 Spatial, Object, Goal, Long 스위트에서 평가한다. 각 스위트에는 과제 10개가 있고 과제당 50회 시행하므로 총 2,000회를 평가한다. 벤치마크가 제공하는 초기 상태와 고정된 평가 시드를 쓰며, 각 에피소드 시작 시 10스텝 동안 장면이 안정되기를 기다린다. 에피소드 길이는 Spatial, Object, Goal, Long에서 각각 220, 280, 300, 520 제어 스텝으로 제한하며, 이 안정화 스텝은 포함하지 않는다. 정책은 12스텝짜리 행동 청크를 예측하고, 청크 하나를 모두 실행한 뒤 다시 계획한다. 스위트별 성공률과 네 스위트의 평균을 보고한다.

**RoboTwin 2.0.** 함께 학습한 정책을 StarVLA 평가 인터페이스 (StarVLA Community, 2026)로 50개 과제 전체에서, 깨끗한 조건과 무작위화 조건 각각으로 평가한다. 조건마다 과제당 100회 시행하므로 설정마다 5,000회가 되며, 두 설정의 성공률과 그 평균을 보고한다. 평가에는 학습 때 보지 못한 과제 지시를 쓴다.

**Real-world evaluation.** AgileX Piper 플랫폼에서 네 가지 언어 조건 조작 과제로 TurboVLA를 평가한다. 과제당 40회, 정책당 160회 시행한다. 매 시행 전에 로봇은 정해진 초기 자세로 자동 복귀하고, 과제 물체는 탁자 위 {{< katex >}}50\times50{{< /katex >}} cm 영역 안에 무작위로 놓인다. 각 시행의 제한 시간은 30 s이며, 그동안 정책은 실패한 시도를 다시 시도할 수 있다. 시행은 과제를 완료하거나, 제한 시간이 끝나거나, 작업 공간 경계를 벗어나 자동 안전 정지가 걸리면 끝난다. 같은 로봇 플랫폼, 파인튜닝 데이터, 평가 프로토콜에서 {{< katex >}}\pi_{0.5}{{< /katex >}}와 비교하고, 과제별 성공률과 그 평균을 보고한다. 성공 기준은 다음과 같다. *grab roller*는 대상 물체를 잡아 탁자에서 완전히 들어 올려야 한다. *move playing card away*는 카드를 잡아 들어 올린 뒤 오른쪽으로 옮겨야 한다. *press stapler*는 그리퍼를 닫은 상태로 스테이플러를 눌러야 한다. *stack three bowls*는 그리퍼가 마지막 그릇을 놓은 뒤에도 세 그릇이 모두 안정적으로 쌓여 있어야 한다. 제한 시간 안에 해당 기준을 만족하면 그 시행은 성공이다.

### B.2 Efficiency Measurement

모든 모델은 NVIDIA RTX 4090 한 장에서 배치 크기 1로 평가한다. 공식 구현을 평가 모드로 두고 그래디언트 계산을 끈 상태에서 측정한다. 각 벤치마크 안에서는 모든 모델이 같은 행동 지평을 쓴다(LIBERO는 12, RoboTwin 2.0은 50). 자기회귀 정책은 지정한 지평에 필요한 만큼 행동 토큰을 생성한다.

**Latency.** 정상 상태(steady-state)의 로컬 정책 추론 지연 시간을 보고한다. 이는 GPU에 올라가 있는 관측에서 시작해 GPU 위에 완성된 행동 청크가 나올 때까지의 시간이다. 시각·언어 인코딩, 행동 생성, 내부 행동 후처리는 포함하고, 입력 준비와 전송, 통신, 환경 실행은 제외한다. 워밍업 10회 뒤 추론 50회를 재어 중앙값을 보고한다. 매 회 GPU 연산이 끝날 때까지 동기화한 뒤 시간을 재며, 처음 컴파일 시간은 제외한다.

**GPU memory.** 추론 VRAM은 두 값의 차이다. 하나는 모델 초기화, 워밍업, 시간 측정 추론 동안 `nvidia-smi`가 보고한 최댓값이고, 다른 하나는 실행 전 유휴 GPU에서 읽은 값이다. 메모리 사용량은 GiB({{< katex >}}1024^3{{< /katex >}} 바이트) 단위로 표기한다. 알고리즘 1에 측정 절차를 정리했다.

**Parameter count.** 완전한 추론 모델의 모든 파라미터를 학습 가능한 것과 고정된 것 모두 포함해 센다. 옵티마이저 상태는 제외한다.
